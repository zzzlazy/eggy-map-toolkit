# 混合类型地图模式库

混合地图不是把两种地图各做一半。先指定主类型：它拥有重玩理由、强制目标、主要失败、整局节拍和终局；次类型只改变玩家如何完成其中一部分。最多一个次类型，压力、任务对象、载具、随机、恐怖等仍按结构修饰器处理。

本文件中的“案例”链接到已审计样本；“原创种子”只是帮助展开设计的假想起点，不是优秀作品证据，也不证明当前组件目录能实现全部逻辑。纯音游、Boss、防守、潜行、回合、体育、创造沙盒或阵营推理参与组合时，再读取 [专项混合类型模式库](specialized-hybrid-patterns.md)。

混合关系证据按“主类型 + 次类型 + 组合方式”单独登记。当前只有经营主 × 生存次的持续叠层，以及防守主 × 经营次的阶段换挡拥有部分实证；其他模式即使两端主类型分别有案例，也仍是待验证设计空间。用研究技能的 `--design-packet` 检查 `hybrid_relation`，不能从本页原创种子自行晋升。

## 四种组合方式

| 方式 | 次类型放在哪里 | 适合 | 主要风险 |
|---|---|---|---|
| 持续叠层 | 全程改变主循环条件，例如上涨危险覆盖竞速 | 压力、角色能力、资源携带 | 两套倒计时或反馈互相抢夺 |
| 局部站点 | 只在若干节点短暂改变动作，例如竞速中的识别门 | 解谜、轻合作、互动 | 站点过长切断主类型节奏 |
| 可选支线 | 主循环外提供可退出活动，例如社交中心的小游戏 | 社交、探索、收集 | 奖励过强后支线反客为主 |
| 阶段换挡 | 准备/经营结束后进入生存或争夺，再回到结算 | 经营＋生存、叙事＋追逐 | 状态交接、旧对象清理和目标切换不清 |

默认优先前三种。只有玩家能清楚感知阶段门槛、旧状态被正确冻结/清理、失败后回到明确阶段时，才使用阶段换挡。

## 混合契约

在路线图和坐标前填写：

| 字段 | 必须回答 |
|---|---|
| 主类型 | 玩家为什么重玩，什么叫完成/获胜 |
| 次类型 | 它具体强化主循环的哪一种判断、关系或情绪 |
| 组合方式 | 持续叠层、局部站点、可选支线或阶段换挡 |
| 次类型范围 | `secondary_scope` 精确引用哪些命名节拍，不写“全程都有一点” |
| 权威状态 | 时间、分数、任务对象、存活、资源中谁决定终局 |
| 时间预算 | `time_budget` 声明强制次循环总秒数与最长连续停摆；不能无限占用主循环 |
| 入口与出口 | 进入条件如何去重；完成、放弃、失败或缺员如何退出 |
| 失败优先级 | 两种规则同时失败时，以谁为准，反馈和复位到哪里 |
| 状态交接 | 进入/离开次类型时创建、冻结、提交和恢复什么 |
| 清理所有者 | 谁取消计时器、释放占用、回收对象/UI/镜头并推进代次 |
| 视觉共语法 | 两种玩法怎样共用世界壳体、路线色、接口与地标 |
| 降级 | 次类型不可用、缺员或性能不足时主循环是否仍闭合 |

**主导性测试**：去掉次类型，主循环仍应能被描述；去掉主类型，地图的重玩理由、终局或大部分强制节拍应明显消失。两者都不成立说明没有主次，只是两张图拼在一起。

## 基础件与密度如何共用

不要为两种类型各建一套互不相干的素材包。按职责建立：

1. **共享世界族**：地面、墙跨、地貌、屋架、边缘与远景，贯穿全图；
2. **主循环族**：跑道跨、竞技场扇区、章节接口、生产站等，决定高频动作；
3. **次循环族**：解谜输入台、任务对象底座、合作交接框、可选活动台等，只在需要处出现；
4. **交接族**：门槛、状态灯、结算框景或换挡平台，让目标变化可见；
5. **地标族**：出生、高潮与终局各用少量独特轮廓。

高完成度来自共享世界族和主循环族的大量展开，次循环族不必为了“各占一半”而复制到每个区域。密度账本仍按区域与层对账；另加一列 `PRIMARY/SECONDARY/HANDOFF/SHARED`，避免每个实例被两套预算重复计算。

## 1. 短竞速主 × 机制/解谜次

**组合方式**：局部站点。竞速拥有计时、检查点和冲线；解谜只提供短时识别、路线选择或可提前读出的操作窗。

**结构**：安全展示符号 → 流动中选门 → 同一规则改变方向/高度 → 终点前快速回收。谜题答案应能在移动中读取，失败进入短支路或就近复位，不让玩家停在窄路读长文字。

**原创种子**：失控邮件分拣线。玩家沿传送廊竞速，根据包裹颜色选择对应闸门；后段颜色映射保持不变，只改变观察角度、门距和传送方向。

**冲突测试**：首次玩家是否因停下来思考而必输；错误门反馈能否说明错因；计时压力是否在安全教学前启动。

已审计的显隐/碰撞反转变奏见 [《case-010》](exemplars/case-010.md)，但其约三分钟长走廊不能直接充当短竞速节拍证据。

## 2. 短竞速主 × 叙事次

**组合方式**：持续叠层或局部揭示。竞速拥有终点和重跑价值；叙事通过远期地标、环境状态与低打断事件解释“为什么跑”。

**结构**：出生给危机与远期出口 → 路线每次转折揭示一个后果 → 喘息台允许观察 → 冲线改变世界状态。强制演出不应打断计时；必须演出时冻结计时、危险和玩家输入，并在结束后同源恢复。

**原创种子**：风暴天文台撤离。玩家沿外环维修桥上升，每次通过气闸都看见主穹顶进一步破裂，终点启动逃生舱并停止风暴机关。

**冲突测试**：复玩时叙事是否拖慢；玩家高速通过是否仍能理解；字幕和危险是否同时要求注意。

## 3. 章节挑战主 × 任务对象/护送修饰器

任务对象不是第二胜负类型，而是章节进度载体。每章必须写“所需对象＋动作＋完成区域 → 可见反馈＋检查点；失败 → 对象回收”。

**结构**：认识对象 → 一次低风险携带/召回 → 改变对象用途 → 组合移动与对象管理 → 对象完成最终空间变化。章节地标和对象状态同时说明进度。

**原创种子**：修复山谷信标。玩家带三个会发光的能量芯片依次穿越崖区，每章将一个芯片安装到塔上，旧区域远景随之点亮。

**冲突测试**：玩家先到出口、对象越界、重生、重复交付或少带一个对象时是否软锁；携带是否把全部移动乐趣变成慢走。

真实任务状态与长流程恢复线索见 [《case-019》](exemplars/case-019.md)。

## 4. 章节挑战主 × 叙事/探索次

**组合方式**：持续叠层。章节挑战拥有检查点、动作学习和最终完成；叙事负责章节意义、地标变化与回访差异。

**结构**：每章同时有动作主题、空间身份和一个状态变化。跨章门槛既提交检查点，也改变远景、光色或可通行区域；可选探索放在喘息平台，不藏在高压跳跃背后。

**原创种子**：沉睡巨城登塔。玩家从被淹街区逐章攀上钟楼，沿途启动排水、照明和钟摆；回望时已完成街区呈现不同轮廓。

**冲突测试**：章节只换颜色还是确实改变空间/动作；强制剧情是否扩大失败损失；回访是否有新信息而非原路折返。

长图体量、章节目标与恢复尺度可参考 [《case-005》](exemplars/case-005.md)，但其后段叙事并未被现有证据验证。

## 5. 机制/解谜主 × 合作次

**组合方式**：持续叠层。谜题拥有规则学习、答案状态和重置；合作让不同角色分别掌握必要动词或信息，但双方都能看见共同状态。

**结构**：A 操作输入 → 世界变化在双方视野中出现 → B 验证/利用 → 双方交换角色或位置 → 组合已学规则。不能把答案拆成两半后让一人照着念；每人都应操作、判断并理解因果。

**原创种子**：双侧潮汐泵站。一人改变管线方向，另一人利用水位移动浮台；到下一站交换控制台与平台侧，最后需要按共享压力表同步收束。

**冲突测试**：最长等待、沟通失败、顺序错误、同时重生、掉线和单人分支；重置是否让两侧回到同一代状态。

角色独占动词与空间交付物见 [《case-015》](exemplars/case-015.md)。

## 6. 合作主 × 任务对象/护送修饰器

共享对象应制造相互依赖，不要让一人永久携带、另一人跟随。把对象的移动、保护、路径开启、交接和找回分给不同角色或位置。

**结构**：共同发现对象 → A 移动/B 开路 → 安全交接 → 能力换位 → 双方共同提交。对象状态、角色状态与章节检查点必须原子提交。

**原创种子**：两人搬运会孵化的星蛋。一人稳定温度才能移动，另一人操作沿途遮阳门；每个安全巢允许换手，失败后星蛋与双方一起回到最近巢。

**冲突测试**：对象能否被带出合法区域、丢进不可达处或被重复生成；谁掉线时由谁接管；第三、第四名玩家是否堵住唯一交接位。

## 7. 生存主 × 积分次

**组合方式**：持续叠层。生存拥有淘汰、观战和终局；积分只鼓励玩家离开安全角、争夺风险位置，不应让已淘汰玩家因旧分数继续改变结果。

**结构**：低风险活动建立危险规则 → 安全区外刷新短时得分机会 → 危险与热点错位迁移 → 终局主动收缩。明确是“最后存活优先、分数破平局”，还是“时间结束分数最高且存活才有效”。

**原创种子**：暴风温室。中心温室最安全但不产分，外围风暴间歇开放能源花；玩家冒险采集并返回提交，后期安全区和花区同时缩小。

**冲突测试**：龟缩是否总赢、领先者是否能垄断安全与资源、同归于尽/无人存活怎样判、淘汰瞬间携带分如何处理。

这是暂定设计种子，当前没有合格本地案例背书；所有公平和终局规则必须实测。

## 8. 积分/争夺主 × 圈速/竞速次

**组合方式**：持续叠层。积分拥有结算；竞速用路线效率、风险捷径和交付速度决定资源周转，而不是另设一个冲线胜利。

**结构**：公平出生 → 选择资源线路 → 通过检查点合法携带 → 回到提交区得分 → 热点迁移或路线反向 → 结算。每件资源只在完整合法路径后计一次，防止掉头刷分、跨点和反复进区。

**原创种子**：云港快递环线。三条环线分别短而拥堵、长而安全、危险但高价值；每轮风向改变一条路线的移动效率，中心提交区保持中立。

**冲突测试**：出生到首资源/提交区真实行进时间、套圈与逆行、领先者占住刷新点、传送或坠落绕过检查点、平局。

这是暂定设计种子，当前没有合格本地争夺案例背书。

## 9. 社交/展示主 × 可选轻玩法次

**组合方式**：可选支线。社交地标网络、表达和回流拥有主体验；轻竞速、合影挑战、收集或小舞台只提供一起做的事，失败不阻止游览。

**结构**：中心看见多个地标 → 到达活动台 → 规则在现场可理解 → 短局自动清理 → 原地继续社交或返回中心。活动入口、观战位和离开口分开，避免围观者堵住玩家。

**原创种子**：漂浮夜市。中心码头连接风筝竞速、双人拍照印章和灯笼收集三个可选活动；完成活动只改变个人纪念展示，不锁住其他场景。

**冲突测试**：单人占用、活动排队、失败后困在子场景、奖励诱导所有人挤同一点、多人镜头遮挡与临时状态残留。

三层景深与换景线索见 [《case-020》](exemplars/case-020.md)，但其完整活动网络与多人并发尚未实测。

## 10. 经营/模拟主 × 合作次

**组合方式**：持续叠层。经营拥有输入、加工、交付、升级和阶段目标；合作让站位、运输或角色能力形成互补，但不能让某人永久成为无决策的搬运工。

**结构**：所有人先完成一次短闭环 → 站点分工出现 → 容量或路线形成可见瓶颈 → 玩家选择升级 → 工作关系改变 → 阶段结算。共享库存与个人权限必须写清所有者。

**原创种子**：云端玩具修理铺。一人诊断零件、一人加工、一人配送；升级可以增加共享缓冲仓、开第二条运输线或让角色临时换岗，而不是只把收益数字放大。

**冲突测试**：一人占住必要工作台、资源被拿走或复制、掉线后岗位无人接管、升级投票冲突、满仓软锁、连续新局保留旧资源。

纯店铺经营的货物链、员工/顾客、目录进度与主动终点可参考 [《case-014》](exemplars/case-014.md)，角色能力型合作可参考 [《case-015》](exemplars/case-015.md)；但尚无同时完成整局与多人实测的经营合作案例，因此站点分工、公平和掉线接管仍是暂定设计。

## 11. 经营/建造主 × 生存次

**组合方式**：持续叠层或阶段换挡，必须二选一。持续叠层适合饥饿、口渴、气温或缓慢环境压力始终给经营动作增加机会成本；压力不能在菜单里不可见地推进，也不能独立抢走经营终局。阶段换挡适合“准备—验证—结算”明确分段：经营阶段负责收集、建造和选择，生存阶段验证这些选择；两阶段共享空间结果，但拥有清楚的开始、冻结和清理边界。

**持续叠层结构**：完成低风险生产闭环 → 压力开始影响路线/容量选择 → 升级同时缓解一种压力并制造新瓶颈 → 阶段目标结算；每个关键菜单和工作站都保持压力状态可读，并为学习操作保留最低安全余量。

**阶段换挡结构**：短生产闭环 → 选择防御/路线升级 → 明确倒计时与准备完成 → 冻结购买和旧搬运 → 危险波次 → 结算损耗与奖励 → 清理生成物并返回经营。

**原创种子**：潮汐浮岛工坊。白天收集木料并选择加高平台、加宽桥或建立避风塔；夜间潮水与风验证布局，幸存结构影响下一轮但有上限和修复成本。

**冲突测试**：准备未完成是否强制开始、波次中能否重复购买、动态建造碰撞、玩家死亡后资源归属、旧危险和建筑代次是否清空。

[《case-011》](exemplars/case-011.md)为同一张图里的“经营主 × 生存次”提供了持续叠层的部分证据：生存压力在菜单、采集与建造期间持续推进，固定配方扩张改变世界；它没有阶段冻结和返回，因此不能支持 `phase_shift`。阶段换挡仍是高状态复杂度暂定蓝图；在经营与生存分别闭环前，不把两者同时实现。

## 12. 叙事/探索主 × 机制/解谜次

**组合方式**：局部站点。探索拥有地标网络、事件顺序和结局；谜题把玩家对世界的观察转成行动，不把主线变成连续密码锁。

**结构**：先在环境中展示规律 → 玩家到达事件地标 → 用规律改变场景 → 返回旧地看见后果 → 新路径开放。线索、输入和结果尽量位于同一空间关系中。

**原创种子**：潮退后的海底档案城。不同塔楼的潮痕高度构成开门顺序；玩家调整水闸后旧街区露出新的通道与故事痕迹，而不是只弹出“答案正确”。

**冲突测试**：漏看可选文本是否仍能解、提示是否只重复答案、回访距离、错误重置、事件越序和多人同时操作。

## 组合失败信号

- 玩家无法一句话回答“怎样赢/完成一次循环”；
- 主类型在次类型站点中连续停摆，或次类型只是无关装饰；
- 同时存在两个终点、两套倒计时、两套分数，却没有权威状态；
- 失败后不知道回到主循环还是次循环，检查点保存了其中一半；
- 两种类型分别使用完全不同的地面、边框、色义和地标，像贴在一起的两张地图；
- 为了让次类型“有存在感”平均分走一半组件预算，导致共享世界和主循环都不完整；
- 阶段换挡后旧机关、对象、UI、计时器或音画状态仍在运行。

## 混合验收

1. 用一句话分别说出主类型、次类型与组合方式；
2. 标出每个强制节拍由谁拥有，次类型不能无边界占用主循环时间；
