# 玩家尺度、相机与空间标定

精确坐标必须来自当前版本和当前玩法条件，而不是凭印象写一个“正常跳距”。角色体型、速度、滚动、二连跳、道具、移动平台、载具、镜头和网络延迟都会改变可行空间。没有实测时只输出标定计划、相对尺寸和待定项，不把经验值伪装成游戏事实。

## 标定上下文

每组数据绑定以下上下文，任一项变化都要重新确认关键指标：

- 游戏版本、地图模式和目标设备；
- 角色形态、移动速度、跳跃/滚动/二连跳或其他能力；
- 单人、目标人数和网络条件；
- 静止/移动起跳、平地/坡面、固定/移动落点；
- 镜头模式、出生朝向和是否有强制相机；
- 测试组件的真实碰撞形状、旋转和表面属性。

公共地图缓存中的变换和距离只能说明该作品怎样布置，不能直接成为通用移动参数。目录中的模型尺寸也不等于碰撞尺寸。

## 建立标定量

使用符号表达设计关系，测得数值后再替换：

| 符号 | 含义 | 用途 |
|---|---|---|
| `B` | 角色带操作余量的有效横向占宽 | 通道、多人并行、触发区和掩体间距 |
| `H` | 角色与常用镜头共同需要的有效净高 | 门洞、顶盖、桥下和镜头防穿 |
| `Jc` | 当前能力下可靠的舒适水平跳距 | 教学、普通节拍和恢复路线 |
| `Jm` | 熟练玩家稳定完成的掌握跳距 | 后段验证和可选快线 |
| `Jx` | 偶尔成功的极限距离 | 仅用于识别边界，不直接作为必经路线 |
| `Vc/Vm` | 舒适/掌握垂直变化 | 台阶、攀爬和落点高差 |
| `Lerr` | 落点误差包络 | 决定平台有效尺寸和边缘缓冲 |
| `S` | 两名并行玩家之间的操作间隔 | 多人通道、会合与超车 |
| `E` | 玩家与危险边缘/墙体之间的安全余量 | 跳台、窄桥、机关边界 |
| `C` | 常用镜头摆动和跟随需要的空间包络 | 隧道、转角、垂直段和大型装饰净空 |
| `Tr` | 失败到重新获得有效操作的总时间 | 检查点、回收区和重跑损失 |

不要假设 `Jc/Jm/Jx` 只是同一固定距离乘百分比；不同起跳角度、坡面和相机可能改变失败类型。记录可复现条件和成功分布。

## 灰盒标定流程

在测试副本或已授权的新建灰盒中准备安全、可回收的标定段；只规划时写出该段，不自行修改地图。

1. **占宽与净高**：走过逐步收窄的门洞、通道和顶盖，记录角色碰撞、镜头穿插、转向和多人相撞开始恶化的位置。
2. **静态跳跃**：用相同起跳面和逐级变化的水平/垂直落点测试；区分站跳、跑跳、滚跳、二连跳和能力组合。
3. **真实节拍**：在实际入射角、前一机关速度和镜头方向下复测，避免把直线实验室结果直接套到弯道或盲落点。
4. **移动目标**：记录平台速度、相位、玩家滞空期间的位移和可见预告；分别测顺向、逆向和侧向接近。
5. **多人占用**：按最低人数和目标人数测试并行、交叉、会合、触发站位和复位；记录堵塞而不是只看几何是否放得下。
6. **相机包络**：在窄门、急转、仰视、俯视、贴墙和大型前景附近主动摆镜头，记录遮挡、穿模、目标丢失和眩晕。
7. **失败回收**：完整测量掉落、判定、传送/重生、重新定向和回到动作点的总时间 `Tr`。

每项使用足以暴露稳定趋势的多次尝试，并至少包含目标水平玩家；不要只记录作者一次成功。对网络或随机机关另测较差条件。

## 从标定量生成尺寸

### 多人净宽

计划允许 `N` 人并行时，使用：

`净宽 ≥ N × B + (N - 1) × S + 2 × E`

这是几何起点，不是验收结论。弯道、坡面、迎面流、道具碰撞和镜头会增加实际需求。只需排队通过的门可更窄，但必须把排队与拥堵写进节拍，而不是误称并行。

### 落点

落点有效尺寸至少覆盖角色占宽、入射方向上的 `Lerr` 和两侧 `E`。移动落点还要加上玩家滞空期间平台可能产生的相对位移。视觉表皮超出碰撞面不能被当作安全余量；碰撞面超出可见表皮则会制造“空气墙/空气落点”。

教学与恢复路线围绕 `Jc/Vc` 设计；主流程掌握段可逐步接近 `Jm/Vm`；`Jx` 只适合作为明确可选、可快速回收的挑战边界。任何必经动作都给前后状态、相机和输入误差留余量。

### 起跳面与落脚面

- 起跳面应允许玩家完成所需助跑、转向和最后一次校准，不把装饰碰撞塞到边缘；
- 落脚后应有制动或继续运动空间，除非“落地立刻再跳”已安全教学；
- 落点后的墙、顶盖、机关或其他玩家不能把成功落地变成不可预见的二次失败；
- 斜面、曲面和模型边缘必须按真实碰撞复测，不能只看视觉外形。

### 机关时间窗

对周期机关记录：可见预告、有效开放时长、通过所需时间、输入/网络余量和失败后恢复。基本关系为：

`有效开放窗 ≥ 目标玩家通过时间 + 观察/输入余量 + 网络/多人余量`

教学段扩大预告或开放窗；组合段只能压缩已经掌握的变量。多个机关串联时评估相位组合，防止单个都可过、组合后却出现长时间无解窗。

### 相机与遮挡

- 门洞和隧道用 `H` 与 `C` 共同决定净高/净宽，不能只按角色碰撞盒；
- 急转前让新方向的地标进入视野，再要求立即跳跃；
- 垂直攀爬同时检查头顶遮挡、下方回收区和镜头俯仰边界；
- 大型前景、粒子、透明面和强光都按相机视线占用物处理，不因“无碰撞”就忽略；
- 强制相机或演出结束时重新给出角色、下一目标和危险边界。

## 载具与特殊移动

载具/滑行/高速状态另建标定量：车体宽 `Bw`、车长 `Lw`、稳定转弯半径 `Rw`、制动距离 `Dw`、超车间隔 `Sw`、镜头包络 `Cw`。赛道宽度、弯角、坡顶视距、护栏和复位区以这些量为基础，不能沿用步行 `B/Jc`。

- 单车通行净宽从 `Bw + 2E` 起算；并行或超车再加入其他车体和 `Sw`；
- 弯道内外侧同时验证车尾扫掠与镜头，而不仅是中心线半径；
- 坡顶、落差和高速门洞要给制动/转向决定足够可见距离；
- 翻车、卡墙、逆行和离开赛道都要有不奖励捷径的快速回收。

改变重力、尺寸、速度、摩擦、传送惯性或操作映射的区域也要建立独立标定上下文，并清楚标记进入和退出时状态如何恢复。

## 按地图类型关注

| 类型 | 最重要的空间标定 |
|---|---|
| 短竞速 | 连续动作下的真实 `Jc/Jm`、超车净宽、弯后视线、检查点 `Tr` |
| 章节挑战 | 每章的新动作包络、难度波形、长坠落回收和相机疲劳 |
| 机制/解谜 | 操作台多人站位、输入/输出同屏可见、重置区与运动对象净空 |
| 合作 | 双方视线、交接物扫掠、会合容量、等待者站位和缺员旁路 |
| 叙事/探索 | 地标视距、演出镜头、返回路径识别和强制控制后的重新定向 |
| 生存/淘汰 | 单位面积人数、换位距离、边缘缓冲、危险预告视距和观战镜头 |
| 积分/争夺 | 各出生到资源/热点的真实时间、视线暴露、侧翼与撤退成本 |
| 社交/展示 | 多人合影占位、镜头距离、交互排队、换景后的方向恢复 |
| 经营/模拟 | 工作台并发站位、运输通道、资源拾取半径、操作等待与扩建净空 |

## 标定记录表

| 上下文/动作 | 测试几何与条件 | 尝试与玩家 | 可靠范围 | 失败边界/原因 | 相机与多人备注 | 采用值 |
|---|---|---|---|---|---|---|

“采用值”必须说明用于教学、主流程、快线、恢复、多人或载具。若尚未测试，写 `TBD-PLAYTEST` 并使用可调参数，不输出假精确坐标。

## 空间验收

- 所有必经落点、门洞、弯道和机关窗都能反查到当前标定上下文；
- 舒适、掌握和极限动作没有混为同一尺寸；
- 目标人数下的净宽由占宽、间隔和边缘余量共同计算，并完成实测；
- 视觉表皮、真实碰撞和路线提示在边缘位置一致；
- 相机从进入、操作、失败到复位全过程都能看见必要信息；
- `Tr` 与本段目标难度匹配，没有因长坠落、动画或重跑放大挫败；
- 载具和特殊能力使用独立标定，不套步行参数；
- 未验证值明确保留为可调参数与试玩任务。
