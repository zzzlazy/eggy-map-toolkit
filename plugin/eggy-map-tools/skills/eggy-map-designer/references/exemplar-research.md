# 优秀地图研究

## 目标

把参考地图拆成可迁移的设计规律，并给每条结论标注证据来源。研究结果服务于原创设计，不复制完整布局或受保护素材。

## 证据层级

1. **元数据事实**：名称、简介、玩法人数、保存时间、统计字段、模式和公开系统。
2. **归档代码事实**：文件清单、单位数量、模型路径、变换、颜色、材质、物理、阴影、触发与资源结构。
3. **画面观察**：镜头、构图、路线提示、空间包裹、光雾和地标。
4. **设计推断**：为什么有效、可迁移到什么尺度、有哪些副作用。

报告中不要用画面猜出精确 EID，也不要把渲染批单位数量称为编辑器顶层组件数量。

## 案例覆盖状态

设计模板、类型合同和参数化装配只能证明“会怎样设计”，不能证明“优秀作品已经怎样做过”。需要经验背书时先读取 `eggy-map-designer` 的 `references/research-coverage.json`，或运行其 `scripts/audit_research_coverage.py --id <类型/修饰器/世界 ID>`：

- `verified_positive`：核心循环、恢复/终局、身份链与被引用结论均有直接证据；
- `partial_positive`：只能迁移覆盖账列出的有限结论；
- `boundary_only`：只用于排除标题、题材或封面的错误分类，不能填补正向参考轴；
- `missing`：保留结构化参考缺口，记录后续所需证据，不在设计技能中自行操作模拟器。

同一案例可以对世界构成是 `partial_positive`，对玩法类型却是 `boundary_only`。设计总账因此按 `primary_loop/world_grammar/spatial_scale` 等轴分别登记支持与缺口，不能给整张案例贴一个模糊的“参考过”标签。

## 可编辑地图

先用 `device_status` 确认设备与版本，再以 `list_maps(exact_name=...)` 获取唯一 `map_ref`，用 `inspect_map` 和 `validate_map` 只读分析。若同名多份，按保存时间让用户选择。

## 公共案例交接


内置或用户提供的匿名蒸馏案例至少应包含：

- 稳定匿名编号与版本范围，以及来源核对的范围；原始名称、地图码、作者和身份映射不得随案例公开；
- `元数据/代码/视觉/设计推断` 四类证据的清楚边界；
- 所支持的主循环、世界语法、空间尺度或修饰器轴，以及每轴的 `verified_positive/partial_positive/boundary_only` 范围；
- 至少一条可迁移原则、一条不可照搬项和一条仍待验证问题；
- 聚合统计的准确口径，例如渲染批单位、逻辑单位、编辑器单位和顶层组件不能混称；
- 原始地图归档、完整脚本、谜题答案、作者素材和临时截图不进入设计技能。

只有交接后的案例 Markdown 与机器覆盖账能成为设计输入。只有缓存 ID、封面、标题、搜索摘要、组件名称计数或高热度时，保持候选或边界，不在这里继续解析补全。

## 审计指标

至少记录：

- 目标时长、关卡/章节数、失败与恢复方式；
- 主路线拓扑、转折、高差、视线控制和出生第一屏；
- 渲染单位数、逻辑/触发复杂度、模型种类、基础几何占比；
- 模型、材质和颜色频次，路线色与危险色的语义；
- 非均匀缩放、倾斜、可见性、物理、阴影、远裁剪和合并策略；
- 高频机关及其在节奏中的位置，而不只列总数；
- 手工迭代、排行、成就、模式和长期进度等系统是否与地图尺度匹配；
- 可迁移原则、不可照搬项和仍需试玩验证的问题。

AI 搜索摘要、作者简介、首屏倒计时和缓存中的耗时字段可能使用不同口径或单位。它们只能用于提出候选；目标时长必须由完整试玩计时或已证实的字段单位确认，并把冲突原样记录。

## 参考覆盖组合

设计任务不按固定“必读地图清单”凑案例，而按本次方案真正需要的证据轴取最少组合：

- `primary_loop`：所选主类型的正向案例；混合图另需 `secondary_loop`，不能让相邻类型替代；
- `hybrid_relation`：同一有向主次、同一 `overlay/local_station/optional_branch/phase_shift` 组合方式的正向案例；两端各自有案例不能拼成这一轴；
- `world_grammar`：目标题材的轮廓、中层结构、接触层、比例锚点与状态变体证据；
- `spatial_scale`：与本图的微型空间、主题短图、多场景或长世界尺度相近；
- `modifier`：只有启用上涨、载具、恐怖、随机、成长、破坏等修饰器时才要求；
- `boundary`：至少一条与本次高风险误分类直接相关的反例，用于形成禁用项，绝不填正向轴。

同一案例确实直接支持多个轴时可以复用；只支持题材或首屏时不能顺带填玩法与尺度。某轴没有正向案例，就在设计总账写 `reference_gaps`、缺口原因和下一研究问题，同时继续使用类型合同做原创设计，但不得把合成模板伪装成经验背书。此包不采集新样本；公开案例只记录下一步所需证据，不把缺口伪装为已完成研究。
