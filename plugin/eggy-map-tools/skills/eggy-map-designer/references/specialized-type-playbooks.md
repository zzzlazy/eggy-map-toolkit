# 专项主类型设计蓝图

本文件补充那些不能被“竞速、章节、解谜、合作、叙事、生存、争夺、社交、经营”可靠代替的主循环。它们各自拥有独立的权威时钟、胜负或创作终局，因此应作为主类型，而不是只写成题材或机关清单。需要与其他类型组合时，先完成本页的主循环，再用 [专项混合类型模式库](specialized-hybrid-patterns.md) 限定次类型节拍、时间、入口/出口和清理边界。

需要把这些循环扩展成数百至数千个有职责的基础件实例时，读取 [专项主类型基础件套件](specialized-assembly-kits.md)；其中的装配数字是组织示例，不是类型配额或性能事实。

防守类已有 [《case-004》部分实证](exemplars/case-004.md)，可支持路线分期开启、波次反制、经济/人口/科研依赖、主动终局和后台单位按需激活；但未实际走过任何波次。纯音游、Boss、潜行、体育和创造沙盒目前都只有分类边界：分别读取 [节奏外观反例](exemplars/case-016.md)、[单目标 Boss 入口边界](exemplars/case-006.md)、[学校逃脱题材边界](exemplars/case-008.md)、[运动/足球详情边界](exemplars/case-021.md)和[固定配方建造边界](exemplars/case-011.md)；它们只能排除误分类，不能支撑主循环。回合策略与阵营推理仍无合格本地案例。所有暂定状态合同和验收方法都要在当前组件能力与目标人数下重新灰盒，任何案例都不为精确数值、节拍或性能上限背书。

## 类型边界

| 玩家反复做什么 | 主类型 | 容易误归为 | 判定边界 |
|---|---|---|---|
| 按统一时钟读取并命中谱面 | `rhythm_performance` | 节奏修饰器 | 谱面判定、连击和结算就是主终局；若只是竞速机关跟拍点同步，仍用原主类型加 `rhythm` |
| 识别招式、规避、制造输出窗口 | `combat_boss` | 生存/积分争夺 | Boss 阶段、生命和伤害提交决定终局，而非只活到时间或比谁分高 |
| 建设或选择防线，抵御分波威胁 | `defense_strategy` | 经营/生存 | 资源循环服务于“路径—防御—漏怪—核心”，波次和核心是权威终局 |
| 管理暴露，取得目标并撤离 | `stealth_infiltration` | 恐怖/非对称角色 | 侦测与警戒状态决定路线；恐怖可只是感官修饰，非对称则是玩家间角色协议 |
| 在离散回合中选择合法动作并结算 | `turn_based_strategy` | 解谜/积分争夺 | 活跃方、阶段和解析顺序拥有唯一权威，玩家不能随时并发提交 |
| 围绕一个比赛对象持续攻守并得分 | `sports_match` | 积分争夺 | 控球、界外、死球与重新开球是循环核心，而不是拾取后交分 |
| 玩家在局内摆放、修改并保留作品 | `sandbox_creation` | 经营/社交展示 | 放置合法性、所有权、预算、撤销和保存就是主循环；展示只是其后用途 |
| 在不完整信息下行动、讨论并判断隐藏阵营 | `social_deduction` | 非对称角色/叙事/积分 | 私密分角、会议/投票、淘汰权限和多阵营胜利条件共同拥有整局；只有不同能力或换色阵营仍是修饰器 |

`rhythm_performance` 不再叠加 `rhythm` 修饰器；二者同时出现是重复建模。其余类型可以使用修饰器，但必须说明修饰器如何改变主循环条件而不创建第二个终局。

## 纯音游 / 节奏演出 `rhythm_performance`

**职责与循环**：校准或倒计时 → 读取前置信号 → 在判定线上输入 → 得到同源判定/分数/连击 → 进入下一乐句 → 结算或重开。

**装配接口**：`CLOCK + CUE_LANE + HIT_LINE + RESULT_RING + COMBO_DISPLAY + RESET_DOCK`。轨道、判定面和结果反馈应由基础件组装成一套重复语法；装饰不能覆盖来向、判定线或结果位置。

**必须声明**：

- 一个时钟权威拥有谱面代次、音画时间、判定、分数、连击、暂停和完成；
- 至少两个可互相降级的提示通道，每个写前导时间、判定反馈和不可用时的替代；
- 判定窗、一次输入只消耗一个音符、早/晚/漏/重复输入和连击提交；
- 难度一次只增加密度、轨道、输入形态或遮挡中的一项，再组合；
- 静音、低闪烁、非颜色提示，以及暂停、死亡、重进和下一首的旧代清理。

**灰盒与试玩**：静音完整打一段；覆盖早、准、晚、重复和漏按；在代表性设备延迟两端测试；暂停/恢复与连续两段不残留旧音符。记录时间误差分布、纯视觉完成率、输入重复消费率、断连击归因和重开残留。

**待取样问题**：谱面如何在 3D 空间保持前读；多人是共享谱面、分轨还是轮换；音画与游戏帧抖动如何处理；高密度段如何保留无障碍降级。

[节奏外观边界案例](exemplars/case-016.md)已经证明 BGM、音符图标、发光线条和“加速鼓点”可以全部服务一张终点型障碍跑道。设计时先做去皮测试：移除音乐与霓虹后，如果玩家仍靠移动、跳跃、复位和冲线完成，保留原主类型；只有唯一谱面时钟消费输入并提交判定/连击/结算时才启用本节合同。该案不是纯音游正向样本。

## Boss / PvE 战斗 `combat_boss`

**职责与循环**：观察预告 → 选择躲避或反制 → 争取安全输出窗口 → 阶段转换 → 击败、团灭或重试。

**装配接口**：`ARENA_RING + ATTACK_LANE + SAFE_POCKET + WEAK_POINT_FRAME + PHASE_GATE + RESPAWN_OR_SPECTATE`。每种攻击用一致的“来源—覆盖区—安全边—结束”语法，Boss 模型不能独自承担碰撞和提示职责。

**必须声明**：

- 至少两个阶段，每阶段写预告、威胁、反制、转换和恢复；
- 唯一伤害权威校验来源、目标、无敌、生命、阶段锁和击败，重复命中不能多次结算；
- 玩家至少有两种有区分度的工具，明确用途、代价/冷却和反馈；
- 场地边界、安全恢复位、Boss 越界、玩家死亡/观战和回场；
- 多人只扩大持久压力或机会数量，不缩短个人最低反应窗；
- 最后一击、全员倒地、阶段伤害同帧时的优先级和完整重置。

**灰盒与试玩**：完全不输入观察首招；逐阶段单独测攻击包络；同时伤害、阶段阈值伤害、攻击中死亡、Boss 越界、全灭和第二次挑战。记录预告到命中的时间、伤害可归因率、场内无事可做时长、阶段时长、贡献差和团灭恢复时间。

**待取样问题**：优秀地图如何教会弱点而不靠长文本；多人倒地救援是否构成可恢复合作；基础件如何构成大体量 Boss 与可替换攻击族。

[Boss 入口边界案例](exemplars/case-006.md)显示“首屏回答打谁、还差几个、从哪里接近、先拿什么”是一项可单独审查的入口合同，也显示多武器与无敌控件若没有职责分组、试用和代价会增加认知或抹掉反制。该案没有实际战斗或可解释阶段图，因此在主类型覆盖账中仍是 `boundary_only`；这些入口观察只能形成设计假设，不能删去阶段、攻击包络、终局冲突和重试门检。

## 防守 / 塔防 `defense_strategy`

**职责与循环**：读取来路 → 在有限位置建设或选择 → 启动波次 → 观察目标与漏怪 → 获得资源 → 修正防线 → 守住核心或失败。

**装配接口**：`SOURCE + LANE + BUILD_PAD + DEFENSE_MODULE + LEAK_GATE + CORE + WAVE_BOARD`。路径结构、建设插槽、射程/职责提示和核心损伤必须是空间信息，不只存在于 UI。

**必须声明**：

- 核心的生命、漏怪记账、失败和外观状态；至少一条完整入口—路径—插槽—漏怪终点—卡怪恢复；
- 至少两波，每波写新增压力、预告、结束条件和清场；
- 建设槽的合法选择、占用、升级/退款与满容量分支；
- 敌人路径和当前波次是一处权威，防御只能锁定合法当前代目标；
- 击败奖励、购买、多人抢建、玩家退出和孤儿占用均为原子事务；
- 漏怪、波次结束、核心归零冲突时的优先级与连续波次/新局清理。

**灰盒与试玩**：空防线、铺满插槽、并发购买、卡路/改路、最后一只漏怪与过关同帧、建造者退出和第二轮波次。记录首次防守决策、路线压力差、资源闲置、各类防御贡献、漏怪归因和旧波残留。

**待取样问题**：UGC 可用组件能否稳定表达路径/仇恨/射程；一人和多人经济怎样缩放；如何用基础件在一屏内读懂多路压力。

[防守案例](exemplars/case-004.md)进一步说明资源、食物、人口、科研和职业必须共同服务下一波准备度，并支持“新路线先预告再激活”“后台人员按需激活表现”的方向；它没有实测建造、寻路、漏怪、连续波次或多人，因此上述能力仍是强制灰盒项。

## 潜行 / 渗透 `stealth_infiltration`

**职责与循环**：观察巡逻与遮蔽 → 穿越视野缝隙或使用工具 → 管理怀疑/警戒 → 提交目标 → 在变化后的空间撤离。

**装配接口**：`BRIEF + OBSERVATION_PERCH + COVER + SENSOR + OBJECTIVE + EXFIL + ALERT_RECOVERY`。遮蔽物、视锥边界、巡逻朝向和撤离地标必须在玩家镜头下相互可读。

**必须声明**：

- 至少四个检测状态及合法转换，例如未见、怀疑、警戒、搜索、重置；
- 每类传感器的范围/规则、预告、反制和恢复，检测方向与程度同源反馈；
- 遮蔽是否真的阻断视线，缝隙、反光或高差是否改变规则；
- 玩家工具的范围、持续、冷却与信息代价；
- 目标只提交一次，撤离从权威目标快照解锁，警戒不会复制目标或永久锁门；
- 多人的共享警报与个人信息边界，以及死亡、断线、重进和整局清理。

**灰盒与试玩**：巡逻空跑、视野边缘、同时被多个传感器发现、全警戒、先到撤离后取目标、警戒中死亡和恢复潜行。记录侦测归因、隐藏占比、单一路线支配、警戒恢复和撤离理解。

**待取样问题**：游戏内视线/触发能否提供可信边界；多人连坐或救援如何反馈；潜行失败是追逐、局部回退还是整段重置。

[潜行边界案例](exemplars/case-008.md)含学校逃脱叙事、监控红色表现和高密度室内装配，但没有视线、怀疑、警戒、反制、恢复或目标后撤离状态。设计评审时先用它做反事实检查：删去标题、封面和红灯后，如果路线仍只是按钮、风场、载具、检查点与终点，就应归章节跑酷，不得用潜行蓝图假装已有机制。

## 回合制棋盘 / 卡牌 `turn_based_strategy`

**职责与循环**：读取局面 → 当前行动者选择合法动作 → 锁定成本与目标 → 按顺序解析 → 判断终局 → 交给下一行动者或重赛。

**装配接口**：`BOARD + TURN_MARKER + ACTION_DOCK + RESOURCE_RAIL + RESOLUTION_STAGE + RESULT`。棋盘所有权、当前回合、合法目标和待解析动作应由形状/位置/状态共同表达。

**必须声明**：

- 唯一回合权威拥有当前玩家、阶段、动作序号、棋盘代次和结算；
- 至少三个阶段和两种合法动作，每种写前提、成本、效果与反馈；
- 资源、棋子、格子和效果在一次事务中提交，过期或非当前玩家输入无效；
- 私有手牌/意图与公共局面隔离，旁观者不能泄漏信息；
- 解析顺序、连锁上限、终局检查时点、超时和当前玩家掉线；
- 无合法动作、同时终局、平局、重赛同意和旧棋盘清理。

**灰盒与试玩**：空动作、同时输入、回合超时、当前玩家退出、旧 UI 延迟提交、平局和第二局。记录非法动作率、决策时长、局面可读性、非行动等待和结果可解释性。

**待取样问题**：世界空间棋盘如何避免镜头遮挡；等待玩家能做什么；复杂连锁如何不依赖长日志。

## 体育对局 `sports_match`

**职责与循环**：开球 → 争夺或传递比赛对象 → 进攻/防守转换 → 得分或出界 → 死球重启 → 常规结束、加时或结算。

**装配接口**：`FIELD + TEAM_SIDES + PLAY_OBJECT + GOALS + OUT_OF_BOUNDS + RESTART_MARK + SCOREBOARD`。边界、球门方向、中线、出生保护和重启点必须构成一眼可读的场地语法。

**必须声明**：

- 至少两队，出生/半场与颜色外的形状识别；比赛对象至少有自由、控制、争抢、死球和重置状态；
- 至少三个场区，各写用途与重启规则；
- 同时触球、控球转移、碰撞/抢断无敌和对象代次由一处权威解析；
- 出界后冻结得分，显示归属/地点，完成一次合法重启；
- 进球校验对象身份、方向、比赛状态并只加一次分；
- 乌龙、错误方向、出生堵塞、得分者退出、超时平局、加时和第二局重置。

**灰盒与试玩**：无人开球、同时触球、各边界出界、乌龙/反向入门、携球者掉线、超时平局和连续两局。记录出生到球、控球分布、得分归因、死球时长、角色贡献差和加时时长。

**待取样问题**：物理对象在延迟下的所有权；窄场/宽场对抢断和镜头的影响；无固定位置玩家如何仍获得贡献感。

[运动合集与足球题材边界](exemplars/case-021.md)显示十项运动合集更接近章节/题芯合集，而单球、球场封面和“连人带球一起踢”也不足以证明合法得分、场界或死球重启。该对照只到详情层，不能断言运行时没有相关逻辑；它的用途是阻止标题和封面越过体育主循环门槛。

## 创造沙盒 `sandbox_creation`

**职责与循环**：浏览目录 → 预览 → 合法性检查 → 放置 → 选择/移动/复制/删除 → 测试或展示 → 保存、继续或退出。

**装配接口**：`CATALOG + PREVIEW + VALIDATION + BUILD_AREA + BUDGET + UNDO + TEST_OR_SHOWCASE + EXIT`。编辑反馈与作品本体分层；预览件和测试代对象不能混入稳定存档。

**必须声明**：

- 至少三类目录，写用途与预算；至少四个建造状态；
- 边界、重叠、支撑、保护区、碰撞和类别配额在提交前共同校验；
- 每件作品有所有者与代次，编辑、移动、复制、删除权限明确；
- 总预算与个人预算显示当前、预估和阻止原因；
- 撤销对准上一笔合法事务，删除一次释放占用、引用和预算；
- 保存是带版本的完整快照，加载按顺序重建引用；测试模式冻结编辑并能无复制地返回；
- 多人同时编辑、所有者退出、未保存退出和会话清理。

**灰盒与试玩**：空世界、预算满、重叠放置、同时编辑同一物体、所有者退出、保存/重载、测试返回和退出清理。记录首次创造、编辑迭代、非法放置率、预算理解、撤销成功和协作者冲突。

**待取样问题**：游戏现有 UGC 能开放哪些局内建造动作；多人权限如何表达；复杂作品保存规模和加载时间；优秀沙盒如何把“能放东西”升级为有目标的创作体验。

[《case-011》](exemplars/case-011.md)的代码可证固定配方建筑的放置成功、占位检查、建筑上限、拆除返还和玩家 1 存档，但这些动作服务生存/经营依赖图。它只能作为 `boundary_only`：没有自由目录、预览、任意编辑、撤销、测试返回和创作快照时，不能因“能建造并保存”就启用创造沙盒主类型。

## 阵营推理 / 社交推理 `social_deduction`

**职责与循环**：私密分配角色 → 在共享场域完成任务、制造事件或观察行为 → 合法报告/召集 → 冻结场上动作并讨论 → 提交一票 → 解析淘汰/跳过 → 检查阵营终局或回到场上。

**装配接口**：`PRIVATE_BRIEF + FIELD_NETWORK + TASK_OR_EVIDENCE_STATION + INCIDENT_THRESHOLD + MEETING_HUB + VOTE_POD + AFTERLIFE_ROUTE + RESULT_REVEAL`。空间既要制造可观察的路线与时间成本，也要避免通过出生位置、专属颜色、共享模型或镜头直接泄露身份。

**必须声明**：

- 一个回合权威拥有代次、角色分配、阶段、存活名单、任务/事件、会议、选票和终局锁；每人恰有一个当前角色；
- 至少两个阵营/角色，每个写私密知识、独占动作、公开可观察痕迹与反制，角色信息只发送给合法玩家；
- `BRIEF/FIELD/REPORT_LOCK/DISCUSS/VOTE/RESOLVE/TERMINAL_OR_FIELD` 等阶段的合法输入、超时和交接；会议开始要冻结或取消场上攻击、任务占用和旧报告；
- 任务、证据、破坏或淘汰机会的所有者、空间成本、一次性提交、重复/越序保护和被打断恢复；系统只提供玩家按规则应知的信息，不输出隐藏真相日志；
- 投票资格、每人一票、修改/锁定、弃权、未投、平票、匿名程度、当前行动者掉线和解析时点；
- 淘汰者失去哪些碰撞、报告、投票、攻击、破坏、任务和信息权限；旁观/灵魂玩法不能改变未声明的阵营结果或泄密；
- 每个阵营至少一个权威胜利谓词，以及任务完成、关键破坏、人数相等、最后淘汰同帧时的优先级；终局只提交一次；
- 角色掉线/迟到时的重分配、中立化、机器人或安全终止，以及第二局重新分角、私密 UI、选票、尸体/事件和冷却清理。

**空间与信息设计**：中心会议区只在会议期成为焦点；场上采用可回环的房间网络，任务点与关键通道形成可观察但非唯一的路线选择。公共状态用位置、门、灯和设备变化表达，私密能力只在本人界面或不会被他人镜头读到的载体上表达。不要让某角色出生在唯一专属房间，也不要用阵营色贯穿其可见外观。

**灰盒与试玩**：完全不输入、重复分角、同时报告、会议锁定时晚到的场上动作、同一人重复投票、平票、行动角色掉线、淘汰者尝试影响结果、旧私密输入延迟提交和连续两局。记录角色理解率、任务/证据推进速度、会议无效等待、选票归因、身份泄露率和终局可解释性。至少用目标人数测试；单人代码与机器人不能证明社交信息、公平或讨论节奏。

**降级边界**：若当前能力无法可靠提供私密角色、会议冻结、每人选票和淘汰后权限，降级为公开非对称合作、阵营积分或叙事谜案，不能只靠玩家自觉和标题声称是阵营推理。

**待取样问题**：私密 UI/消息在当前 UGC 的可信边界；语音或快捷交流缺失时怎样提供足够讨论；任务是否制造可推理的时间/空间痕迹；多人掉线、迟到和观战如何不泄密；成熟作品怎样控制会议频率和无效争论。

## 证据晋升

每类至少需要一张身份链完整、成功进入单人、代码可读且新增结构知识的样本。要把“暂定蓝图”晋升为“部分实证”，还应至少完成一次核心循环或观察到对应终局，并验证一个异常场景。多人归属、公平或私有信息结论必须有目标人数实测，不能由单人缓存推断。
