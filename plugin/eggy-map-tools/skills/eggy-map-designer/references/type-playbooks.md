# 常见类型设计蓝图

本文件把九种常见类型原则变成可直接展开的设计骨架。纯音游、Boss/PvE、防守、潜行、回合策略、体育对局、创造沙盒与阵营推理另见 [专项主类型设计蓝图](specialized-type-playbooks.md)。它们都不是固定关卡配方：先按主循环选一个主类型，再按需要叠加一个次类型或结构修饰器。确实选择次类型时用 [混合类型地图模式库](hybrid-map-patterns.md) 定义组合方式、权威终局和状态交接。短竞速、章节、解谜、合作、叙事和社交展示需要从本页的“装配种子”继续展开时，读取 [线性与体验型地图基础件套件](linear-and-experiential-kits.md)；数量均为组织示例，不是硬配额，实际规模由目标时长、视距、玩家数量、组件能力与目标设备决定。

## 证据状态

使用三种标记：

- **实证**：身份和代码已核对，并有足以支持该结论的画面或试玩；
- **部分实证**：已有代码/首屏证据，但缺完整试玩、多人或后段验证；
- **暂定蓝图**：来自通用关卡约束，尚无合格本地案例，设计时必须列为待验证假设。

## 所有类型共用的蓝图页

每张设计先填一页，不直接跳到组件坐标：

1. **体验契约**：目标人数、局长、操作门槛、主情绪和记忆点；
2. **玩家决策图**：重要节点、可选边、恢复边和终局；
3. **节拍/回合表**：每拍的新信息、主要动词、失败损失、反馈和耗时；
4. **状态闭环**：准备、开始、进行、阶段变化、胜负/离场、清理与重置；
5. **装配族**：路线或场域模块、环境壳体、中层结构、交互底座、地标和反馈件；
6. **展开预算**：按区域与 `COL/MASS/MID/ROUTE/MECH/PROP/FX/LOGIC` 对账；
7. **试玩指标**：只记录能决定下一次修改的数据。

若某一类型不需要传统胜负，也必须定义玩家如何完成一次有效循环、如何离开活动、如何重新定向。

## 短竞速

**循环骨架**：定向与起跑 → 低风险教学 → 连续流动 → 一次路线选择或动作变奏 → 已学动作组合 → 清楚冲线。

**装配种子**：建立 `RUN_STRAIGHT`、`RUN_TURN`、`RUN_LANDING`、`RUN_RISK`、`RUN_FINISH` 五族。每个路线模块至少区分接触面、侧脸/厚度、支撑或护栏、路线色和可选装饰；“一块拉长地板”只能算灰盒。用 `路线模块展开 × 放置数 + 转折地标 + 机关底座 + 终点框景` 估算成品量。

**关键状态**：起跑保护、计时、检查点提交、掉落复位、越过检查点、冲线和结束后机关停机。全局上涨或追逐危险还要定义启动预告、最慢可接受路线、被追上后的处理。

**只测这些**：出生后首次正确移动时间、连续停顿、超车点拥堵、每个检查点的重跑损失、快慢线收益、终点误入率和中位/高分位通关时间。

## 章节挑战

**循环骨架**：章节地标预告 → 新动作教学 → 两到三次有意义变奏 → 局部高潮 → 检查点与景观换章。难度做波形，不做单调递增直线。

**装配种子**：每章至少有一套独有的环境壳体或地貌族、一套共享接口件和一个远期地标；壳体不能只换颜色。先分别预算每章的 `MASS/MID/PROP`，再预算贯穿全图的路线、检查点和远景，避免前两章精致、后段裸露。

**关键状态**：章节进入、检查点、局部目标、越界回收、一次性触发幂等、跳章防护、最终完成和重进后的清理。长图的失败损失应收敛到章节尺度。

**只测这些**：每章理解时间、连续失败次数、重跑距离、章节辨识率、视觉疲劳、性能峰值和玩家在哪一章退出。

## 机制/解谜

先声明结构模式。`curriculum` 课程型复用一个规则族，循环是“安全展示 → 亲手验证 → 每次只改一个变量 → 组合 → 迁移 → 回收”；`anthology` 合集型允许每个房间更换题型，但每房间都必须重建“读题/观察 → 输入 → 正误反馈 → 局部复位 → 完成提交”。谜底可以未知，规则与合法动作不能靠猜。

**装配种子**：为每个机制站建立 `入口净空 + 规则面 + 输入台 + 状态框/连线 + 变化对象 + 结果框景 + 重置台 + 恢复/出口`。基础件主要用于把因果关系画在空间里：同色边框、管线、方向符号和开合结构；装饰不得遮住输入与输出。课程型复用同一底座语法并只改变变量轴；合集型复用房间壳体、层牌、入口、提示、检查点和出口接口，局部题芯与语义色再变化。

**关键状态**：`ENTRY/OBSERVE/INPUT/RESULT/LOCAL_RESET/COMPLETE/RETURN`，以及初始值、合法/错误/重复/越序输入、完成锁和重置代次。一次性物件、被携带物和多人不同步必须有恢复路径。延迟提示只在当前单元活跃且未完成时计时；有效进展、完成、离开或重置都要取消旧提示回调，提示事件保持幂等。

**只测这些**：入口是否清楚、玩家能否复述当前单元规则、第一次错误后是否知道错因、首个提示触发率、提示依赖率、无进展时长、局部重置耗时/成功率、检查点恢复、房间重进、越序软锁和组合段的错误类型。[八层密室案例](exemplars/case-007.md)支持“题芯可异构、接口应统一”的结构，但未实测任何谜题完成或复位；所有谜题时限、提示阶梯和难度仍需重新设计。

## 双人/多人合作

**循环骨架**：认识角色能力 → 一次宽松的单向帮助 → 对方回馈 → 能力换位或交接 → 两种能力组合 → 共同收束。合作机会必须在双方之间往返。

**装配种子**：为角色建立稳定的颜色/形状族，为每次交接建立 `A 输入 + 世界变化 + B 落点/操作 + 回馈路径 + 会合框景`。两侧可以共享结构接口，但不可仅镜像装饰。重复四到八个交接模块时，让因果语法一致、空间动作变化。

**关键状态**：角色绑定、能力授予、双方进度、交接完成、任一人重生、重复进入、越序、掉线/缺员降级、检查点和终点。若允许单人，单人是一条明确状态分支，不是碰巧绕过机关。

**只测这些**：每名玩家主动操作占比、最长连续等待、对方动作可见率、交接误解、两人同时失败、掉队恢复、额外玩家拥堵和单人分支完整性。

## 叙事/探索

**循环骨架**：出生定调与远期诱饵 → 主动移动发现 → 跨门/登高/回望触发事件 → 环境或关系状态变化 → 返回旧地看见差异 → 选择收束或继续探索。

**装配种子**：先做地标网络和场景壳体，再做状态变体与近景发现簇。每个重要节点应有到达框景、可达中景、远期诱饵和清楚出口；把高密度用在揭示镜头、互动近景与状态变化处，移动过渡段可以留白。文字只补充世界观，不承担唯一导航。

**关键状态**：事件未触发/播放中/已完成、控制模式、场景变体、当前目标、关系值、选择历史、必要对象归属、返回时的持续状态、跳过演出、死亡/退出恢复、多个事件同时满足和结尾后的控制权。一次事件按 `门槛 → 锁重复入口 → 接管镜头/控制 → 决策 → 原子提交场景/任务/关系 → 归还控制并重新定向` 设计。

**只测这些**：首次迷路点、玩家漏看的事件、强制停顿时间、回访变化识别率、可选发现率、文本阅读与移动冲突，以及结束后是否知道去向。

[《case-017》](exemplars/case-017.md)直接支持“选择在下一个节拍改变 NPC/设施、目标、指引或关系”的方法，也支持固定镜头与自由控制之间要有清楚交接；但只观察到前段，不能证明结局、回访和恢复可靠。[《case-003》](exemplars/case-003.md)补充了工业入口、超大室内、基础件高展开和入口 UI 遮挡边界，但没有观察实际场景转场或任务完成；混合尺度章节必须为每个场景声明建立镜头、尺度锚点、入口/出口、状态快照和清理所有者。[《case-019》](exemplars/case-019.md)继续为“世界对象承载任务状态、章节完成后明确交接”提供对照。涉及叙事时把事件前、提交瞬间、归还控制、回访和重进画面列为必测。

## 生存/淘汰

**循环骨架**：安全观察 → 单一危险教学 → 波次或场地变化 → 危险组合 → 安全空间收缩 → 快速终局。危险先让玩家归因，再增加速度、密度或组合。

**装配种子**：用可重复竞技场扇区、边缘包边、危险底座、安全区边框和观战框景构成场域。装饰层尽量非碰撞；所有会改变走位的结构都进入公平审计。可复制扇区形成高实例量，但 A/B/C 变体只能改变视觉表皮，不得偷偷改变一侧通行优势。需要扇区参数、波次场域和数百件展开账时读取 [生存、争夺与经营基础件套件](nonlinear-and-economy-kits.md#一生存竞技场套件)。

**关键状态**：准备保护、统一开始、存活/淘汰、观战、波次切换、危险清理、平局、无人存活、终局停机和下一局重置。生成物和持续运动机关不得污染下一局。

把 `ROUND`、`MODE`、`FIELD_EVENT`、`WEATHER` 和每名玩家的 `PLAYER_LIFE` 分开。回合控制器唯一决定是否允许危险、是否结算和是否重置；模式只配置生命/得分线/候选池，场地与天气各自遵守 `SELECT → TELEGRAPH → ACTIVE → CLEANUP`，玩家生命只负责活跃、重生、淘汰与观战。随机场地与天气可叠加时先做兼容矩阵，不让两个系统各自直接宣判终局。

**只测这些**：各出生点首个安全选择、取得控制后的无输入基线、危险来源识别、阶段提示识别、无解组合、永久安全角、边缘卡位、淘汰后等待、终局长度、平局和重置残留。[最小案例](exemplars/case-018.md)只证明 60 秒计时与掉落板能闭环，并以首屏失足暴露安全观察缺口；[高复杂度案例](exemplars/case-022.md)证明多模式、随机事件、天气、生命/观战和高实例场域可以共同存在，也以无法跳过的奖励弹窗暴露入口层缺口。两案均未实测多人公平、完整波次或连续重置。

## 积分/争夺

**循环骨架**：公平出生 → 获取低风险资源 → 争夺高价值热点 → 带资源撤离或转换得分 → 热点迁移 → 追赶窗口 → 明确结算。

**装配种子**：把场地拆成对称或经行进时间校准的出生扇区、资源台、冲突热点、侧翼路径、撤离/得分区和中性地标。视觉变体可以表现阵营，但碰撞、视线和真实路程必须单独测量，不能用外观对称代替公平。需要资源节点、热点广场、得分口和反雪球账本时读取 [生存、争夺与经营基础件套件](nonlinear-and-economy-kits.md#二积分争夺场套件)。

**关键状态**：队伍绑定、比分、资源归属、携带/掉落、重复计分、热点刷新、领先/落后状态、平局、时间结束、玩家中途加入和整局清零。

**只测这些**：各出生到首资源/热点的真实时间、强位置暴露与反制、领先者资源占比、追赶机会、击败/得分来源可读性、平局和赛后残留。[擂台案例](exemplars/case-009.md)直接支持选装、阵营、比分和返场需要分层，也证明千件级场域可由极窄资产词汇展开；单人观察不支持任何 3V3 公平或反雪球结论。

## 休闲/社交/展示

**循环骨架**：出生看见中心、近处活动和远处诱饵 → 到达地标 → 合影/表达/轻玩法 → 换景或返回中心 → 重新汇合。没有传统终点，也要能完成一次有效会话循环。

**装配种子**：中心用主地标族，外围每个场景用一套合影框景、活动台、座位/站位、导视门架和景观簇。高密度优先服务人物轮廓和拍照构图，互动区保留多人净空；不可达植被、雪、云和远景默认无物理、少投影。

**关键状态**：进入定向、交互占用、换景、返回中心、多人走散、临时外观/文字/召唤物清理和再次进入。高频交互不能被一人永久独占。

**只测这些**：首次有效行动时间、主要地标到达率、活动停留、回流时间、多人镜头遮挡、交互排队、闲置玩家可做的事和离开后状态清理。

## 经营/模拟/建造

**循环骨架**：领取或发现输入 → 加工/运输 → 在制品/成品 → 上架或交付 → 顾客/目标结算 → 选择升级或扩建 → 新瓶颈出现 → 阶段目标/主动离场。局部货物事务和跨循环目录是两层状态：数字增长必须对应可见的空间、容量、并行度、自动化或能力变化。

**装配种子**：按功能建立订货/采集区、储藏、加工站、在制品缓冲、运输线、上架/交付台、顾客/需求入口、结算台、升级展示和下一阶段扩建接口；每个站点用一致的底座、输入/输出、状态面和容量表达。基础件大量用于厂房/店铺壳体、货架、容器、管线、桌位和进度可视化，但玩家高频操作面保持净空。需要生产单元接口、店铺站点、四站小型工厂和可见经济展开账时读取 [生存、争夺与经营基础件套件](nonlinear-and-economy-kits.md#三经营与建造套件)。

**关键状态**：资源/货物唯一 ID、类型、数量、所在容器、归属、容量、批次、加工中、完成、领取、上架/交付、顾客/订单、员工认领、升级、必需解锁集合、终点解锁、断线/重进、多人同时操作和新局清零。全局进度从权威解锁集合复算，不能由多个购买按钮随意累加；满足条件后先锁完成快照，再开放唯一结算/出口。若无法可靠持久化，必须把体验限定为单局闭环并明确说明。

**只测这些**：首次完整循环时间、每阶段瓶颈、无操作等待、货物丢失/复制、容量堵塞、顾客/员工孤儿任务、升级是否改变决策、目录进度可读性、终点状态与目录是否一致、多人抢占、权威保存者缺席、加载重建和经济软锁。[海岛案例](exemplars/case-011.md)支持依赖图、生存压力、建筑上限、拆除折损和世界快照；[烘焙店案例](exemplars/case-014.md)支持局部货物链、员工/顾客角色、`0/25` 式目录和主动胜利出口。两案都未实际走完生产、升级或重进，所有数值、调度和平衡仍需实测。

## 专项主类型

当下列系统本身决定整局成功、失败或作品保存时，选择主类型而不是修饰器，并读取 [专项主类型设计蓝图](specialized-type-playbooks.md)；它们与常见类型组合时再读取 [专项混合类型模式库](specialized-hybrid-patterns.md)：

- `rhythm_performance`：谱面时钟、判定、分数和连击拥有终局；
- `combat_boss`：Boss 阶段、伤害和击败/团灭拥有终局；
- `defense_strategy`：路径、波次、核心与漏怪拥有终局；
- `stealth_infiltration`：检测、目标提交与撤离拥有终局；
- `turn_based_strategy`：当前行动者、阶段与解析顺序拥有终局；
- `sports_match`：比赛对象、死球重启与合法得分拥有终局；
- `sandbox_creation`：玩家放置、权限、预算和保存组成主循环。
- `social_deduction`：私密角色、任务/证据、会议/投票、淘汰权限和阵营条件共同组成终局。

其中纯音游不再叠加 `rhythm` 修饰器；节奏只改变竞速、战斗或其他主循环条件时才使用修饰器。

## 可叠加的结构修饰器

这些不是独立主题，应附着在一个主类型上。下列只是路由摘要；实际启用时读取 [结构修饰器蓝图](modifier-playbooks.md) 填权威、包络、恢复、清理、专项指标与最坏场景。两个以上并用时逐对检查兼容性。

- **上涨/追逐/倒计时压力**：用一个持续可见的世界状态迫使前进；验证预告、最慢可接受路线和被追上后的恢复，不要只改一个简介数字。
- **护送/收集/伙伴**：把对象本身作为可见进度；每章写“需要对象 + 玩家动作 + 完成区域 → 世界反馈 + 恢复”。
- **载具/驾驶**：先用载具转向半径、加速/刹车距离、车身净空和跟随镜头决定赛道宽度、坡度、弯角与护栏；步行尺度不能直接套用。
- **躲藏/搜寻/非对称身份**：分别写搜寻者和躲藏者的信息、能力、反制和终局；消除永久无风险藏点，保证失败来源可解释。
- **节奏/音游**：声音之外提供可提前读取的视觉拍点，明确判定窗、连击中断、延迟容错和静音可玩性；装饰动画不能冒充判定反馈。
- **恐怖/悬疑**：恐怖是信息与节奏修饰器，不是把画面调黑；保留接触面和出口可读性，用安全—预告—揭示—恢复控制张力。
- **垂直攀爬/坠落**：逐层给出上方目标与下方回收关系，验证相机仰俯、头顶遮挡、长坠落等待和捷径越序。
- **随机/程序变化**：随机值只在预先定义的可解范围内变化；记录种子/选择、预告、重复抽取、极端组合、公平和重置，不能用随机掩盖内容不足。
- **累计能力成长**：把输入计数、夹紧后的权威能力值、反馈档位和检查点快照分开；至少在最低、中段、最高三档重新标定空间、相机和碰撞，终局与新局清除旧能力。

## 蓝图验收

在进入坐标或部署前回答：

1. 主类型的循环是否能用一行箭头写完；
2. 每个节拍是否改变信息、动作、风险、空间或关系中的至少一项；
3. 状态机是否覆盖失败、越序、多人、终局和重置；
4. 装配族是否能真实展开为场所，而不是把大地板与机关换个主题色；
5. 成品展开预算是否按关键镜头与类型职责分配；
6. 引用的案例结论是否没有越过其证据状态；
7. 暂定蓝图是否明确列出必须由试玩或未来案例验证的假设。

任一项答不清时，保持“概念/灰盒”标签，不输出貌似精确的最终坐标清单。
