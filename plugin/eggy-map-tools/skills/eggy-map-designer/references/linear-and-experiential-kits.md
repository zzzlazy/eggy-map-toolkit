# 线性与体验型地图基础件套件

本文件把短竞速、章节挑战、机制/解谜、合作、叙事/探索和社交/展示六种主类型，展开为可参数化的基础件装配族。玩法循环与状态合同仍以 [常见类型设计蓝图](type-playbooks.md) 为准；这里专门回答“怎样把灰盒路线变成有包裹、有结构、有信息层级的数百至数千件场所”。

件数均为**组织示例**，不是最低配额、性能上限或公共作品的复制值。先根据真实空间合同选择密度档，再按 [基础件装配与成品密度](assembly-and-density.md) 对账；使用 [参数化装配与坐标展开](parametric-layout.md) 生成唯一实例，并用 [性能与降级预算](performance-and-budget.md) 测峰值。不能为了达到示例数字，把无职责微件撒满地图。

## 证据边界

- [《case-024》](exemplars/case-024.md)支持封闭短竞速的连续包裹、危险色和窄资产高复用，但未验证 90–120 秒时长、多人并行与终点复位。
- [《case-005》](exemplars/case-005.md)支持长章节的宏观体量、颜色引导和批量性能职责；缺少中后段可控画面与完整试玩。
- [《case-007》](exemplars/case-007.md)支持异构题芯共享房间接口、提示与逐层恢复的代码骨架；没有完成任何谜题。
- [《case-015》](exemplars/case-015.md)支持角色能力、空间交付物和单人降级方向；没有双人实测。
- [《case-017》](exemplars/case-017.md)支持地标、镜头/控制交接与场景状态变化；只观察到前段。
- [《case-020》](exemplars/case-020.md)支持三层景深、换景线索与装饰性能职责；没有完整地标网络和多人停留实测。

所以本页能提供结构起点，不能替任何方案宣称精确跳距、等待时长、谜题质量、合作公平、剧情恢复或多人镜头已经通过。

## 共用分层与接口

每个装配族先声明局部 `U/V/F`、宽高深、入口/出口、玩家与镜头净空、共享接口所有者、A/B/C 变体和职责层：

- `COL`：少量连续接触面、墙体、落点、边界与真实遮蔽；
- `MASS`：山体、建筑、舞台、地标和不可达远景的大轮廓；
- `MID`：梁柱、侧脸、厚度、护栏、檐口、管线、门窗和结构接缝；
- `ROUTE`：接触表皮、方向边、落点框、章节门槛、回流线和会合口；
- `PROP`：承担比例、功能或叙事线索的近景簇；
- `STATE_FX`：只从权威状态派生的门、灯、标牌、裂纹、目标和反馈面；
- `MECH/LOGIC`：机关、输入、检查点、事件与控制器另计，不靠大量视觉件复制逻辑。

重复表皮默认无物理、少投影且静态；连续碰撞代理负责通行。共享墙、梁、边线和转角只能由一侧计数。变体应改变轮廓、朝向、视线、用途或状态，不以随机旋转微件制造假丰富。

## 一、短竞速 `short_race`

### 路线跨 `RACE_ROUTE_BAY`

参数：跨长 `D`、净宽 `W`、净高 `H`、中心线曲率 `K`、风险侧 `RiskSide`。入口/出口沿中心线相切；每跨必须给下一跨至少一个可提前读取的方向信号。

| 子结构 | 单跨展开种子 | 职责 |
|---|---:|---|
| 连续接触与边界代理 | 1–4 | 真实跑面、侧挡、掉落与复位边 |
| 跑面表皮、侧脸与厚度 | 8–24 | 让道路不是一张拉长平板 |
| 支撑、桥架或地貌连接 | 6–20 | 解释悬空/高差并建立中层节奏 |
| 路线边、落点框与转向标 | 5–16 | 先于危险说明速度方向和下一动作 |
| 机关标准底座与扫掠框 | 0–2 组，每组 5–14 | 让真实机关范围可读，机关本体另计 |
| 壳体、远景接口与收缝 | 6–20 | 连成主题世界，默认不改变碰撞 |

单跨约 26–98 个空间实例。A 流动、B 转折、C 风险/恢复变体共享净宽与接口；不能把直跨整体旋转后留下反向提示、悬空端头或镜头盲角。

### 全程装配族与示例

- `START_GATE`：出生缓冲、第一视线、目标和低风险动作预告；
- `RACE_ROUTE_BAY × N`：直线、转弯、落点、风险和恢复跨按节拍组合；
- `OVERTAKE_POCKET`：短并行或风险收益分流，回接处保留多人净宽；
- `LANDMARK_TURN`：在主要方向变化处同时承担远期地标和路线确认；
- `FINISH_FRAME`：终点从前一拍可见，冲线面、减速区、结果与退出不重叠。

十跨主题短图示例：路线跨 `10×64=640`、出生/终点 170、三个转折地标 150、连续环境壳体 260、机关底座与状态反馈 120、远景及收缝 90，共约 **1,430 个空间实例**；检查点、危险本体与逻辑另计。最坏视区不应同时看见全部十跨，需用转角、门槛、体量或雾化自然分区。

## 二、章节挑战 `chapter_challenge`

### 章节场景包 `CHAPTER_SCENE_PACK`

每章参数：空间包围盒、动作身份、视觉身份、入口地标、高潮节点、检查点、失败回收和下一章建立镜头。一章不是“换一套颜色”，而是由若干路线跨与独立壳体共同形成一段可复述场所。

| 子结构 | 单章展开种子 | 职责 |
|---|---:|---|
| 3–7 个路线/平台/桥跨 | 150–420 | 教学、变化、组合与高潮 |
| 章级大轮廓与连续包裹 | 80–260 | 从远处区分本章并遮住兜底底板 |
| 中层结构与比例锚点 | 50–180 | 梁柱、岩层、设备、屋面或街巷关系 |
| 入口、检查点和出口框景 | 25–75 | 明确章节边界、恢复和下一方向 |
| 状态/危险底座与反馈 | 20–80 | 显示局部目标、机关阶段和完成 |
| 近景主题簇与收缝 | 30–120 | 强化关键镜头，不平均铺满过渡段 |

单章约 355–1,135 个空间实例，取决于空间跨度而非章节名称。相邻章至少在高差、朝向、轮廓、动作或材料结构中改变两项；共享检查点门架、远景和接口只由一个所有者计数。

四章长挑战示例：四个场景包 `4×610=2,440`、跨章交通与回望框 360、贯穿远景 520、终章地标/收束 300、全图导航与收缝 180，共约 **3,800 个空间实例**。若四章物理分离或存在明显尺度转换，不能因总数较低倒选 `themed_short`；应从 `multi_scene` 或 `long_world` 的空间合同评估。

## 三、机制/解谜 `mechanism_puzzle`

### 谜题房间单元 `PUZZLE_ROOM_CELL`

参数：房间宽深高、规则面朝向、输入数、结果状态数、重置口和出口。课程型让房壳和输入—结果语法稳定，只改变一个规则变量；合集型可换题芯，但入口、观察、输入、反馈、重置、完成和恢复接口保持一致。

| 子结构 | 单房展开种子 | 职责 |
|---|---:|---|
| 连续地面、墙与门洞代理 | 2–7 | 真实房间、越序边界和出口状态 |
| 房壳表皮、梁柱与顶面 | 35–110 | 建立空间厚度和章节辨识 |
| 规则面、连线和状态框 | 15–55 | 把因果画在空间中，不只写长文字 |
| 输入台、对象位与操作净空 | 每输入 6–18 | 清楚区分可操作、已提交与锁定 |
| 结果框景与完成变化 | 12–40 | 正确、错误、冷却和完成同源反馈 |
| 提示、重置、检查点与出口载体 | 15–45 | 支撑渐进提示和局部恢复 |
| 功能道具、比例件与收缝 | 15–60 | 服务题意与镜头，不遮输入输出 |

单房通常约 100–335 个空间实例，真实题芯和逻辑另计。状态面只保留少量可替换件，不能让整个房间数百件各自监听答案。

六房合集示例：六个房间 `6×205=1,230`、共享竖向/中心交通 260、层牌与恢复门槛 110、外部壳体和远景 360、终局回望与收缝 140，共约 **2,100 个空间实例**。课程型也可用四个更精细的同规则房间，但每房必须改变观察、输入或空间迁移，而非只加步骤数。

## 四、双人/多人合作 `cooperative`

### 交接单元 `COOP_HANDOFF_CELL`

参数：角色 A/B 入口、独占动作、世界变化、对方机会、回馈边、会合口和缺员旁路。合作信息要穿过空间，不能只在双方各自 UI 中发生。

| 子结构 | 单交接展开种子 | 职责 |
|---|---:|---|
| 双侧接触与连续边界代理 | 2–8 | 保持角色路线、视线和恢复点一致 |
| A/B 侧结构与形状身份 | 20–70 | 用形状＋位置区别角色，不只靠颜色 |
| 输入台与世界变化框 | 12–40 | 让 A 的动作在 B 的镜头中可见 |
| B 机会、回馈路径与会合框 | 18–55 | 完成因果往返而非单向开门 |
| 同步/占用/恢复状态件 | 8–25 | 等待、成功、失败与重置同源显示 |
| 壳体、远景接口与收缝 | 12–45 | 把双线包进同一世界并保留互看窗口 |

单交接约 72–243 个空间实例。A/B 变体可以交换角色、改变高差或交付物，但独占动词与反馈方向必须清楚；镜像表皮不是新的合作动作。

八次交接短合作示例：交接单元 `8×135=1,080`、角色教学/绑定 120、三处共享会合与检查点 180、连续壳体和远景 320、终点共同收束 120，共约 **1,820 个空间实例**。单人降级所需旁路、替代能力和提示是状态分支，不得偷偷把双人关键结构全部做成可绕过。

## 五、叙事/探索 `narrative_exploration`

### 地标场景单元 `LANDMARK_SCENE_CELL`

参数：地标轮廓、到达框景、近景发现、可见出口、返回边、事件状态和前后版本。先完成能无文字导航的地标网络，再增加镜头、角色与文本。

| 子结构 | 单地标展开种子 | 职责 |
|---|---:|---|
| 大体量与地平线轮廓 | 25–100 | 从前一节点建立远期诱饵和比例 |
| 可达中景、入口与门槛 | 25–90 | 把远景变成可走的路线和揭示镜头 |
| 立面/地貌中层结构 | 45–160 | 门窗、檐口、台阶、梁柱、岩层或设施关系 |
| 近景功能/叙事道具簇 | 25–100 | 提供可观察线索，不平均堆满全场 |
| 事件/目标/状态变体载体 | 12–55 | 前后场景从统一剧情状态派生 |
| 回流、重新定向与收缝 | 15–60 | 返回后读出变化并找到下一出口 |

单地标约 147–565 个空间实例；不可达背景与状态备用件分别记录峰值可见，不把所有版本同时算作玩家看到的完成度。

四地标探索示例：四个地标单元 `4×410=1,640`、三段过渡/回望路线 390、跨场远景和世界边界 520、出生/结局/返回中心 260、状态变体与氛围收缝 310，共约 **3,120 个空间实例**。每次状态变化至少改变人口、设施、路线、目标或环境中的一项；仅换对白不需要复制整套场景。

## 六、休闲/社交/展示 `social_showcase`

### 社交目的地 `SOCIAL_DESTINATION`

参数：目标人数、合影主向、活动容量、到达口、离开/回流口、占用反馈和背景层级。人物轮廓与镜头净空优先于表面微件。

| 子结构 | 单目的地展开种子 | 职责 |
|---|---:|---|
| 主轮廓与合影框景 | 20–75 | 让目的地从中心可辨，并提供记忆画面 |
| 站位、座位与多人净空边 | 8–35 | 支持目标人数，不用装饰侵占镜头 |
| 活动台、入口与离开接口 | 12–45 | 构成到达—活动—离开/返回循环 |
| 中层景观、前景框与侧景 | 30–110 | 形成近中远层次，避免平面布景 |
| 占用、轮换与状态反馈 | 5–20 | 从会话状态派生，避免永久独占 |
| 远景接口、导视与收缝 | 18–65 | 连接中心并保留下一处诱饵 |

单目的地约 93–350 个空间实例。A 合影、B 轻互动、C 表达/换景可以共用到达和回流接口，但必须提供不同的可做之事，不是三套只换主题资产的相框。

中心加五目的地示例：中心主地标 360、五个目的地 `5×225=1,125`、环路/支路与换景门 310、不可达景深和边界 470、导视/重聚/退出 150，共约 **2,415 个空间实例**。远景、植被、云层和观众轮廓优先关闭物理及不必要投影；互动台和站位保留连续碰撞与满员测试。

## 十七类装配路由与共同验收

三份套件共同覆盖全部主类型：

| 装配资料 | 主类型 |
|---|---|
| 本文件 | `short_race/chapter_challenge/mechanism_puzzle/cooperative/narrative_exploration/social_showcase` |
| [生存、争夺与经营基础件套件](nonlinear-and-economy-kits.md) | `survival/score_contest/management_simulation` |
| [专项主类型基础件套件](specialized-assembly-kits.md) | `rhythm_performance/combat_boss/defense_strategy/stealth_infiltration/turn_based_strategy/sports_match/sandbox_creation/social_deduction` |

每张成品在进入坐标部署前都要回答：

1. 主循环的关键动作发生在哪个装配接口，基础件是在形成场所还是掩盖系统缺失？
2. 宏观体量、中层结构、接触/导航和表面/氛围分别由哪些实例承担；机关与逻辑是否被错误计入可见世界？
3. 每个重复族的入口、出口、净空、碰撞代理、共享件所有者和至少两种有意义变体是否已经声明？
4. 分区预算能否由 `单体展开 × 放置数 − 共享接口 + 独立地标` 复算，并与真实展开清单完全一致？
5. 峰值镜头、状态变化和降级顺序是否保留主轮廓、路线、危险、交互和目标反馈？
6. 暂定案例或未试玩能力是否仍标成假设，而不是被精确坐标和千件总数伪装成已验证？

只要其中一项答不清，就保持概念/灰盒成熟度；继续补装配、组件能力或试玩证据，不以增加无职责件数通过成品门。
