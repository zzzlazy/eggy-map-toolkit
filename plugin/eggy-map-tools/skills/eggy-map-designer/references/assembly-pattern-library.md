# 基础件装配模式库

本库提供结构配方，不绑定某个主题或组件 EID。实际设计先读取地图坐标语义，再用当前版本组件目录把“方块、柱体、棱柱、环件、曲面、灯、不可见碰撞代理”等角色替换为可写组件。没有目录证据时保留类别占位，不虚构模型或属性。

当这些局部配方需要沿路线、圆环、网格、中心辐射或垂直结构重复时，按 [参数化装配与千件级坐标展开](parametric-layout.md) 定义基向量、接口、布局生成器与受控变体；本文件的“建议展开”不能直接替代世界坐标清单。生存场、积分争夺场和经营生产链还需要完整场域族、公平/经济约束与分层账本，读取 [生存、争夺与经营基础件套件](nonlinear-and-economy-kits.md)。

## 局部坐标约定

每个装配体使用自己的局部坐标：

- `U`：左右，范围通常为 `-W/2…W/2`；
- `V`：向上，地面为 `0`；
- `F`：前后，正方向朝装配体出口；
- 原点：底面中心或入口中心；
- `W/H/D`：装配体的总宽、高、深。

部署时才把 `U/V/F` 映射到地图世界轴。每个局部件记录 `角色、基础形状、局部位置、旋转、尺寸、层、碰撞、投影、变体条件`。尺寸用 `W/H/D` 的比例表达，能让同一配方适配不同尺度。

先用少量大件保证主轮廓和连续表面，再在玩家接触处、边缘、转角、洞口和关键镜头增加中小件。不要把同一平面无收益地切碎。

## 1. 门架与章节入口 `PORTAL_FRAME`

适用：出生门、章节切换、终点框景、主题建筑入口。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 左右立柱 | 6–10 | 柱芯靠 `U=±0.42W`，外加基座、柱帽或分段包边 |
| 顶梁与檐口 | 4–8 | 主梁位于 `V≈0.8H`，上/下压条形成厚度 |
| 前后深度框 | 4–8 | 在 `F=±D/2` 形成可读洞口，不只做一张薄片 |
| 标牌/图形焦点 | 1–4 | 位于视觉中心，不侵入玩家净高 |
| 灯与路线色 | 2–6 | 左右对称建立入口，危险门可改成脉冲色但不改变碰撞 |
| 碰撞代理 | 1–3 | 分别覆盖左右柱与顶梁，保留门洞净空 |

单体通常约 18–35 件。A 完整、B 带破损、C 带侧门；三者的门洞、地面接口和主轮廓保持一致。

## 2. 承重平台跨 `PLATFORM_BAY`

适用：跑酷落点、厂房走道、悬空平台、社交观景台。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 连续碰撞面 | 1 | 覆盖真实可站区域，避免用几十块装饰分别碰撞 |
| 顶部表皮 | 1–4 | 根据分缝或材质节奏拆分，不影响落点判断 |
| 四侧厚度/包边 | 4–8 | 玩家能看到的边优先；不可见贴墙侧可省略 |
| 主梁/横撑 | 4–10 | 沿跨度方向建立承重逻辑，悬挑端必须有解释 |
| 支腿/吊杆 | 0–8 | 接地、接墙或接上方结构；漂浮主题也要有视觉规则 |
| 护栏/路线灯 | 0–10 | 只放在安全语义需要处，不缩窄起跳与超车净宽 |

单体通常约 12–35 件。相邻平台共享支腿或碰撞代理时必须在展开账中扣除共享件。

## 3. 楼梯与坡道 `STAIR_FLIGHT`

适用：建筑过渡、垂直攀爬、观景层连接、节拍喘息。

- 用一个连续斜坡或少量分段碰撞代理保证移动稳定；可见踏步再用 8–20 个表皮件表现。
- 两侧各用一条梯梁或墙体解释踏步受力；开放侧按风险需要增加立柱和扶手。
- 顶部、底部各留完整落脚平台，不能让最后一级直接进入机关扫掠区。
- 远景楼梯可用 3–6 个大阶块；近景主路线才使用完整踏步、踢面、梯梁和栏杆。

单体通常约 16–40 件。变体优先改变转向、栏杆开口和表皮破损，不改变步高、坡度与净宽。

## 4. 桥跨与悬空通道 `BRIDGE_SPAN`

适用：峡谷、厂房、空岛、合作交接和风险捷径。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 连续通行碰撞 | 1–2 | 安全线连续；破洞只在明确玩法处切断 |
| 桥面板 | 3–10 | 顺跨度形成节奏，避免密缝干扰速度读取 |
| 两条主梁 | 2–4 | 位于桥面下或两侧，连接端落在支座上 |
| 横撑/斜撑 | 4–12 | 每个可见跨至少出现一组结构节奏 |
| 立柱、护栏、索件 | 4–20 | 根据工业、木桥、魔法或自然主题换形状语法 |
| 两端支座与灯 | 4–10 | 清楚表现桥从哪里开始、通向哪里 |

单体通常约 20–55 件。长桥由若干标准跨和一个转折/破损跨组成，不把整座桥拉成单块。

## 5. 墙跨、立面与洞口 `WALL_BAY`

适用：厂房、城堡、街区、洞穴内衬、竞技场边界。

- 骨架：左右柱、上下梁与必要斜撑，约 6–12 件；
- 表皮：2–8 块主墙板/岩片，保留洞口和材质分区；
- 中层：压条、窗框、檐口、转角盖和板缝，约 8–20 件；
- 附着：管线、旗帜、灯、裂缝、藤蔓或标牌，约 2–12 件；
- 碰撞：用 1–3 个代理覆盖实体区域，不堵住窗门。

单体通常约 20–50 件。连续立面采用 A 完整、B 开窗/缺板、C 带门/转角；接口和主色稳定，局部变化控制在约 20%–30%。

## 6. 岩壁、山体与洞穴段 `CLIFF_SEGMENT`

适用：峡谷、山洞、海岸、雪山、异世界地貌。

- 先用 3–8 个大块形成不规则主轮廓和路线包裹；大块之间必须互相穿插，避免像独立石头排队。
- 用 6–18 个中块处理凹口、外挑、层理和转角；轮廓变化大于表面噪声。
- 用 4–15 个小块、棱柱或圆锥处理断口、落石和近景尺度；不可见背面不铺微件。
- 植被、积雪、熔岩或发光裂缝作为 2–10 个主题附着层，不承担主体轮廓。
- 通行面与阻挡面用少量简化碰撞代理覆盖；视觉岩片默认不逐件参与物理。

单体通常约 18–50 件。相邻段整体旋转、镜像和高度错位，再用少量转角件收缝；不要逐石完全随机。

## 7. 管线与机械骨架 `PIPE_RACK`

适用：工厂、实验室、蒸汽朋克、能源站、机关因果连线。

- 主干用 2–6 根圆柱或长条保持连续方向；转弯用弯头、环件或短接头明确连接。
- 每隔稳定距离放支架、法兰或固定环，建立尺度和重复节奏。
- 分支端必须接到容器、墙口、机关底座或明确截断件，避免管道悬空消失。
- 用一条高饱和细线或灯组表达“可交互/有能量”，其余保持结构色。
- 背景管线关闭物理和投影；玩家能踩到或会误碰的管线另设简化代理。

一段通常约 12–45 件。A 直通、B 分叉、C 带阀门/破损；用这些段连接成网络，不靠散落圆柱冒充机械复杂度。

## 8. 植被与景观簇 `VEGETATION_CLUSTER`

适用：森林、雪景、花园、遗迹、社交展示和不可达背景。

- 1–3 个主干/主石决定簇的方向与高度；
- 3–10 个树冠、灌木或积雪块形成中层轮廓；
- 4–16 个草、花、枝、蘑菇或碎石处理地面接缝；
- 0–3 个灯、粒子或主题焦点只放在构图需要处；
- 通常全部视觉件无物理、少投影，另用地形或单一阻挡代理控制玩家边界。

单簇通常约 8–30 件。用大/中/小三种尺度和 A/B/C 朝向变体形成聚簇、疏密和留白，不均匀铺满全图。

## 9. 机关或解谜站 `MECHANISM_STATION`

适用：按钮门、顺序谜题、能量传递、合作操作台、阶段开关。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 操作底座 | 4–10 | 让输入对象从环境中凸显，保留多人站位 |
| 因果连线 | 3–12 | 管线、轨迹、重复符号或视线框连接输入和输出 |
| 结果框/门体 | 4–12 | 开关前后都有可读轮廓，不依赖一行文字 |
| 状态反馈 | 2–8 | 至少区分待机、正确、错误/冷却 |
| 碰撞与净空 | 1–3 | 底座和门体使用代理，运动范围不放装饰碰撞 |

单站通常约 14–40 个视觉/碰撞件，逻辑对象另计。相同规则复用底座和反馈语法，变奏只改变位置、方向、顺序、资源或时间中的一个新维度。

## 10. 竞技场扇区 `ARENA_SECTOR`

适用：生存、积分争夺、团队对抗、回合小游戏。

- 地面与外边界用 2–6 个连续代理，保证扇区接口无缝；
- 中层用 4–12 个掩体、坡面、平台或风险边缘建立选择；
- 资源/危险底座 1–4 个，清楚显示生效范围与退路；
- 阵营/区域边框、方向灯与地标 6–20 个，用于定位而非额外碰撞；
- 环境壳体和观战框景 8–30 个，与实际战斗碰撞解耦。

单扇区通常约 20–65 件。复制成 4/6/8 个扇区后先保证碰撞、视线和行进时间一致，再给表皮做变化；外观丰富不能破坏公平。

## 11. 合影与社交活动台 `PHOTO_ACTIVITY_STAGE`

适用：拍照、舞台、换装展示、多人休闲节点。

- 站位平台与多人净空 2–6 件；
- 前景框、左右侧景、中景主体和远景轮廓共 12–40 件，明确三层景深；
- 灯与特效 3–12 件，不能吞掉角色轮廓；
- 座位、轻互动或呈现控件底座 4–20 件；
- 入口/出口与返回中心导视 3–8 件。

单场景通常约 25–80 件。每个主要场景至少提供观察、互动、合影、轻玩法或通往别处中的两项；否则再多装饰也只是背景。

## 12. 经营工作站 `WORKSTATION`

适用：工厂、餐厅、商店、农场、加工与建造循环。

- 工作台壳体、支脚和操作面 6–16 件；
- 输入容器、缓冲仓和输出容器 3–10 件，并用位置/颜色表达流向；
- 传送、管线或加工通道 4–16 件；
- 容量、加工中、完成和故障反馈 3–10 件；
- 标牌、价格/库存、升级外观和主题附着 4–20 件；
- 连续碰撞代理 1–4 件，高频操作面不堆微碰撞。

单站通常约 20–70 件。A 初级、B 升级、C 满载/故障可以共享接口，但升级必须产生可见的容量、速度、路线或功能变化。餐厅/商店再把站点组合为 `订货/储藏 → 制作/烤制 → 上架 → 顾客/桌位 → 结账`，每站固定玩家操作面、货物输入/输出、状态面和唯一碰撞代理；货物、员工与顾客逻辑另计，不靠陈列模型数量代替库存或排队状态。

## 13. 人类尺度室内房间跨 `ROOM_BAY`

适用：学校、住宅、办公室、医院、商店、实验室和叙事室内。先定义房间功能、入口/出口、主要视线和玩家动作，再填家具；不能从空盒开始均匀撒桌椅。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 连续地面/墙/顶碰撞代理 | 2–6 | 只覆盖真实边界，门窗、通风口与可穿越洞口保持一致 |
| 壳体表皮与踢脚/檐口 | 8–24 | 地、墙、顶有厚度和收边；不可见背面可省略 |
| 门窗与功能开口 | 6–20 | 框、扇、把手/门槛和状态面分层；开口承担路线或回望 |
| 主家具簇 | 12–48 | 先摆 1–3 个决定功能的簇，再补次要座位/储物，不平均填满 |
| 机电与结构附着 | 4–18 | 灯、风口、管线、插座、监控或消防件沿结构逻辑布置 |
| 指引、任务与状态焦点 | 2–10 | 黑板、公告、目标台或出口灯只承担当前信息，不与装饰争抢 |
| 收缝与近景接触件 | 6–24 | 门角、桌边、地面接缝和玩家会停留的操作面优先 |

单房间通常约 40–140 件。A 标准、B 开放/损坏、C 任务/危险状态保持门洞、净高、碰撞和主家具占地；变体优先替换 20%–40% 的功能件，而不是整房复制后只改颜色。

[《case-008》](exemplars/case-008.md)提供首屏教室与 3810 单位代码对照：大量方块、圆柱、棱柱、薄片和组件组构成课桌、讲台、窗、通风设施、人物和车辆；它支持室内装配方法，不支持潜行机制。

恐怖或废墟室内不要另起一套无接口的“破房间”。在同一 `ROOM_BAY` 上派生 `A_INTACT / B_DAMAGED / C_ABNORMAL`：A 建立功能、照明与导视；B 只替换局部墙板、家具、灯和地面附着，并让碎屑能追溯到缺口；C 只在真实状态触发后改变约 20%–30% 的尺度、对齐、门洞或光色，保持主碰撞与返回接口可审计。[《case-013》](exemplars/case-013.md)提供入口壳体与 2964 单位代码部分证据，但没有验证楼内变体切换、钥匙流程或威胁节拍。

## 14. 自制道具骨架 `PROP_RIG`

适用：桌椅、监控、风扇、货架、机器、车辆、角色雕塑和题材焦点。一个道具先决定远看剪影、承重/连接和交互面，再决定细节。

| 子结构 | 建议展开 | 职责 |
|---|---:|---|
| 主剪影体 | 2–8 | 用少量大形状决定识别，不从微件开始 |
| 连接/承重件 | 3–16 | 腿、轴、梁、关节、支架、法兰或车架解释结构 |
| 接触/交互代理 | 1–3 | 单独负责可站、阻挡、座位、按钮或受击包络 |
| 表面分层与功能件 | 4–24 | 面板、边框、轮毂、镜头、抽屉、屏幕、把手或标签 |
| 状态件 | 0–8 | 待机/运行/警戒/损坏只替换少量面、灯或姿态 |
| 收缝与主题微件 | 2–12 | 只放在近景与轮廓转折，不铺不可见背面 |

单件通常约 12–60 件；大车辆、角色或机械焦点可拆成多个子骨架。所有局部件归一个稳定父组与局部原点，真实碰撞/交互代理和视觉子件分离。A/B/C 变体复用连接接口和状态槽；若复制几十次，远景版应降为主剪影与少量功能件。

道具密度必须服务空间：桌椅形成可读通道和遮挡，管线连接来源与去向，机器留操作面，监控朝向与其真实检测规则一致。若道具只是填空，不计入成品化价值。

## 15. 可破坏房间单元 `DESTRUCTIBLE_ROOM_CELL`

适用：解压拆除、破墙开路、可毁掩体、部件拆解和以破坏改变空间的章节/积分玩法。它扩展 `ROOM_BAY` 或其他主题壳体，不替代主类型终局；先用一个房间验证命中、状态、碰撞、奖励和重置，再参数化复制。

| 子结构 | 建议展开 | 局部规则 |
|---|---:|---|
| 静态框架与安全接口 | 8–24 | 柱、梁、门框、外沿和不应被打掉的承重轮廓；保持入口/出口、相机和恢复路径 |
| 可毁目标集合 | 4–24 | 每件有稳定 ID、合法伤害包络、代次和离散状态；数量由判断与反馈能力决定，不把整面墙无收益切碎 |
| 依赖面与收口 | 2–10 | 地板、天花、门、遮挡或容器由显式前置集合控制；共享件只归一个房间/组所有 |
| 碰撞代理集合 | 3–12 | 静态框架、可毁面和安全边界分开；视觉裂纹/碎片不各自承担全功能碰撞 |
| 受损/完成反馈槽 | 4–16 | 裂纹、材质、状态灯、房间牌、奖励口和下一路线从权威状态派生 |
| 主题功能与尺度件 | 6–24 | 工具架、零件、容器、管线或家具解释为何可拆以及拆后用途 |
| 碎片池与逻辑 | 另计 | 声明峰值、寿命、碰撞、回收、命中去重、奖励提交与终局优先级，不用视觉件数代替状态合同 |

单房间通常约 30–110 个静态/状态/碰撞展开实例，复杂焦点房可更高；数值不是每面墙的切块目标。连续房间复用层高、门洞、标牌槽、目标材质和完成反馈，只改变 20%–40% 的目标拓扑、工具、风险、依赖或拆后用途。走廊、外壳、远景和共享结构另行分账，不能把房间数乘单体后忘记边界与共享件。

[《case-002》](exemplars/case-002.md)提供的是部分研究证据：归档以 30 种模型路径展开 7166 个批加载单位，名称出现多个功能房间、墙组完成、依赖地板/天花、奖励和出口词汇；没有实际命中或重进。配方中的耐久、目标数、碎片量、延迟和碰撞切换必须按当前版本能力与目标设备试玩，不照搬原作。

**接口自检**：

- 玩家能否在第一次命中前区分可毁、不可毁、危险和已完成面；
- 最后一击是否一次提交状态、碰撞、依赖、奖励和路线，而非若干独立延迟；
- 玩家站在将消失的面上时是否有预告、安全落点或一致恢复；
- 同一击、多玩家同帧、迟到事件和旧代碎片是否不会重复推进；
- 静态框架与可毁件能否分组替换，重置后模型与碰撞是否一致；
- 多房间之间是否至少改变一个判断轴，而不是只提高耐久。

## 千件级不是一句口号

下面只演示展开方法，不是任何地图的固定配额。一个约两分钟、主题包裹明确的短图可以这样估算：

| 内容 | 装配数学 | 展开实例 |
|---|---:|---:|
| 路线与落点平台 | `26 × 20` | 520 |
| 转折、桥跨和楼梯 | `10 × 30` | 300 |
| 环境墙跨/岩壁段 | `14 × 38` | 532 |
| 章节门架与三个焦点地标 | `6 × 28 + 3 × 45` | 303 |
| 机关站及底座 | `7 × 24` | 168 |
| 独立路线提示、灯、氛围和收口 | `180` | 180 |
| **规划展开总数** |  | **2,003** |

这 2,003 件可以只使用约 15–35 种基础形状/主题资产；统一来自稳定装配语法，不来自每件都不同。反过来，若路线只有 30 块地板、8 个机关和几十个装饰，即使尺寸很大也仍是百件灰盒。

设计时把公式换成实际区域和装配族。部署预览必须展开到唯一实例、扣除共享件并和分层预算对账；不要把本表数字直接复制成目标，也不要为达到数字制造不可见或无收益实例。

## 配方自检

- 从玩家可见角度看，装配体是否有主轮廓、厚度、支撑和接口；
- 与相邻装配体连接时是否无缝、无重叠、无意外台阶或夹缝；
- 近景碰撞代理是否连续，视觉微件是否默认不参与物理；
- A/B/C 变体是否保持玩法尺寸，只改变受控的视觉或局部结构；
- 重复十次后是否仍能按稳定前缀隐藏、替换、合并或降级；
- 展开件数是否能反查到配方，且每件具有可见、结构、玩法或系统作用。
