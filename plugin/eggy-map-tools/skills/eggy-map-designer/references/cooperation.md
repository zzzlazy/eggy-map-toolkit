# 合作机制

## 什么才算合作

真实合作需要可说明的依赖链：**玩家 A 的选择或动作，改变玩家 B 的信息、路径、能力、时机或安全性；B 的行动再推进共同目标或回馈 A。** 只有并排移动、在终点集合、踩两个不相干按钮或等待另一人到场，不足以构成合作。

## 可复用的合作原型

- **开路与通过**：一人维持开关、平台或视野，另一人通过并在远端回开路径；必须避免前者永久被留在原地。
- **接力**：道具、能量、状态或控制权在玩家之间传递；每次交接有明显反馈和失误回收点。
- **信息分工**：一人看见顺序、方向或危险，另一人执行；信息必须可准确表达，不能依赖猜测或语音环境。
- **同步窗口**：双方在时间窗内完成互补动作；先用宽窗口教学，再缩短或加入空间压力。
- **保护与运输**：一人移动目标，另一人清障、挡险或提供落点；双方都持续做决策，避免一人全程等待。
- **能力互补**：不同路线或身份拥有不同可操作对象，周期性换位或互相解锁，避免固定“主角/工具人”。

## 设计每个合作拍点

逐项写清：

1. A 看见什么、能做什么；
2. A 的动作改变 B 的什么状态；
3. B 如何看见或听见这次改变；
4. B 的动作如何推进目标或回馈 A；
5. 任一人失误、掉队、离开或提前通过后如何恢复；
6. 等待者仍有什么低风险观察、准备或辅助动作。

若其中第 2、3 或 5 项为空，机制通常会表现为伪合作、因果不清或软锁。

## 三份契约

在画双线路线前先写三份最小契约。

### 角色契约

每个角色记录：独占动词、可作用对象、产出的路径/状态/资源、对方如何利用、玩家如何看见结果、失败如何撤回。独占动词必须改变共同进度；仅有不同外观、出生侧或移动路线不算能力分工。

### 交接契约

每次交接记录：谁先行动、交付了什么可见状态、另一人获得什么新机会、前一人何时重新获得行动权。整局至少让控制权在双方之间往返，而不是一人连续解题、另一人长期跟随。交接点应处于可观察且可恢复的状态，避免必要玩家被门、落差或一次性触发永久留在后方。

### 缺员降级契约

若允许单人进入、队友离开或角色未绑定，明确由什么替代缺员能力：自动触发、双技能角色、旁路、可重复 NPC、检查点恢复或退出提示。降级分支应保留核心因果和教学，只减少协调成本；不要简单移除所有阻挡，也不要让双人状态与单人状态共用未重置的一次性开关。

把双人和单人视作同一地图的两条可验证状态路径：分别列出生绑定、能力授予、章节门、存档、失败、重生和终点条件。

## 2–4 人适配

- 明确最低人数和目标人数。双人强依赖机制不能假设四人时仍自然成立。
- 额外玩家应增加并行帮助、容错或分工选择，不应堵住触发区、窄门和落点。
- 所有必要触发都检查重复进入、同时触发、越序触发和玩家在区域内重生。
- 会合点放在安全、可观察的位置，并让先到者知道队友在哪里、下一步何时开始。
- 若允许单人试玩或队友中途离开，为研究、教学或异常状态提供跳过、自动复位或退场路径；不要让地图永久卡死。
- 额外玩家不能抢走角色专属道具或把一次性交接提前消费；多人复活后要重新确认角色和能力归属。

## 反馈语言

合作因果至少用两种通道中的一种清楚表达：空间变化（门开、桥出现、危险停止）或界面/声光反馈。颜色需要保持角色或线路一致，远距离对象用连线、重复符号、朝向或地标建立对应关系。

## 试玩矩阵

至少验证：最低人数、目标人数、一个新手加一个熟练玩家、两人同时失误、玩家越序、玩家重生、玩家中途停止行动，以及允许时的完整单人分支。分别记录每个角色的主动操作时间、最长连续等待、交接成功率、呼叫次数、误解原因、恢复时间和缺员接管是否完整；合作强度不以按钮数量衡量。
