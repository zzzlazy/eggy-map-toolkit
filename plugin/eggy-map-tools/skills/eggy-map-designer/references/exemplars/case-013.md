# 匿名案例 case-013

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它提供了一张身份与代码一致的“废弃旅馆外壳 + 大型房间网络词汇”部分样本。可控首屏先用完整楼体、重复窗格和中央入口建立正常建筑秩序，再用枯树、荒草、暗窗、碎屑和开放门洞制造侵蚀；2964 个运行时单位又证明场所由大量基础件、结构收口、家具与破损层共同组成。适合参考恐怖建筑首屏、完整/破损变体、房间语义和千件级室内分账；不适合作为威胁 AI、钥匙顺序、谜题、追逐、恐怖节拍或性能的已验证样板。

## 证据边界

- 已观察详情、内容提示、取得控制后的入口首屏和游戏内正常退出；没有进入楼内或触发任何钥匙、威胁、陷阱、塌陷、存档或结局。
- 归档展开 2964 个单位、163 种模型路径/ID；可变形方块 972、基础圆柱 156、球体 141、组件组 163、破损石砖墙 84、古树枝杈 64、四分之一圆环 59。
- 名称表出现大厅、浴室、餐厅、庭院、停车场、员工通道等空间，以及多种钥匙、电箱、保险箱、安全出口、陷阱、塌陷和结局。这里只把它们当作房间/状态词汇，不还原真实流程。
- 本次入口初载显示约 3 FPS、延迟 128，对话清空后恢复到 60 FPS、延迟 51；它证明加载瞬态和稳定视区要分开记录，但不代表楼内峰值。

## 恐怖建筑先有正常语法

恐怖空间不应从黑箱开始。先定义能独立成立的建筑装配，再派生损坏和异常：

```text
HOTEL_BAY =
  FLOOR_SLAB
  + WALL_MASS
  + WINDOW_OR_DOOR_FRAME
  + CORNICE_OR_BASE
  + INTERIOR_DEPTH
  + COLLISION_PROXY

VARIANT_A_INTACT    = HOTEL_BAY + FUNCTION_SIGN + NORMAL_LIGHT
VARIANT_B_DAMAGED   = HOTEL_BAY - LOCAL_PANEL + CRACK_EDGE + DEBRIS_CLUSTER
VARIANT_C_ABNORMAL  = HOTEL_BAY + CONTROLLED_SCALE_OR_ALIGNMENT_BREAK + STATE_LIGHT
```

三个变体保持层高、柱距、门宽、接口与接触面一致，变化集中在约 20%–30% 的局部件。只有状态机真的改变空间时才使用 C；随机歪斜所有墙、门和家具会消灭正常—异常对照。

## 首屏五层职责

| 层 | 本案可见线索 | 新地图的实现要求 |
|---|---|---|
| `MASS/ENCLOSURE` | 四层矩形旅馆正立面 | 建筑先有侧脸、厚度与占地，不是一张贴图墙 |
| `STRUCTURE/RHYTHM` | 窗格、楼层线和中央门廊 | 重复接口稳定；局部缺失才产生意义 |
| `NAVIGATION/GOAL` | 中轴台阶、敞开入口与门内亮面 | 玩家取得控制后无需读长文也知道最近动作 |
| `SURFACE_DETAIL/ATMOSPHERE` | 枯树、高草、暗窗、碎屑 | 侵蚀按来源聚簇，保留通行与镜头净空 |
| `STATE_FEEDBACK` | 本次只见废弃状态 | 设计新图时必须补同机位正常/异常变化，不能假装已从本案验证 |

门洞是“空间承诺”：从室外能看见一点内部深度、光或轮廓，但不应在首屏暴露全部答案。剧情框若存在，放在构图已经说明入口之后，并确保可立即关闭、无输入时不会自动触发失败。

## 房间网络总账

不要把十个房间做成十个同样的盒子。先写房间功能和门槛，再写装配与状态：

| 房间节点 | 功能锚点 | 可见定位 | 进入门槛 | 状态变化 | 失败恢复 |
|---|---|---|---|---|---|
| 公共大厅 | 接待/总导视 | 高挑空间、主楼梯、外门视线 | 无或教学 | 导视/照明改变 | 可退回入口 |
| 客用功能区 | 浴室、餐厅、休息等 | 独有家具簇、材质与声景 | 钥匙/电力/线索 | 门、灯、道具同源变化 | 必要物可重取 |
| 服务区 | 员工通道、器材、电箱 | 管线、低净空、维护标识 | 员工权限或工具 | 设施状态改变公共区 | 不封死唯一返回路 |
| 过渡节点 | 楼梯、庭院、停车场 | 窗外地标、楼层号、方向色 | 章节提交 | 回望构图或威胁升级 | 就近存档/退路 |
| 结局节点 | 安全出口/提交处 | 与普通门显著但一致的标记 | 权威条件集合 | 原子锁定结局 | 重进不残留半完成状态 |

每把必要钥匙或权限物都要有 `spawn → acquire → carry/own → submit → consumed/preserved → reset` 合同。静态名称只能提出这些审计问题，不能证明原作已经解决。

## 恐怖节拍仍需另行证明

本案可支持的是场所与气氛，不支持直接复用一条恐怖循环。设计时仍应逐拍填写：

```text
SAFE          玩家相信什么规则，退路在哪里
ANTICIPATE    哪个声音、光、遮挡或空间差异给出预告
REVEAL        威胁/异常何时可见，玩家仍有哪些反应
CONSEQUENCE   被发现、选错或逗留的明确代价
RELEASE       何时归还控制、方向和稳定信息
```

同一威胁重复出现时，至少改变信息、空间关系或玩家选择之一；次数成就不能代替遭遇变奏。安全区、预告、反制、冷却、无声/低闪烁降级、死亡恢复和会话清理都必须在自己的地图中实测。

## 从 2964 件学什么

- 972 个可变形方块是大体量、墙地顶、家具或局部造型的基础词汇，不等于 972 个独立房间；总账仍要拆到场景、区域、装配族和职责。
- 大量薄件、非均匀缩放和倾斜件能形成窗框、檐口、碎屑、树枝与破损边，但同一平面无收益地切碎不能计入成品密度。
- 可见性、物理和投影的原始字段显示作品进行了职责分账，但入口从约 3 FPS 恢复到 60 FPS 也提醒我们：加载瞬态、稳定视区和楼内峰值必须分开，静态开关与总单位数不足以证明运行性能。室内尤其要按“当前房间 + 门洞可见邻室 + 动态威胁”计算峰值。
- 首屏密度集中在建筑边缘、入口、树草和地面碎屑，中间前院保留了观察与移动留白。恐怖细节不是越均匀越好；留白让门洞和异常更有权重。

## 可迁移的部分方法

1. 先搭一座功能可信、入口和层级清楚的普通建筑，再建立 `INTACT / DAMAGED / ABNORMAL` 三种墙跨、门框、灯组和走廊变体；恐怖变化附着在共同接口上。
2. 首屏用 `建筑大体量 + 重复开窗节奏 + 中轴门槛 + 两侧侵蚀簇 + 地面尺度碎屑` 完成五层职责。标题和剧情文字只能补充，不能替代可进入的门。
3. 破损按原因聚簇：塌陷集中在受力或事故点，荒草沿墙脚和无人维护区增长，碎片从缺口向外散开，异常尺度只在需要制造不安的节点出现；不要逐件随机旋转。
4. 房间网络用门牌、材质、灯色、窗外地标与机电差异定位；钥匙、员工卡和电力状态分别使用不同世界内反馈，避免所有进度只显示在文本或背包中。
5. 千件级室内按视区预算。远房间和不可达装饰默认不参与物理/投影，桌椅群和墙面细节用连续代理；动态门、威胁、关键灯与交互物单列峰值成本。
