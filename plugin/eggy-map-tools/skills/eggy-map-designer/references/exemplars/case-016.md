# 匿名案例 case-016

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它有 BGM、音符图标、发光线条和“加速鼓点”，却由长障碍路线、复位与终点拥有权威。用它检查“音乐化跑酷”和“纯音游”是否被错误合并，不把题材词或组件名当成谱面证据。

## 证据边界

- 已观察取得控制后的出生段：目标为“通关蛋仔 0/1”，玩家面前是连续黑色平台、传送带和悬空落点；没有可见谱面判定线、早晚判定、连击或分数。
- 归档含 315 个批加载渲染单位和 19 种模型路径；高频项为道具箱 105、传送带 91，名称池另有销毁区域 37、存档区域 33、小地板 20 和“加速鼓点”11。
- 对 `Perfect/Good/Miss/Combo/连击/判定/音符/分数/得分` 的有限字面量审计为 0。它与首屏和终局一致，但不能证明未知压缩逻辑中绝无其他等价实现。

## 分类边界

```text
本案例已证明
BGM + 音符图标 + 鼓点机关 + 霓虹路线
        + 移动/跳跃/复位 + 到达终点
        = 原主类型（章节或长跑酷）+ 音乐/节奏表现

本案例未证明
唯一谱面时钟 → 前读 → 判定线输入 → 早/准/晚/漏
             → 连击/分数 → 乐句结算与清理
        ≠ rhythm_performance
```

若玩家不按节拍也仍通过同一空间路线，节拍只是在预告机关或装饰演出；若每次输入由谱面代次和判定窗消费，分数/连击决定完成，才把纯音游设为主类型。两者的恢复测试也不同：前者测路线检查点与机关相位，后者测暂停、延迟、旧音符清理和下一乐句。

## 可迁移检查

1. 去掉 BGM、音符模型和霓虹材质后，权威终局是否仍是跑到终点？若是，不能按纯音游设计。
2. 是否存在唯一时钟、音符 ID、一次输入一次消费、判定结果与连击提交？缺一组就先保留证据缺口。
3. 提示能否在静音、低闪烁或仅形状条件下工作？音乐化机关也要有替代通道。
4. 若节奏只是修饰器，明确它改变哪一个原有节拍，不再建立第二套分数终局。

## 不应照搬与必须再测

- 不复制路线、星云背景、道具箱/传送带比例、具体时长、复位数量或作者素材。
- 未完成全程，不能评价障碍曲线、检查点损失、性能峰值和终点收束。
- 本案例只能形成分类禁用项，不能支持谱面密度、判定窗、延迟补偿、多人分轨或纯音游装配尺度。

## 身份与证据范围

- `[元数据事实]` 最低与推荐人数均为 1，玩法为通关型，BGM 记录为 `The Other Side Of Paradise`。公开元数据包含中位完成时长约 525 秒、平均约 572 秒和 3000 秒上限；字段口径可能不同，不据此推断难度或节奏质量。
- `[视觉观察]` 已进入单人、取得控制并通过游戏内流程正常退出；只观察出生段，没有完整通关或计时输入延迟。

## 实际首屏循环

- `[视觉观察]` 详情封面和出生画面都是星云背景中的长黑色障碍跑道。玩家沿连续平台、传送带和悬空落点前进，右上目标是“通关蛋仔 0/1”，中央是剩余时间；首屏没有谱面轨道、固定判定线、早晚判定、连击或分数显示。
- `[视觉观察]` 路面有线状发光纹理，近处存在音符图标，整体容易被 AI 搜索按“音乐、节拍、音符”召回；但可见玩家动词仍是移动、跳跃、复位和到达终点。
- `[设计推断]` 权威终局来自路线通关，不来自统一谱面时钟上的输入判定。因此它应归为章节/长跑酷，至多叠加音乐或节奏外观，不能归为 `rhythm_performance`。

## 代码边界

- `[代码事实]` file 95 可复算 315 个批加载渲染单位、19 种模型路径；高频项为道具箱 105、传送带 91、销毁区域名称 37、存档区域名称 33、小地板 20、分阵营出生点 16 和“加速鼓点”11。
- `[代码事实]` 315 个单位中 189 个使用非均匀缩放，141 个至少一轴不小于 5；位置包络沿 X/Z 延伸到约 850 米量级，支持长路线而非固定舞台的空间判断。单位口径是批加载渲染单位，不等同于编辑器顶层组件。
- `[代码事实]` 对 `Perfect`、`Good`、`Miss`、`Combo`、`连击`、`判定`、`音符`、`分数` 和 `得分` 做有限字面量审计，结果为 0。这个结果不能证明压缩脚本中绝不存在等价逻辑，但与首屏、通关目标和机关词汇一致，不支持纯音游入站门槛。
- `[代码事实]` 11 个“加速鼓点”、音符图标和 BGM 只能证明音乐化反馈或机关命名；它们不提供音符代次、输入消费、判定窗、谱面完成或结算权威。

## 可迁移边界

- `[设计推断]` “和音乐一起发生”不是纯音游的充分条件。只有玩家反复读取前置信号、在统一判定线上输入，并由同一时钟提交早/准/晚/漏、连击/分数和乐句结算时，才把 `rhythm_performance` 作为主类型。
- `[设计推断]` 音乐跑酷可以保留原主类型，把节拍用于机关预告、运动相位或演出同步；此时检查的是最慢合法路线、机关相位恢复和静音替代，不应套用谱面判定合同。
- `[设计推断]` 搜索和分类先看权威终局、主要动词与状态闭环，再看标题、BGM、音符模型和霓虹外观。命中装饰词时应先降级为候选，不能消耗纯音游正向证据名额。

## 不应照搬与未知

- 不复制作者路线、星云背景、音符图标、传送带序列、道具箱布局、具体时长或复位密度。
- 未完成全程，不能评价平台节奏、检查点损失、后段视觉、难度曲线、性能峰值或终点收束。
- 该案例只证明“节奏外观/鼓点机关不等于纯音游”，不能支持任何谱面密度、判定窗、延迟补偿、多人分轨或静音完成率。
- 纯音游正向样本仍须同时提供确切身份、可见判定与连击/分数、唯一谱面时钟、至少一段实际输入和一次清理/重开证据。
