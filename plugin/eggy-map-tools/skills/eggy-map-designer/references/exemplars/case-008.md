# 匿名案例 case-008

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它有潜行题材、警卫封面和“监控变红”表现，但实际证据支持的是长章节逃脱跑酷，而不是潜行权威循环。它既能防止把标题和气氛误认成机制，也提供一个 3810 单位的室内学校基础件装配样本。

## 证据边界

- 只观察出生教室：讲台、黑板、课桌椅、窗和通风口构成第一场景，黄箭头指向通风管。没有实际完成任何章节或触发监控。
- 归档含 3810 个编辑单位：可变形方块 1411、基础圆柱 582、等腰三棱柱 176、四棱锥 143、半圆柱 125、1/4 方圆环 113；89 个组件组、2018 个父子单位和 54 个表现器绑定。

## 分类边界

```text
本案例已证明
逃离题材 + 监控红色表现 + 老师/警卫叙事
        + 通风管/按钮/风场/载具/检查点组成的章节路线
        = chapter_challenge（可带逃脱题材）

本案例未证明
传感器范围 → 怀疑 → 警戒 → 搜索/追击 → 恢复
          + 遮蔽或工具反制 + 目标提交 + 变化后的撤离
        ≠ stealth_infiltration
```

地图里有 84 次“监控变红”文本命中，却没有可核验的视野、怀疑、警戒、巡逻、追击或被发现状态；特有触发主要是固定点爆炸音效和通用角色生命周期。潜行类型必须以状态和玩家决策分类，不能按封面、标题、敌人模型或红灯分类。

## 学校场景形状语法

| 层级 | 基础件职责 | 组合方式 |
|---|---|---|
| 宏观壳体 | 方块、薄片、长梁 | 连续地板/墙/天花、门窗开口、走廊和房间尺度 |
| 中层结构 | 圆柱、三棱柱、半圆柱、方圆环 | 桌椅腿、管道、窗框、栏杆、风扇、车辆骨架和角色轮廓 |
| 表面细节 | 极薄方块、球/半球、锥台 | 黑板字牌、桌面层、五官、灯具、按钮、轮毂和收缝 |
| 玩法代理 | 无形方块、存档/销毁/事件区 | 连续碰撞、章节恢复、触发和胜利；不让每个可见小件参与物理 |

3382 个单位使用非均匀缩放，2181 个含极薄轴，2363 个有 X/Z 倾斜；2343 个关闭物理、3641 个关闭投射阴影。成熟场景不是“把 3810 件都做成独立动态物体”，而是用少数形状、分组、姿态和性能职责展开具体物件。

## 从逃脱跑酷升级为真正潜行

若沿用学校题材，先加一个最小可验证潜行单元，而不是继续堆监控装饰：

1. 在观察位看见一名巡逻者或一台传感器的朝向、覆盖边和周期；
2. 用墙角、桌群或通风口提供一条可信遮蔽路线，并让视觉几何与检测边界一致；
3. 进入边缘先转 `SUSPICIOUS`，持续暴露才转 `ALERT`，同源显示来源、方向与程度；
4. 玩家可等待、绕行或使用一次有代价的工具；警戒后进入局部追逐/回退，再恢复到可玩状态；
5. 取得钥匙/作业/门禁目标后改变撤离路线，目标只提交一次，重生和重进不会复制或永久锁门。

这个单元通过后再沿“教室—走廊—办公室—操场”组合传感器；场景密度不能掩盖检测合同缺失。

## 不应照搬与必须再测

- 不复制题材文本、作者角色、关卡顺序、时长、车辆阵列或单位总数。18 个存档区来自长图，不是短图配额。
- 未实测后段路线、障碍、恢复、终点、多人或帧率。上述装配结论来自代码聚合与首屏，不支持完整体验评价。
- 真正潜行方案必须重新灰盒视线边界、遮蔽物可信度、多人警报、目标/撤离、死亡恢复和连续新局。

## 身份与证据范围

- `[视觉观察]` 详情页显示跑酷标签、4.9 评分、约 553 万游玩和 28.3 万点赞；这些是传播信号，不证明潜行规则、难度或性能。
- `[视觉观察]` 只观察了出生教室，没有实际穿过通风管、完成任何章节、触发监控或到达操场终点；路线后段、检查点、失败和多人均未试玩。

## 首屏与题材承诺

- `[视觉观察]` 出生教室用讲台、黑板、课桌椅、窗、网格围栏和墙上规则形成完整室内场景；大黄箭头直接指向左侧通风管入口，近景目标在取得控制后立即可见。
- `[视觉观察]` 世界文字说明“学校放假了，老师却无故拖堂”“趁老师睡着，顺着通风管道逃出去”，局内目标仍是约 50 分钟限时和“剩余人数 1/1”。首屏没有怀疑条、警戒状态、可见视锥、工具代价或已窃取目标。
- `[代码事实]` 后段文字包括“终于重见光明了，穿过操场就可以逃出去了”，另有“第一关管子”“第一关门”“第二关网”等对象名，支持“教室—通风管—分关障碍—操场—终点”的章节逃脱结构。

## 为什么不是潜行主类型

- `[代码事实]` 归档存在大量命名为“监控变红”的表现器事件，但全文没有可核验的“视野、怀疑、警戒、巡逻、追击、被发现、门禁或窃取目标”状态词。红色监控外观只能证明主题反馈槽存在，不能证明检测真值。
- `[代码事实]` 主要触发数据有 26 个触发条目，大部分是通用游戏模式、出生/死亡/胜负回调；地图特有循环计时器每秒在四个固定单位位置播放爆炸音效。未发现传感器读取角色位置、视线阻挡、警戒转换、搜索恢复或撤离解锁的事件图。
- `[视觉观察]` 封面和校规用警卫、抓捕、惩罚和逃跑叙事制造潜行想象，但详情明确标注跑酷，首屏以箭头、通风管和章节终点驱动前进。
- `[设计推断]` 因此它应分类为 `chapter_challenge`，可叠加逃脱/追捕题材；不能作为 `stealth_infiltration` 的检测合同证据。标题、封面、监控模型或红色表现都不能替代侦测—警戒—反制—恢复—目标提交循环。

## 可迁移原则

- `[设计推断]` 大型室内章节图先做房间壳体和功能家具，再嵌入路线。教室的墙、地板、窗、黑板、课桌、讲台和通风口同时建立场所身份、尺度、遮挡与下一动作，不需要用孤立主题 Prefab 撑场景。
- `[设计推断]` 高频基础件通过“组件组 + 非均匀缩放 + 薄片/长梁 + 少量碰撞代理”构成大量具体物件。成品密度来自装配族和变体，不来自为每个物件换一套独特模型。
- `[设计推断]` 章节恢复件应跟路线单元对账：存档、销毁、按钮、风场和载具分别属于某一关接口，并声明掉落/载具丢失后的恢复。18 个存档点是长图尺度结果，不是短图配额。
- `[设计推断]` 主题信号与玩法真值必须分层。监控变红可以强化气氛；若要升级为潜行，仍需唯一检测权威、可读范围、警戒状态、工具/遮蔽反制、被发现后果与恢复。

## 不应照搬与未知

- 不复制学校剧情、作者角色、校规文字、关卡顺序、监控造型、车辆段、地图时长或 3810 件规模。
- 只看了出生教室，不能判断后续环境质量、迷路、检查点间距、障碍节奏、相机、完整通关或多人拥堵。
- 性能字段显示大量关物理和投影，但没有目标设备帧率、峰值视区、透明/动态数量或加载切换实测；不能把单位总数当作性能上限。
- 下一张潜行候选必须在首屏或代码中至少证明一种传感器范围、两级以上警戒转换、可用反制以及目标后撤离；否则按题材边界样本处理，不再缓存同类“逃脱跑酷”。
