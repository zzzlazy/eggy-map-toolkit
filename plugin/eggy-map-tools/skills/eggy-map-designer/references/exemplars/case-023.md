# 匿名案例 case-023

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它提供了一张可控首屏与代码身份一致的“海洋环境封套 + 超长垂直章节跑酷”部分样本：海草/珊瑚近景、路线中景、雾化海床远景共同让水下主题成立，889 个单位又展示了环境资产、章节机关与恢复节点怎样在约 945 米高度跨度中分账。适合参考海洋壳体、垂直路线框景、章节模板和存档/救援接口；不适合作为完整海底世界、沉船探索、水流机制或实际攀爬镜头的样板。

## 证据边界

- 已观察详情、可控出生首屏和游戏内正常退出；没有移动、完成第一跳或观察后续高度层。
- 归档展开 889 个批加载单位、70 种模型路径/ID，位置的 Y 范围约 `6.9..952.1`；名称表含存档区域 69、自然传送门 39、事件区 39、销毁区 36。
- 海底礁石、珊瑚、海草、深水、岩壁、海盗船零件和鲸骨形成明确题材词汇；本次只确认它们存在于同一归档，未还原完整分布。
- 元数据中位完成时长约 1294 秒、最快约 5.3 秒，口径冲突明显；所有精确节拍、难度和救援收益都需重新标定。

## 海洋封套的五层职责

普通跑道整体染蓝仍是普通跑道。水下首屏至少分出五层：

| 层 | 设计职责 | 本案可见线索 | 新地图的实现要求 |
|---|---|---|---|
| 水体体积 | `ATMOSPHERE/ENCLOSURE` | 蓝色雾化、光纹、远层降对比 | 不遮落点；透明与粒子集中在有限视区 |
| 海床与岩壁 | `ENCLOSURE/SCALE_REFERENCE` | 低对比地面、远景轮廓 | 至少包住一侧与下方，避免路线漂在无尺度天空 |
| 生物/遗迹簇 | `SILHOUETTE/SURFACE_DETAIL` | 海草、珊瑚、礁石；代码另有船件与鲸骨 | 以大中小簇和留白组织，不逐件均匀撒布 |
| 接触与路线 | `CONTACT/NAVIGATION/DANGER` | 安全浅色出生面、粉色海星落点 | 接触边缘高对比；装饰与碰撞代理分离 |
| 章节目标 | `GOAL/STATE_FEEDBACK` | 最近落点链、倒计时与文字 | 使用世界内上方地标/层牌先定向，文字只补充 |

至少让近景、中景与远景各承担不同职责。隐藏路线色后，世界仍应能读成水下；隐藏珊瑚 Prefab 后，海床、岩壁、洞口、桅杆/肋骨和材质节奏也应保留主题。

## 垂直海洋章节模板

把长路线拆成可验证的层，而不是把同一障碍沿 Y 轴复制：

```text
SEA_LAYER =
  LANDING
  + ORGANIC_OR_RUIN_CLUSTER
  + ROUTE_RIBBON
  + UPWARD_LANDMARK
  + SIDE_REFERENCE
  + NEXT_LAYER_FRAME
  + CHECKPOINT
  + FALL_CATCH_OR_FAST_RETURN
```

同一模板可以复用接口，但至少沿三条变量轴做受控变化：

- **拓扑**：横移、绕柱、穿洞、短折返或环绕；
- **轮廓**：珊瑚塔、礁石门、船肋、鲸骨、海草峡缝；
- **动作**：普通跳、一次能力、等待窗或危险躲避；每层只引入一个主要求。

层间必须留出仰视相机净空；上层底面不能遮住当前落点。长坠落要么被中间平台接住，要么快速回到刚提交的层。存档、卡关救援门和付费/广告捷径是三种不同合同，分别建状态与视觉层级。

## 从 889 件学什么

- 889 是整条超长路线的环境、机关、恢复和表现总账，不是海洋地图最低数量。39 个礁石、39 个传送门、39 个事件区与 39 个道具箱只说明批量章节接口占据大量预算。
- 70 种模型已足以形成明显海洋词汇；变化主要应来自簇的大小、倾斜、朝向、密度、留白和与路线的关系，而不是每层换一套无关资产。
- 69 个存档区域说明恢复对象可能多于视觉章节；设计账应分别记录“可辨认章节数”和“恢复提交点数”，不能把检查点数当内容量。
- 312 个批量合并映射提示重复环境可能经过合并，但静态数量不证明帧率。仍需记录峰值可见、物理、投影、透明、粒子、运动体和生成物。
- 这张图的主要结构仍是悬浮跑酷。若目标是可探索海底世界，需要把预算转向连续海床、洞口/街巷、地标网络、可返回环路与状态变化，而不是继续增加落点链。

## 首屏信息反例

可控画面同时存在顶部长期说明、倒计时、广告直达终点、商店与公告牌。通用顺序应是：

1. 世界内地标和最近两步先说明方向；
2. 主目标、当前层和必要危险位于第二层；
3. 卡关后才出现救援门或提示；
4. 商店、广告、社交与排行榜保持可选、可关闭，不遮住路线观察面；
5. 无输入基线验证可选 UI 不会自动触发、抢焦点或改变终局。

## 不应照搬

不复制标题、关卡排列、章节数量、文本、广告直达、资产阵列或具体路线。这个案例支持的是水下前中远分层、冷环境/暖路线的语义分工、垂直层接口和恢复预算；它不证明完整路线的可玩性、镜头、难度、性能、传送可靠性或海洋动态状态。

## 路线、恢复与内容量

- `[代码事实]` 名称表含存档区域 69、事件触发区域 39、自然传送门 39、道具箱 39、销毁区域 36；入口文字还提示“每关四十秒后都会有传送门”。这些证据共同支持大量章节化恢复/跳过节点，不能证明精确的一关一门映射，也不能证明任一传送、存档或广告路径可靠。
- `[设计推断]` 极长垂直路线应把恢复预算和景观预算同时按层分账。每层不仅要有落点与机关，还应有上方地标、侧向参照、坠落接住/快速回收、下一层框景和不同于相邻层的环境簇；否则 69 个存档只能降低重跑损失，不能解决迷向与视觉疲劳。
- `[设计推断]` 39 组礁石、传送门、事件区和道具箱的同量级重复可能对应某种章节模板。可迁移的是“稳定接口 + 受控变体”的生产方法，而不是复制数量：共享入口/出口、存档和恢复接口，变化落点拓扑、海洋簇轮廓、主色重音与动作要求。
- `[设计推断]` 海洋主题应把接触面和生物装饰分工。实际落点用高明度、稳定边缘和连续碰撞代理；海草、气泡、薄珊瑚与远景岩壁主要承担包裹、尺度、方向和氛围，默认不应制造意外碰撞。

## 可迁移的部分方法

1. 先建立蓝色体积雾、海床/岩壁和前中远三个生物簇层，再放路线；只改天空或全局色调不算海底世界。
2. 用一条高对比路线色贯穿近两步，环境可用同类冷色但降低明度竞争；危险和可交互物另设语义色。
3. 把每个垂直章节封装为 `安全落点 + 生物/礁石簇 + 下一落点框景 + 上方地标 + 侧向参照 + 存档 + 坠落恢复`，相邻层至少改变轮廓、朝向或动作之一。
4. 重复资产按簇而不是均匀撒布：每簇有一个主高度、一个倾斜方向和留白边；远层减对比、近层保轮廓，中层负责把视线送向下一步。
5. 长图的存档、跳过门和商业捷径必须分开表达。存档保护已完成进度，救援门解决持续卡关，商业入口属于可选系统；三者不能共同占据主任务的第一视觉层级。
