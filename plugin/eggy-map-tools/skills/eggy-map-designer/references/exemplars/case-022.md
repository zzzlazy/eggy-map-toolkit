# 匿名案例 case-022

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它提供了当前案例库里第一个高展开、高触发的生存派对正面对照：1,863 个空间单位与 4,031 个 ECA 触发记录共同支撑多模式、随机场地、天气、生命、观战、复活、结算和再次开局。同时，自动遮挡出生观察面的奖励弹窗构成清楚的入口反例。

## 证据范围

- 已观察海岛木桩/窄板出生场；未点击“领取免费道具”，也没有观察完整回合、多人、公平、结算或第二局。
- 代码事实包括：经典 5 命、3 分积分、无限生命三种模式；简单/一般/困难；木板变窄、柱子摇晃/消失；晴雨雪雷暴；观战、复活、无人存活结束、下一轮和暂停运动器。不能从字符串还原精确触发顺序与数值。

## 可迁移的系统合同

不要把所有逻辑塞进一个“游戏开始”布尔值。至少分成以下权威状态面：

| 状态面 | 最少状态 | 只能负责什么 |
|---|---|---|
| `ROUND` | `ENTRY/PREPARE/LIVE/SETTLE/RESET` | 唯一终局、计时与是否允许玩法事件 |
| `MODE` | 当前规则与难度 | 生命、得分线、可选事件池，不直接宣判胜负 |
| `FIELD_EVENT` | `SELECT/TELEGRAPH/ACTIVE/CLEANUP` | 板面/柱体变化和对应反馈 |
| `WEATHER` | `SELECT/TELEGRAPH/ACTIVE/CLEANUP` | 视野、地面或雷击变化，不重复创建回合 |
| `PLAYER_LIFE` | `ACTIVE/RESPAWNING/ELIMINATED/SPECTATING` | 单玩家生命、复活、观战与终局候选 |
| `OPTIONAL_SYSTEM` | `HIDDEN/AVAILABLE/CLAIMED/CLOSED` | 可选能力或奖励；不得阻塞主循环与出生观察 |

推荐回合合同是：`ENTRY_READ → PREPARE → 选择并预告当前代事件 → LIVE → 清理当前代 → 继续/FINAL → SETTLE → RESET → PREPARE`。这是新设计的可靠性蓝图，不是对案例触发图的还原。

## 场地与随机规则

- 每个危险族都使用 `预告—生效—冷却/清理` 同源反馈；阶段升级每次只改速度、密度、组合、可玩面积中的一到两个轴。
- 场地事件和天气建立兼容矩阵：每一格写“是否允许、保留的反应路径、最坏出生点、清理责任”。随机抽取只在通过可解性过滤的候选集合中进行。
- 无输入基线必须覆盖三个终端：不应在标题/规则约定时长前误判胜利；不应在玩家取得控制且读完首个预告前遭遇不可避免失败；也不应因等待房主、弹窗或模式选择而永久停住。
- 观战是场域的一部分：淘汰者离开碰撞/触发层，进入能看懂剩余危险与终局的安全视角；不能留在竞技场继续挡人或触发事件。

## 基础件展开方法

案例中“古树枝杈”968 个与“茂密树冠”726 个合计约占 1,863 个单位的 90.9%，并大量使用细长缩放、倾斜和组件组。可迁移的不是具体素材，而是做法：

1. 用 1–2 个主基础件统一木桩、窄板、边缘、支撑和表皮节奏；
2. 用连续碰撞代理保证真实落脚面，不让每片可见枝条都承担物理；
3. 用少量危险底座、状态灯、出生/观战框景和终局地标建立信息层；
4. 视觉高频件与 4,000 级触发逻辑分账，分别测峰值可见、碰撞、计时器、运动体、生成物和重置项。

## 设计边界

- 首屏奖励弹窗 15 秒后仍遮挡主要观察面，不能照搬；主任务、首个安全选择和危险提示必须先于礼包、教程入口或可选能力被理解。
- 不复制三种模式、5 命/3 分、海岛轮盘、天气池、道具或礼包。首版地图若尚未稳定跑通一种模式，不要同时实现三种。
- 高播放、收藏与评分只说明样本有研究价值，不证明公平、随机可解、商业入口或重置可靠。
- 完整回合、多人、平局、房主缺席和连续新局都未实测；实施时仍须进入目标人数试玩矩阵。

## 身份

- `[元数据事实]` 最低与推荐人数均为 1，简介为“轮盘转得越来越快”；公开缓存记录 `play=7,633,605`、`valid_play=6,122,772`、`winner_nums=1,051,470`、`like=17,186`、`favorite=144,979`。完成时长中位数约 488 秒，`game_time_limit=0`，不能据此还原任何一种模式的单轮时长。

## 证据

- `[视觉观察]` 详情封面和出生画面显示海岛水面上的木桩/窄板竞技场。进入单人模式后，中央“系统提示”自动遮挡主要观察面；15 秒后仍未消失，唯一显著按钮写着“我已知晓！领取免费道具”。研究过程没有点击奖励入口，而是从游戏内正常退出，因此没有观察到完整一轮、淘汰、结算或第二局。
- `[代码事实]` 归档包含 1,863 个批加载单位、30 种模型路径和约 3.27 MB 的批单位数据；元数据记录 22,042 次总操作、4,031 个 ECA 触发记录和 57 次编辑地图记录。代码可证明这是高视觉展开、高逻辑展开的回合系统，不只是一个旋转机关。
- `[代码事实]` “古树枝杈”968 个、“茂密树冠”726 个，两类合计约占单位数的 90.9%；另有 124 个组件组、39 个木板条、22 个可变形方块、12 个破旧木板和 6 个分阵营出生点。1,716 个单位至少一轴不大于 0.25，1,479 个单位带 X/Z 倾斜，说明大量基础模型通过细长缩放、姿态、颜色和编组形成木板、桩体、边缘与植被表皮。
- `[代码事实]` 逻辑字符串明确出现三套玩法：经典 5 命、积分模式“每场胜者得 1 分、3 分获胜”和无限生命的无尽模式；另有简单/一般/困难选择、房主检测、开始提示、下一轮、积分轮结束与游戏结束。
- `[代码事实]` 随机场地事件至少包括木板变窄、柱子摇晃、柱子下沉消失；天气至少包括晴、雨、雪、雷暴，并有对应预告文本。代码还出现存活检测、玩家进入观战、复活、生命计数、无人存活结束、暂停运动器、随机道具发放和终点开启。字符串能证明这些系统存在，不能证明精确顺序、概率、速度或清理实现正确。

## 蒸馏

- `[设计推断]` 成熟生存场不是“机关越多越好”，而是至少四个可独立验证的状态面：整局/模式、场地危险与天气、玩家生命/淘汰/观战、结算/重置。各状态面只能通过明确事件交接，不能让天气、板面事件和玩家死亡各自直接改写终局。
- `[设计推断]` 随机变化应先选择结果、发布同源预告、进入有效期，再统一清理或换代；场地事件与天气若可同时存在，需要先定义兼容矩阵和最坏组合，保证每个组合仍有可读反应。
- `[设计推断]` 1,863 个单位并不依赖庞大资产词汇。两个高频基础模型承担九成展开，再由少量水体、板面、道具和地标件赋予主题与玩法身份；这是“窄词汇、高组织度”的强例，但不代表每张生存图都需达到同样数量。
- `[设计推断]` 开局说明、模式选择和可选道具都属于入口层，不能遮住出生安全面或把领取奖励变成观察规则的前置条件。无输入基线必须单独测试：玩家不操作时不应误判胜利、在看清前被淘汰、无限等待，或因为可选弹窗而无法进入主循环。

## 不应照搬与未知

- 不复制地图标题、海岛轮盘布局、模式数值、随机事件组合、道具/礼包、兑换码或商业入口。
- 首屏奖励弹窗是明确的入口反例，不把高播放量、收藏量或 4.4 详情评分当作该入口合理的证据。
- 没有实测各出生点公平、危险预告时长、随机组合可解性、淘汰等待、积分归属、房主掉线、平局、结算停机和第二/第三局清理。
- 本案例只支持代码结构、基础件展开和首屏反例；所有速度、概率、生命数与目标时长都必须为新地图重新设计并试玩。
