# 匿名案例 case-017

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它提供了目前案例库里最直接的“镜头—选择—环境—关系—任务”联动证据，也展示了城市剧情场景如何由两千余个单位和少数高频基础形状装配出来。适合用来设计剧情探索、关系模拟、悬疑调查、任务型城市空间或带剧情站点的混合地图；不适合照搬角色与故事内容。

## 证据范围

- 已观察：开始页、黑屏转场、固定镜头、电话选择、控制权归还、城市公园/写字楼移动、电梯事件、二次选择、NPC 群组变化、目标改写、角色对白、4% 好感和雨伞任务。
- 未观察：完整故事、旧地回访、结局、死亡、跳过、退出重进恢复、第二轮或多人打卡。
- 旧式单位表有 2,108 个单位、151 种 EID、149 个父组和 996 个被编组单位；方块-可变形、自定义曲面与基础圆柱合计 833 个，约占 39.5%。元数据记录 2,679 个 ECA 触发。

## 叙事节拍合同

每个关键事件都写成六步，不把“播一段对白”当作完整节拍：

| 步骤 | 必须回答 | 玩家可见反馈 |
|---|---|---|
| 门槛 | 哪个位置/前置/选择允许事件开始 | 目标靠近、场景聚焦或低强度预告 |
| 锁定 | 如何阻止重复触发和多人重入 | 旧指引关闭、输入暂存或角色站位固定 |
| 接管 | 镜头和移动是否被接管，多久 | 黑边、镜头切换、控件显隐或明确可跳过 |
| 决策 | 玩家此刻能改变什么 | 互斥选项，后果范围可理解 |
| 提交 | 哪些状态必须一起改变 | 场景/NPC、关系、目标、对象和存档同一提交点更新 |
| 归还 | 玩家下一步去哪里，如何恢复方向 | 控件回来，任务句与空间指引指向同一目标 |

把节拍写成状态向量，而不是只写章节号：

```text
STORY_BEAT       当前叙事节点
CONTROL_MODE     FREE / CINEMATIC / CHOICE / DIALOGUE
SCENE_VARIANT    事件前 / 事件后 / 回访版本
ACTIVE_OBJECTIVE 当前可执行目标
RELATIONSHIP     关系值或档位
CHOICE_HISTORY   已提交选择集合
```

一个权威转换同时驱动镜头、NPC 显隐、任务文本、指引、好感 UI 和后续门槛。不要由“人群看起来消失了”反推剧情已提交。

## 选择反馈梯度

选择后的反馈按由近到远安排：

1. 0–1 秒：按钮/声音确认输入已接受；
2. 1–5 秒：镜头、角色表情或对白确认语义；
3. 5–15 秒：场景人口、目标、路线或关系 UI 至少改变一项；
4. 后续章节：选择历史影响新的门槛、奖励、关系或结局；
5. 重进/跳过：必要的前四层状态能从权威快照重建。

不是每次选择都需要大分支。局部选择可以在同一主线上改变关系和下一段表现，但必须让玩家知道它不是装饰按钮。

## 城市剧情装配语法

该案例的高频基础族可转译为通用职责，而不是复制具体街区：

| 基础族 | 主要职责 | 常用变化 |
|---|---|---|
| 可变形方块 | 楼体大面、室内壳体、门槛、台阶、家具主体 | 长宽厚分层、退台、开口、灰阶 |
| 自定义曲面 | 树冠/花簇、衣物/角色轮廓、装饰边、柔化城市硬边 | 曲率、薄轴、重叠轮廓、局部倾斜 |
| 基础圆柱 | 灯柱、栏杆、树干、结构柱、角色/道具关节 | 粗细、分节、端帽、成组节奏 |
| 小地板/薄片 | 可走接触面、玻璃/招牌/纸张、边框 | 极薄缩放、材质与碰撞职责分离 |
| 球体/环件 | 灯罩、花木体块、装饰节点、视觉焦点 | 尺寸序列、局部发光、少量高对比 |

先用 4–6 种基础族做建筑、园景和室内的共享接口，再给每个剧情站点增加一个近景焦点：传单、电话、电梯按钮、雨伞架。场景密度要服务镜头和触发，不在所有过渡区域平均铺小件。

## 可迁移的场景状态法

- **人口变化**：事件前用人群制造阻挡/压力，提交后只保留相关角色，让路线和关系同时变清楚。
- **设施变化**：门、灯、电梯、显示屏或天气在提交点切换，既是叙事后果也是新的导航。
- **关系显影**：关系 UI 不必常驻；在第一次相关选择或对白后出现，避免首屏系统噪声。
- **任务落地**：常驻目标句解释意图，近景道具承载交互，最后几米用指引收束。三层必须同时换目标。
- **镜头复用**：固定建立正常跟随、对话双人、物件特写、揭示和返回控制五种镜头职责；每个事件从职责库组合，不为每句对白新建一套镜头逻辑。

## 必测与降级

- 演出中死亡、离开、跳过或断线只能落到“事件前完整态”或“事件后完整态”；禁止半开门、旧人群与新目标并存。
- 回访旧场景时检查人口、设施、指引和关系反馈是否共同保留；重新加载需从存档重建，而非依赖对象当前显隐。
- 多人进入同一门槛时明确谁看镜头、谁能选择、其他玩家是否等待，以及掉线后由谁接管。
- 若当前组件能力不足以可靠保存多分支，降级为一条主线加局部关系差异；若不能安全接管镜头，使用短定点构图与环境切换，不伪造不可跳过长演出。
- 性能不足时先减少不可达楼体背面、远景小窗、非焦点花簇和重复 NPC 表皮；保留接触代理、剧情近景、状态变化、目标对象与指引。

## 不应照搬

不复制标题、角色、公司、电话、对白、好感数值、雨伞任务、结局或具体城市构图。这个案例证明的是“叙事状态如何在空间中被看见”和“基础件如何围绕镜头职责展开”，不是一份剧情模板。

## 身份

- `[元数据事实]` 简介明确“只有一号位单人开是剧情，多人是打卡模式”，最低与推荐人数均为 1；本次只观察单人剧情，不测试多人打卡。
- `[元数据事实]` `pass_time_mid≈686.1`、`pass_time_avg≈577.6` 秒，但最快记录约 17.5 秒，口径显然会混入提前离场或不同模式；不能直接当作剧情目标时长。

## 视觉证据

- `[视觉观察]` 开始页先声明视距/音乐要求、单人与多人模式差异和“好感归零失败”，再由手动“开始游戏”进入黑屏过渡。约十余秒后固定镜头以公园、花丛、长椅和旋转木马作背景，让送传单的熊成为近景焦点。
- `[视觉观察]` 首个电话用全屏拟态来电界面提供“拒绝/接听”选择；接听后进入带黑边的对白镜头，演出结束才恢复移动摇杆与跳跃控件。控制权切换在视觉上明确，不让玩家一边移动一边漏读关键对白。
- `[视觉观察]` 自由控制恢复后，顶部持续显示“进 DDTV 并乘电梯去报道”，目标附近出现红色叹号式空间指引。玩家从公园进入写字楼大堂，靠近电梯按钮后镜头切到人群与按钮，电梯门开启。
- `[视觉观察]` 第二次选择为“过去道谢/安静等电梯”。选择道谢后，大部分排队人群消失，只保留后续相关角色；目标改成“去向拿传单的好心人道谢”。靠近对应角色后进入双人近景对白，好感条出现并保持为 4%。
- `[视觉观察]` 对白结束后目标继续变成“找把雨伞”，红色指引落在墙边雨伞架附近。到此退出；没有继续寻找结局，也没有验证回访旧地点、死亡、重新进入或多人模式。

## 蒸馏

- `[设计推断]` 叙事事件应作为一个可恢复事务：`门槛满足 → 锁重复入口 → 接管镜头/控制 → 对白或选择 → 原子提交场景、任务和关系 → 归还控制并重新定向`。只播放对白而不改变场景或下一目标，选择就会显得虚假。
- `[设计推断]` 叙事状态不是单一“当前章节”。至少分开记录 `剧情节拍`、`控制模式`、`场景版本`、`当前目标`、`关系值` 和 `选择历史`；镜头、NPC 显隐、目标文字、指引和好感 UI 都从这些权威状态读取。
- `[设计推断]` 选择应在下一个节拍内给可见后果。该图用“人群减少 + 目标改写 + 角色对白 + 好感出现”连续确认玩家确实选了道谢，比只在很久后的结局改一句文本更容易被理解。
- `[设计推断]` 导航可以分三层：常驻任务句负责“为什么去”，空间中的按钮/角色/雨伞架负责“去哪里”，贴近目标的红色指引负责“最后几米”。三者同源更新，文字不承担唯一导航。
- `[设计推断]` 高密度剧情场景仍可由很小的基础形状语法展开。方块、曲面、圆柱、小地板和球体分别承担建筑大面、轮廓修形、柱/灯/躯干、接触面和花木/角色曲面，再由编组、薄轴缩放、倾斜和受控色板形成完整城市空间。

## 不应照搬与未知

- 不复制角色关系、公司设定、电话界面、对白、好感数值、结局条件、成就名、城市布局或多人打卡模式。
- 没有验证拒接电话、安静等电梯、回访旧地、好感增减阈值、坏/大结局、演出跳过、死亡恢复、退出重进、存档恢复或多人成员状态；这些仍是设计与测试合同，不是已证明实现。
- 开始页信息量较大，且首次进入建筑时目标边界并不完全直观；不能把该图当作“首屏零摩擦”或“导航无缺陷”案例。
- 2,108 个单位与 2,679 次 ECA 触发只说明规模和结构，不等于帧内同时活动量、逻辑正确性或性能稳定；峰值可见、物理、阴影和动态逻辑仍需实测。
