# 匿名案例 case-019

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

这是一张任务化长流程跑酷。它适合回答：随行对象如何同时承担角色、进度和章节条件，以及长图为什么需要“章节合同”和高频恢复，而不只是把路线继续拉长。

## 证据范围

- 有出生区画面与发布缓存聚合数据，只观察了首屏，没有完成后段试玩。
- 缓存中位通关时间约 772.4 秒；601 个批加载渲染单位与 6,722 个触发计数属于不同系统口径，不能相除或互换。

## 构成拆解

- **可见任务状态**：黄、粉、绿、红、蓝、黑六个随行角色在出生区直接出现；数量、颜色、是否聚齐和是否到家比抽象数字更容易理解。
- **首屏承诺**：六色宽跑道、瀑布和远处标题把“带六小只回家”的对象、方向和情绪同时摆进第一视线。
- **章节合同**：任务文本把所需对象、玩家动作、完成区域与解锁反馈连在一起，例如聚集、带过白色区域或共同推物。
- **恢复密度**：发布字符串表含大量触发、存档、事件、圆点指引、传送与销毁区域，说明长流程的系统密度主要用于分段、引导和恢复。
- **基础结构**：大地板、无形碰撞、可变形方块、箱体和传送带形成跨长距离模块；主题装饰并不需要在每章换一套模型。

## 可迁移设计卡

每章先写一行合同：

`当前可见对象 + 所需玩家动作 + 完成区域 → 成功反馈 + 下一章权限；失败/重生 → 对象与章节恢复`

再检查：

| 字段 | 应明确的内容 |
|---|---|
| 对象状态 | 当前数量、位置、归属、是否可召回/丢失 |
| 章节门槛 | 必须带什么、做什么、在哪里结算 |
| 完成反馈 | 对象、门、环境、提示和检查点是否同源更新 |
| 越序 | 玩家先到出口、少带对象或重复进入时会怎样 |
| 重生恢复 | 玩家和对象分别回哪里，已完成章节是否幂等 |
| 信息优先级 | 主任务、下一动作是否先于教程、商店和可选能力被理解 |

长流程的内容预算要同时包含场景、任务状态与恢复节点。渲染单位较少不等于内容简单；逻辑复杂也不能弥补空旷壳体，二者需分别验收。

## 不应照搬与未知

- 不复制六个角色、彩色路线、技能配置、关卡顺序、商业入口或任务文字。
- 现有证据不能证明随行对象丢失后的找回、六色后续含义、完整节奏或每个阶段的难度。
- 多种界面系统同时出现在出生区会争夺注意；迁移时保留“可见任务状态”，不要照搬首屏信息拥挤。

## 身份

- `[视觉观察]` 详情页标注跑酷、解压、唯美，并提供单人进入。
- `[元数据事实]` 有效游玩约 397.6 万、点赞 174,029、评分聚合约 4.47；中位通关时间约 772.4 秒，属于长流程而非短图。

## 证据

- `[视觉观察]` 出生区把黄、粉、绿、红、蓝、黑六个随行角色排成一列，前方六色宽跑道指向瀑布与大标题；角色、颜色和远期出口在第一视线中建立“带六小只回家”的任务承诺。
- `[视觉观察]` 局内同时显示召唤、垫脚石、二连跳、滚动冷却、教程和商店等多组按钮；功能商店会在出生后自动打开。研究过程中立即关闭，未点赞、购买、投币或使用任何商业功能。
- `[代码事实]` 归档为 48 块、8 字节表项布局；批加载渲染单位 601，模型路径 58 种，ECA 触发计数 6,722。
- `[代码事实]` 字符串表包含 53 个通用触发区域、22 个存档区域、21 个事件触发区域、20 个圆点指引、10 个穿梭之门和 10 个销毁区域，显示流程被拆成大量可恢复、可引导的阶段状态。
- `[代码事实]` 明确任务文本包括“把六小只全部带过来，进入白色区域即可解锁下一关”“走到红圈处把六小只聚集起来”和“跟六小只一起把方块推进洞里”；角色名称与“六小只的家”也在字符串表中成组出现。
- `[代码事实]` 高频结构是 161 块大地板、41 个无形碰撞盒、约 118 个三色主题装饰、36 个可变形方块、34 个箱子和 16 条传送带；空间坐标横跨约两千米量级，说明它用模块化章节承载长流程。

## 蒸馏

- `[设计推断]` 随行角色可以成为“看得见的任务状态”。六个角色的数量、颜色、是否聚齐和是否到家，比抽象进度条更容易让玩家理解长期目标。
- `[设计推断]` 每章应写成可复述合同：要求的动作、需要保留的对象、完成区域、成功反馈和失败恢复。本图的集合、带队、共同推箱与白区解锁文本把目标、动作和结算条件连在一起。
- `[设计推断]` 长流程任务跑酷需要高频的阶段引导和局内恢复；触发区、存档区、圆点指引与传送门共同提示“章节状态”比单纯增加跑道长度更重要。
- `[设计推断]` 六色在出生区同时承担角色身份和路线分组，但后续是否始终一一对应尚未验证；设计时必须规定颜色语义何时保持、何时合流，避免玩家把装饰色误读为强制分线。
- `[设计推断]` 首屏信息需要优先级。核心任务、操作能力、教程、商业入口与社交号召同时出现，会与首个目标争夺注意；通用设计规范应保证主任务和下一动作先于可选系统被理解。

- 不复制六小只角色、彩色路线、关卡顺序、任务文本、技能配置、商店、广告或互动号召；可迁移的是可见状态载体、章节合同、完成区域反馈和长流程恢复结构。
- 本轮只观察出生区并主动退出，没有验证召唤/垫脚石技能、六色是否对应独立路线、角色丢失后的找回方式、后续章节难度或完整通关节奏。
- 601 个批加载单位与 6,722 个触发计数来自不同系统口径，不能把二者相除为“每组件脚本量”，也不能据字符串还原完整触发图。
