# 匿名案例 case-006

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 能支持的结论

- `[视觉观察]` 出生首屏直接显示“击败蛋贩子 0/1”、约 50 分钟倒计时、中心道路远端目标、多种武器陈列、物品栏和“无敌”控件。玩家无需寻找战斗入口，但同时读取的工具和 UI 较多。
- `[代码事实]` file ID 3 名称池含 1163 个字符串；高频编号前缀包括“基础方块_塑料”190、“方块”49、“方块-可变形”27、“三棱柱”20、“球体”16，以及“武器物品箱”10、“水雷”24、“质量回复电池”48、“放电柱/激光发射器/音浪风圈”各 6。名称池计数不等同于顶层组件或同时激活单位。
- `[代码事实]` 有限搜索命中“基础伤害”“去拿炸弹”“胜利区域”和标题资源中的“血条”；没有得到阶段、弱点、护盾、复活或冷却的可解释触发图。

## 设计边界

- 可迁移的是 Boss 首屏四问：打谁、还差几个、从哪里接近、先拿什么。目标与远端敌人共用中心轴，工具位于两侧，入口很快。
- 多工具应按输出、控制/破防、保命和恢复分组，并先提供低风险试用；把十种武器平铺给新玩家会增加比较成本。
- “无敌”若没有代价会破坏预告—反制—输出窗；作为教学或无障碍选项时，需声明持续、冷却、成绩影响和可用阶段。
- 大量基础件名称支持用窄几何词汇构成战斗场地的方向，但缺少单位变换与后段画面，不能从名称池推出装配配方、完成度或性能。
- 本案只证明单目标 Boss 的入口和资源词汇，不证明至少两阶段、攻击包络、弱点、伤害去重、团灭、Boss 越界、重试或多人缩放。它是边界样本，不是完整 Boss 配方。

## 使用限制

- 不复制题材、武器排列、无敌控件、道具数量、长时限或城市布局。
- 规划 `combat_boss` 时仍按专项蓝图完成至少两个阶段、两种差异化工具、统一伤害权威、同帧终局优先级和完整重置。
- 下一份正向案例必须观察一次完整“预告—反制—输出窗”、一次阶段切换，以及死亡或重试后的清理。

## 首屏战斗合同

- `[视觉观察]` 取得控制后，右上角立即显示“击败蛋贩子 0/1”，中央显示约 50 分钟倒计时；远端道路上排列多个带红色短条的角色或目标。目标动词和剩余数量不需要阅读长说明。
- `[视觉观察]` 出生点左右直接陈列多种武器，底部有物品栏，右侧另有醒目的“无敌”控件；玩家第一步更像选择工具并向目标推进，而不是寻找战斗入口。
- `[视觉观察]` 场地使用可读的城市街道轴线，远端目标在中心透视线上，武器陈列位于道路两侧；但首屏同时出现大量武器、背包、无敌和其他 UI，工具职责与推荐起手没有被分层教学。

## 蒸馏

- `[设计推断]` Boss 图的首屏至少应同时回答“打谁、还差几个、从哪里接近、先拿什么”。本案用中心轴目标和两侧工具把入口成本降到很低，适合作为单目标战斗的最小入口对照。
- `[设计推断]` 工具陈列应按功能而不是稀有度分组，例如持续输出、破盾/控制、保命和恢复；每组先给一个低风险试用目标，再让 Boss 验证选择。十种武器同时并排会把战术选择退化为试遍所有道具。
- `[设计推断]` “无敌”若是无限、无代价或随时可用，会抹掉预告—反制—输出窗；若确为教学/无障碍工具，应明确持续时间、冷却、可用阶段和是否影响成绩，并与正常路线分层。
- `[设计推断]` 名称池中大量基础方块、棱柱和球体说明战斗场地也能由窄基础词汇构成城市轮廓；但本案缺单位变换和完整镜头证据，只能支持“基础件可能承担场景”的方向，不能提供装配比例或性能上限。
- `[设计推断]` 一个“击败 0/1”目标和标题中的血条只能证明 Boss 最小终局入口。完整 `combat_boss` 仍必须增加可读攻击包络、至少两个阶段、反制/输出窗、Boss 越界、玩家死亡/观战、最后一击与全灭冲突以及干净重试。

- 未观察真实 Boss 外观、生命值、攻击、受击、阶段、仇恨、恢复、击败、失败、胜利区域解锁和第二次挑战；多人缩放完全没有证据。
- 该样本把 Boss 从“完全无入口证据”推进到“单目标战斗入口与资源词汇部分实证”，但不是强化 Boss 正向基准。下一张只接收能低成本观察一次完整预告—反制—输出窗、至少一次阶段切换，以及死亡或重试清理的候选。
