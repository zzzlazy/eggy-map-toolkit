# 匿名案例 case-007

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它补齐了“房间式解谜合集”的代码样本：八个题芯并不共享同一谜底或机关规则，却复用层牌、入口计时、延迟提示、正确/错误反馈、局部恢复与逐层推进接口。它也证明 700 级单位的机制图仍可用 354 个可变形方块和 50 个组件组搭出完整房间壳体，而不是让机关 Prefab 代替空间设计。

## 证据范围

- 已观察出生目标和第一层入口，未可靠进入第一题，也未实测解题、提示、复位、死亡恢复、越序或终局。
- 代码可证明八层标签、八个入口计时器、“提示1–8”、9 个存档区域、9 个传送门、密码正确/错误、真假按钮、宝箱和多类局部机关存在；不能还原谜底、完整事件顺序或实际可靠性。

## 先选结构：课程还是合集

| 结构 | 规则关系 | 玩家学习 | 允许变化 | 常见失败 |
|---|---|---|---|---|
| `curriculum` 课程型 | 全程共享一个规则族 | 展示 → 验证 → 单变量变化 → 组合 → 迁移 | 方向、数量、时序、空间关系之一 | 同时改太多轴，玩家无法归因 |
| `anthology` 合集型 | 各房间可有独立规则 | 每房间重新完成观察—输入—反馈闭环 | 题型可变，但交互与恢复接口稳定 | 只写“多观察”，让玩家猜作者意图 |

两者都可以做长图，但不能混淆。合集型的统一性来自房间接口、视觉语法和恢复尺度，不来自一句覆盖全部题目的规则；课程型若频繁更换题型，则不再形成知识迁移。

## 通用房间合同

每个谜题单元都写成一张小合同：

1. `ENTRY`：玩家在哪里取得控制，当前目标和可观察对象是什么；
2. `OBSERVE`：允许安全查看哪些关系，不在读题时计入不可避免失败；
3. `INPUT`：合法输入、重复输入、越序输入和多人同时输入如何处理；
4. `RESULT`：正确与错误由同一对象或同一信息面反馈，玩家能指出错因；
5. `LOCAL_RESET`：恢复输入、可动物、门、提示计时器和一次性触发；
6. `COMMIT`：先锁定完成，再开放出口和检查点，重复进入不能重复结算；
7. `RETURN`：死亡、离开、断线或误入后回到当前房间的可解初态。

把共享壳体参数化为 `ROOM_SHELL + FLOOR_LABEL + ENTRY_GATE + RULE_PANEL + INPUT_BAY + RESULT_FRAME + RESET_DOCK + CHECKPOINT + EXIT`。题芯单独挂在 `INPUT_BAY/RESULT_FRAME` 接口；房间变高、转向或换材质时，接口位置和净空仍保持一致。

## 提示合同

- 提示计时只在 `ROOM_ACTIVE && !ROOM_COMPLETE` 时运行；进度、完成、退出和重置都要取消旧回调。
- 采用至少两级渐进提示：先指出应观察的对象或关系，再给下一步动作；最后一级才接近答案。
- 记录 `首次有效输入时间、首个提示触发率、提示后完成率、直接等答案比例`。提示使用率高不一定是玩家弱，可能是题面、构图或反馈失败。
- 提示、错误反馈和答案不能只靠相同位置的长文字；用机关本体、语义色、连线、门态和声音共同表达因果。

## 恢复与难度

- 长合集把失败损失限制在单房间；每完成一房间再提交检查点。传送门只是恢复手段，不应成为跳题捷径。
- 课程型按“推理变量”推进；合集型按“推理步数、干扰项、信息跨面组合、动作执行压力”推进。每次升级明确改变什么，并保留前一层可读性。
- 错误选择若没有伤害，也要马上告诉玩家“哪个假设被否定”；若有死亡或长复位，必须先提供低代价验证。
- 房间入口必须在正常镜头与移动下实测。本次 ADB 观察没有可靠穿过第一层入口，只能说明入口操控仍是未知，不能当作已验证范例。

## 设计边界

- 不复制八层题面、数字答案、真假按钮顺序、地图壳体或计时值。
- 元数据中约 21 分钟的完成中位数不能直接成为新图目标；先按目标受众决定 2–8 个谜题单元和每单元失败损失。
- 代码中存在提示、存档和传送，不等于它们实际清理正确。重复进入、提示超时、错误后重置、检查点恢复和第二次游玩都必须独立测试。

## 身份

- `[元数据事实]` 简介为“破解层层关卡才能到达终点哦，开始挑战吧，小问题已修复。”，最低与推荐人数均为 1。公开缓存记录 `valid_play=899,074`、`winner_nums=146,361`、点赞 26,743、收藏 48,757，完成时长中位数约 1,263 秒；这些数据只说明样本值得研究，不证明谜题公平或提示合理。

## 证据

- `[视觉观察]` 出生区先显示“多观察、多思考”“难度逐层递增”和“密室共八层”等目标文本，并有明确的进入挑战区域；顶部进度为“通关蛋仔 0/1”。本次只观察到出生与入口，没有可靠穿过第一层入口，也没有实际解开谜题、触发提示、复位或走完整局。
- `[代码事实]` 旧式编辑器归档包含 702 个单位、71 个唯一 EID 和 76 个名称族；其中 354 个为“方块-可变形”，另有 50 个组件组。472 个单位带父级、81 个父件拥有子件、最大子件数 35，说明房间壳体与机关大量以基础件编组装配，而非仅摆放成品机关。
- `[代码事实]` 八层空间沿高度按约 20 个单位递增排列。每层均可找到层级公告、入口事件区域和一个计时器；计时器目标值依层约为 180–300，并分别发出“提示1”至“提示8”事件。代码可证明“进入后计时、延迟提示”的共用接口存在，不能证明单位就是秒、提示文本质量或计时器能否被正确取消。
- `[代码事实]` 全图有 9 个存档区域和 9 个虚空传送门，位置覆盖入口、各层和最终区域；另有“恭喜完成挑战”与终点线。它们强烈支持逐层恢复架构，但没有实测每个传送门的目标、死亡回收或越序保护。
- `[代码事实]` 局部题型并不相同：归档包含四位数密码 UI、“密码正确/密码错误”、墙上数字与形状线索、按钮开关及真假事件、藏宝宝箱、开关区域、石墩、浮冰和冰锥等。至少有 4 个按钮中多个触发“假的”，另一个触发“五层”；可证明存在诱饵与正确选择的显式分支，不能据此还原答案。
- `[代码事实]` 元数据记录 6,302 次总操作和 271 个 ECA 触发记录。517 个单位明确启用物理、35 个关闭物理，531 个单位非均匀缩放、223 个带 X/Z 倾斜，显示空间壳体、可走面与机关并非由少量拉伸地板构成。

## 蒸馏

- `[设计推断]` 这是“谜题合集”而不是“单规则课程”。各层可更换题型，但必须复用同一房间合同：`进入并读题 → 安全观察 → 输入 → 正确/错误同源反馈 → 局部复位 → 提交完成 → 存档/前往下一层`。共享接口能降低重新学习操作方式的成本，却不能替每层省略局部规则教学。
- `[设计推断]` 延迟提示应由“进入本房间且尚未完成”启动，在玩家取得有效进展、完成、离开或重置时取消；提示事件必须幂等。时间一到直接公布答案会把解谜变成等待，优先按“观察对象 → 关系 → 下一步动作”逐级加深，并记录提示依赖率。
- `[设计推断]` 约 21 分钟的中位完成时长需要把失败损失限制在单房间。每层入口、局部复位、完成提交与检查点要形成原子事务；死亡、误触、重复进入和提示回调不能把玩家送回多个房间之前或留下半开机关。
- `[设计推断]` 课程型和合集型需要不同的难度来源。课程型每站只改变一个变量并在后段组合；合集型可以更换规则，但每层都要重建观察—输入—反馈闭环，难度来自推理步数、干扰项和信息组合，不能只延长计时或把文字藏得更深。
- `[设计推断]` 垂直堆叠的重复房间适合用参数化“房间壳体 + 接口带 + 局部题芯”装配。共享墙地、层牌、入口、提示、存档与出口接口可以批量生成；题芯、语义色和关键剪影再逐层变化，既提高实例量，也保留辨识度。

## 不应照搬与未知

- 不复制八层标题、数字密码、答案、真假按钮顺序、具体题面、垂直坐标或装饰组合。
- 没有观察任何题目被解开；不能声称提示内容、错误反馈、局部重置、检查点、传送目标、越序保护或最终结算实际可靠。
- ADB 盲走未能可靠穿过第一层入口，只能把入口操控与相机列为待正常控制验证，不能据此认定地图存在碰撞故障。
- 单人入口不支持多人同步、共享状态或拥堵结论；所有谜题数量、时限、提示阶梯和房间尺度都要为新设计重新试玩。
