# 匿名案例 case-004

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它把塔防的“路径—波次—反制—核心”与黄金、食物、人口、科研、贷款和人员配置合成一张截止时间依赖图。它适合回答防守图为什么要有波次权威、路线扩张、职业反制、经济约束、主动终局和后台单位性能策略；不适合作为具体天数、价格、数值或多人公平模板。

## 证据边界

- 只观察到单人进入后的版本公告，没有实际建造、启动或完成任何波次。公告直接提到按交互激活后台人员、设备 UI 适配、计划天数调整、新职业以及怪物强度/资源补助选项。
- 归档展开 323 个批加载单位、26 种模型路径、166 组动态网格；170 个通用方盒、29 个隐形碰撞代理。触发图有 526 个条目、114 个自定义事件入口，并可见生命实体创建、生命上限修改、障碍创建和 AI 导航调用；元数据另记录 9390 条 ECA 触发。空间实例、触发条目和编辑统计是不同口径，均不等于编辑器顶层组件数或运行峰值。

## 防守—经营依赖图

```text
黄金 ─┬→ 招募/放置人员 ─→ 路线覆盖 ─┐
      ├→ 研究/改造 ─────→ 职业反制 ─┤
食物 ─┴→ 可持续人口                 ├→ 下一波准备度
帐篷 ───→ 人口上限 ────────────────┘

波次日程 → 敌人性质/数量/新路线 → 漏怪/城市压力
计划完成 + 生存条件成立 + 贷款清零 → 开放主动胜利
```

经济不是与塔防并排的支线。每个资源、建筑或职业都要能回答“它改变了哪条路线、哪种敌人、哪个压力窗”；无法改变防守决策的经济节点应删去或降为主题表现。

## 波次合同

案例字面量按天引入绿色怪群、第二路线、冻结附近人员的冰系怪、冰锥怪和后续持续波次，并把范围攻击、科研改造和免疫冻结的除雪角色作为反制线索。可迁移结构是：

| 字段 | 设计要求 |
|---|---|
| `wave_id / generation` | 唯一波代；旧代敌人和监听不能进入下一波 |
| 预告 | 明确倒计时、来路、敌人性质和新增规则 |
| 压力变化 | 一次优先改变路线、数量、抗性/控制或节奏中的一项 |
| 可用反制 | 波前已可获得，说明覆盖对象、代价与盲区 |
| 结束条件 | 所有合法敌人已击败/回收，生成器已关闭，漏怪事务已提交 |
| 清理 | 取消旧目标、投射物、冻结、路径占用和临时提示 |

新路线不能在怪物出现时才被玩家发现。先在世界中显示源点、方向、漏怪终点、可建设位置和激活时间，再让该路成为压力来源。

## 人员、防御槽与目标权威

- 固定防御槽维护 `EMPTY → RESERVED → ACTIVE → UPGRADING/SELLING → EMPTY`；购买先锁资源与槽位，成功后一次提交，失败同时回滚两端。
- 可移动人员另外维护职业、所有者、当前位置/站位、目标、行动、控制效果、免疫、升级和回收。不要因为人物站在底座上就把它当固定塔。
- 敌人由路线/波次权威创建并带代次、路线、路径进度、生命与漏怪标记；防御只锁定当前代、合法路线和合法范围内的目标。
- 冻结、范围伤害和免疫都从同一伤害/状态入口结算，不能由多个视觉触发各自改生命。目标失效、越界、卡路或波次清理时必须释放人员任务。

## 生存、债务与终局

该案例同时存在食物连续为负失败、怪物进入城市压力、计划天数、未偿贷款阻止胜利和主动点击胜利。设计时把它们归到一个终局权威：

```text
RUNNING
  ├─ food_failure / core_failure → FAILURE_LOCKED
  └─ schedule_complete && defense_survived && debt == 0
       → VICTORY_READY → player_confirm → VICTORY_LOCKED
```

同帧发生计划完成、最后一只漏怪、食物结算、还贷和点击时，先固定本轮快照，再按预定优先级提交一次。`VICTORY_READY` 只开放按钮和反馈，旧波、购买、贷款或资源事件不能在终局锁后反改结果。

## 空间与性能分账

- 路线表皮、城市/基地壳体和岗位外观可由通用方盒与动态网格装配；真实寻路边界、漏怪门和接触面只用少量连续碰撞代理。不要让每块墙、雪地和装饰都参与物理。
- 323 个批加载单位并不代表系统简单：元数据的 9390 条 ECA 记录显示逻辑轴很重。设计总账应分别记录静态场景实例、活动人员、敌人、目标监听、投射物、状态效果和事件峰值。
- 公告给出一种可迁移的降级策略：后台人员仅在放置、点击、认领任务或战斗相关时移动，其余时间保持权威状态但冻结表现。优先减少无决策价值的持续运动、阴影与远景更新，不删路线、预告、反制和核心反馈。

## 不应照搬与必须再测

- 不复制具体天数、职业、贷款、食物规则、升级、怪物倍率或数值；目标 5 分钟与 25 分钟的防守图需要完全不同的压力和恢复尺度。
- 本案例没有实测任何波次，不能证明寻路、射程、目标选择、冻结、购买、退款、卡怪、漏怪或终局可靠。
- 单人标签不支持多人经济、抢建和归属结论。部署前至少测试空防线、满槽、两波连续、最后一只漏怪与波次完成同帧、单位卡路/越界、建造者退出和第二局。

- `[代码事实]` 一个主要数据块可解析为含 `unit`、`_unit_create_index` 和 `del_parent_unit_list` 的 MessagePack 键值结构。动态网格和删除父单位列表说明运行时状态替换存在，但不能仅凭字段名复原每次替换时序。
- `[代码事实]` 触发图聚合得到 526 个条目，其中 134 个启用；事件入口包含 114 个自定义事件、7 个生物进出触发区、5 个循环计时和 4 个游戏初始化。API 汇总包含大量整数状态读写、195 次计时器注册、69 次生命实体创建、58 次最大生命变更、13 次障碍创建和 7 次 AI 导航命令。这支持“生成单位—路径移动—生命/升级—自定义事件总线”的系统骨架，但调用次数不是运行峰值，也不证明事件连线无误。

- `[代码事实]` 归档包含怪物强度、怪物生命倍率和伤害增幅等参数词汇，也包含人员放置与升级事件。字面量证明这些概念存在，不证明具体数值、目标选择、射程、购买原子性或寻路恢复。

## 蒸馏

- `[设计推断]` 防守经营不是两个并排小游戏，而是一张截止时间依赖图：黄金、食物、人口、科研和职业配置共同决定下一波到来前的防线成熟度；经济节点必须能解释“它如何改变哪条路线的防守选择”。
- `[设计推断]` 波次教学应采用“何时变化—哪路变化—敌人新增什么性质—可用什么反制”的同源信息。第二路、冻结和冰锥压力都在时间轴上逐步加入，比只把敌人血量变大更能形成策略阶段。
- `[设计推断]` 新路线必须在激活前拥有可见入口、来向、城市/核心方向和可建设准备期。路线开启、当前波代、敌人代次、漏怪提交和清场应归同一波次权威，避免旧敌人阻塞下一天。
- `[设计推断]` 可移动人员和固定塔要分开建模。人员至少需要职业、所有者、当前目标、站位/移动状态、冻结或免疫状态、升级与回收；即使外观看起来像塔，也不能只用“底座是否占用”表达其生命周期。
- `[设计推断]` 食物失败、核心被突破、计划完成、贷款未清和主动胜利可能同帧冲突。先由一个终局权威固定本轮快照，再按明确优先级提交失败或开放胜利按钮；按钮只请求终局，不能绕过债务或生存条件。
- `[设计推断]` 公告中的性能策略很有价值：高逻辑密度不要求所有后台角色持续移动。远离玩家或没有任务的人员可冻结表现，只在放置、认领任务、攻击或镜头相关时激活；权威状态继续存在，视觉代理按需更新。
- `[设计推断]` 170 个通用方盒、29 个碰撞代理和 166 组动态网格表明“基础件—碰撞—状态外观”可以分层；但 323 个批加载单位、526 个触发条目与元数据的 9390 条 ECA 记录也说明视觉完成度和逻辑复杂度是两条独立预算轴，不能用其一冒充另一项。

## 不应照搬与未知

- 不复制 18 天以上流程、具体天数、职业名称、价格、贷款周期、食物惩罚、怪物倍率、升级路径、冰雪主题或胜利条件；这些都必须按目标时长和可验证组件能力重做。
- 本次没有实际走过一波。不能宣称目标选择、路径、射程、冻结、范围伤害、购买/退款、人口占用、债务、粮食结算、主动胜利或失败恢复正确。
- 未验证同一天多事件的解析顺序、最后一只怪与漏怪/计划完成的冲突、卡怪回收、单位越界、玩家退出、重进、第二局清理或低端设备帧率。
- 最低与推荐人数都是 1，本案例不能支持多人抢建、共享资源、建造归属、房主退出或多人经济缩放。
- 该案例足以把防守蓝图从“完全暂定”提升为“代码与入口部分实证”，但下一张防守样本应低成本完整观察至少两波、一次建造/升级、一次漏怪或失败和下一轮清理。
