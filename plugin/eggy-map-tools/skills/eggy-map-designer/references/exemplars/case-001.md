# 匿名案例 case-001

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它补足了“用基础件和功能件拼出完整载具产品族”的证据：九辆外观不同的赛车共享稳定的车辆接口，长赛道则由少量资产词汇经过大比例缩放、旋转和职责分层展开。它适合指导载具装配、赛道壳体和选车状态，不提供已验证的驾驶参数。

## 证据范围

- 出生区截图只证明九车展台、选择标记、泊位/围栏语法和 `0/1` 终局 UI。没有完整驾驶、通关、多人或第二局实测。
- 发布缓存含 743 个批加载渲染单位、31 种模型路径；中位完成时长约 271 秒。元数据的编辑操作和 ECA 数不等于可见组件数或同时活动逻辑数。

## 构成拆解

- **载具装配族**：9 个车辆核心、9 个载具主体、9 个座椅、9 个加速区域和 36 个轮子，形成可推断的九套统一接口。先稳定核心、座椅、轮位、碰撞与控制接口，再用外壳和材质做车型变体。
- **赛道职责层**：193 个可变形方块、94 段动画围栏、93 个无形方块、91 段铁丝围栏、49 个箭头路障、35 个等腰三棱柱和 31 块大地板分别提供路面体量、可见边界、碰撞代理、方向提示与坡/弯塑形。接近的数量不证明逐段绑定，实施时仍要显式建立接口。
- **基础件塑形**：636/743 个单位非均匀缩放，300 个单位至少一轴绝对缩放不小于 10，497 个姿态未对齐 15 度。31 种模型通过尺度与姿态形成大范围非正交赛道，而不是用大量不同 Prefab 堆题材。
- **进入与换车状态**：出生区先展示车型并标记当前选择；文本池另有返起点、换车连同蛋仔复位、自由赛道和高处观赏。它提示选车、占用、观战和复位是独立事务，但实际逻辑尚未验证。
- **尺度边界**：坐标包络在 X、Z 两轴都接近或超过千米，中位完成约 4.5 分钟。这是长赛车/展示参考，不是短竞速密度配额。

## 可迁移设计卡

| 层 | 必须声明 |
|---|---|
| 车辆接口 | 核心、外壳、座椅、轮位、控制/加速、碰撞扫掠包络、可用/占用状态 |
| 选择事务 | 进入展台、选择确认、占用冲突、未选车、换车、上下车中断与复位 |
| 道路表面 | 直道、弯道、坡道、制动区的局部基向量、宽度、坡度和接缝 |
| 边界职责 | 可见护栏、无形碰撞代理、方向提示和不可达背景分别预算，不能互相冒充 |
| 操控标定 | 低/中/高速度的转弯半径、制动距离、镜头、净空和最坏碰撞 |
| 恢复 | 翻车、卡死、坠落、弃车、换车、玩家死亡和载具缺失的恢复口袋 |
| 终局 | 车与玩家的到达关系、同帧冲突、终局后停车/释放和第二次进入清理 |

先用一辆灰盒车标定三个速度档，再复制稳定接口做车型变体；赛道装配按 `ROAD_SURFACE + VISIBLE_EDGE + COLLISION_PROXY + DIRECTION_CUE + SCENERY` 分层展开。车辆数和赛道长度由目标人数、时长与视区预算决定，不能把九辆/743 单位当默认配额。

## 不应照搬与未知

- 不复制车型、车辆数量、展台、路线、格纹视觉、音乐、商业入口或隐藏玩法。
- `use_vehicle_enable=0` 与车辆组件共存，说明权限字段不能独自证明玩法不存在；实施前仍要以当前版本组件证据为准。
- 所有精确转弯、刹车、镜头、碰撞、换车、观战、恢复与重置参数都未实测，必须保持 `TBD-PLAYTEST`。

## 身份

- `[元数据事实]` 最低与推荐人数均为 1；有效游玩约 184.9 万，中位完成时长约 271 秒，平均完成时长约 311 秒，详情评分约 4.5。热度与评分只证明传播和反馈，不直接证明操控、公平或性能。

## 证据

- `[视觉观察]` 出生区是封闭的车辆展台：九辆外观不同的赛车并排朝向玩家，当前可选车辆用悬浮三角标记；黑色地面、白色泊位线、格纹旗和围栏让“先选车”成为第一动作。首屏 UI 显示 `通关蛋仔 0/1`，完全不输入期间没有误判完成。
- `[视觉观察]` 出生画面没有直接展示第一个弯道或远期终点，因此这次不能判断驾驶路线、刹车点、道路宽度、镜头和恢复口袋。进入约半分钟后通过游戏菜单正常退出，未进行完整驾驶或通关。
- `[代码事实]` 归档含 743 个批加载渲染单位、31 种模型路径；元数据另记录 12,386 次编辑操作和 389 个 ECA 触发，三种口径都不能称作编辑器顶层组件数或同时活动逻辑数。
- `[代码事实]` 字符串表中恰有 9 个车辆核心、9 个载具主体、9 个载具座椅、9 个载具加速区域和 36 个赛车轮子。它支持“九套 `1 核心 + 1 主体 + 1 座椅 + 1 加速区 + 4 轮` 的重复接口”推断，但缓存没有还原父子关系或精确参数。
- `[代码事实]` 赛道/边界词汇集中于 193 个可变形方块、94 段动画围栏、93 个无形方块、91 段铁丝围栏、49 个箭头路障、35 个等腰三棱柱和 31 块大地板；另有 16 个分阵营出生点、11 个事件触发区域、3 个加速箭头、3 个传送门与 2 组终点/胜利区域。
- `[代码事实]` 743 个渲染单位中 636 个采用非均匀缩放，381 个至少一轴绝对缩放不小于 5，300 个不小于 10，497 个旋转没有对齐 15 度，99 个在 X 或 Z 轴倾斜。位置包络约为 X `-13.3…983.4`、Y `-42.5…162.1`、Z `-904.2…169.2`；这证明大范围、非正交基础件塑形，不证明实际行驶方向或路线长度。
- `[代码事实]` 文本池出现“回起点请连车蛋仔一起复位”“换车请连车蛋仔一起复位”“没抢到车的宝宝可观察他们的车技”“自由赛道”“高处观赏”。它们证明作者为换车、返场和观赏准备了说明，不证明这些分支已经无卡死或公平。
- `[元数据事实]` `use_vehicle_enable=0` 与归档中的车辆核心/座椅/轮子同时存在；这个权限字段不能被解释成“地图没有载具”，只能记录为当前发布配置与内容共存。

## 蒸馏

- `[设计推断]` 载具应作为可替换的产品装配族，而不是单件装饰或玩家皮肤。先定义统一接口 `CORE + BODY + SEAT + WHEELS + ACCELERATION/CONTROL + COLLISION ENVELOPE`，再换壳、轮胎、灯光和材质；九辆车因此能共享选择、复位和赛道接口。
- `[设计推断]` 完整赛道不是一块拉长地板。可见围栏、无形碰撞、方向路障、坡面基础件和地板是不同职责层；94/93/91 这种接近的数量只提示它们可能并行覆盖长边界，不能据此宣称逐段一一配对。设计时应显式分别预算 `ROAD_SURFACE / VISIBLE_EDGE / COLLISION_PROXY / DIRECTION_CUE / SCENERY`。
- `[设计推断]` 31 种模型可以展开成 743 个单位和约千米级坐标包络，关键来自大量非均匀缩放和非正交姿态，而不是不断增加资产种类。载具赛道的基础件变体应服务于直道、弯道、坡道、缓冲区和观景层，不为数量平均撒件。
- `[设计推断]` “选车展台”本身是进入状态：要处理车辆被占用、玩家未选车、上下车、换车、返起点、观战与开始授权。场上摆出多辆车不等于这些事务自然成立；选择标记、可用状态与复位提示必须来自同一权威状态。
- `[设计推断]` 中位通关约 4.5 分钟说明它更适合长自由赛道/展示型赛车参考，不应把其体量、车辆数或恢复方式直接套进 90–120 秒短竞速。

- 不复制九辆车的具体外观、泊位布局、格纹封面、商业/赞助入口、作者文案、音乐、路线和隐藏玩法。
- 尚未验证车辆父子关系、核心/座椅/加速区参数、低/中/高速转弯半径与刹车距离、相机包络、碰撞、翻车/卡死恢复、换车事务、观战入口、终点优先级和第二次进入清理。
- 不把 743 个批加载单位写成 743 个编辑器顶层组件；不把 12,386 次编辑操作或 389 个 ECA 触发写成帧内复杂度。
- 下一张载具样本应优先允许短成本完成一圈或至少经过紧弯、坡道和恢复点，补真实操控包络；若只能看到车辆展台，不再重复取样。
