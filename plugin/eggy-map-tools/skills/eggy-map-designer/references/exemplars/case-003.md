# 匿名案例 case-003

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

它提供了“工业入口怎样先成为一个地方”和“多场景叙事怎样用不同尺度建立章节身份”的部分证据：工厂门景由大体量、门洞、罐体和管线构成，真正可控首屏则是超大厨房。它也提供一个重要反例——教程、商店和角色文字可以把已经完成的环境遮掉。适合参考工业门景、微缩室内、长叙事场景包和成品密度分配；不适合作为完整工厂跑线或玩法闭环样板。

## 证据边界

- 已观察详情封面、工厂入口建立镜头、超大厨房可控首屏和正常退出；没有完成任务或观察两个场景之间的转场。
- 归档含 4640 个单位、158 种 EID、167 个名称族、3198 个父子单位和 331 个带子件单位；可变形方块 768、三棱柱 650、基础圆柱 214、木板条 212、组件组 196。
- 归档记录 2656 个 ECA 触发；已解析图有 240 个触发器、960 个 API 调用和 20 个表现器绑定。文本支持收集金券、吃巧克力、角色解锁和多个章节/小游戏，但本次没有实测顺序与可靠性。

## 工业入口的四层构成

不要从“摆几个工业 Prefab”开始，而按远到近建立四层：

| 层 | 要解决的问题 | 可用形状与职责 |
|---|---|---|
| 记忆剪影 | 远处为什么一眼像大型设施 | 筒仓、罐体、塔架、粗竖管；`SILHOUETTE/SCALE_REFERENCE` |
| 建筑包裹 | 玩家从哪里进入、两侧为何站得住 | 柱跨、厚墙、横梁、栅格、侧翼体量；`ENCLOSURE/STRUCTURE` |
| 设备语法 | 这里生产或输送什么 | 有起点/终点的管线、法兰、支架、维护平台；`STRUCTURE/ATMOSPHERE` |
| 路线收束 | 入口和下一动作是否同向 | 中央门洞、地面轴线、亮度梯度、门内远景；`NAVIGATION/GOAL` |

先让这四层在灰材质下成立，再加警示色、灯、标牌和少量主题件。若隐藏传送带、箱子和警示灯后场景又变回空地，仍只是机关灰盒。

## 混合尺度场景包

本案只证明“工厂门景”和“超大厨房”两个明显不同的尺度世界均存在，不证明其实际转场。设计同类长图时，每个场景包至少声明：

```text
SCENE_ID          唯一场景与版本
ENTRY_CONDITION   从哪一节拍进入
ESTABLISHING_SHOT 先给玩家看的尺度与方向
SCALE_ANCHORS     三种熟悉物件，用于读懂角色比例
ACTIVE_OBJECTIVE 取得控制后的唯一主任务
EXIT_GATE         完成条件和离开方向
STATE_SNAPSHOT    返回或重进时需要重建的状态
CLEANUP_OWNER     计时器、生成物、UI 和临时角色由谁清除
```

尺度变化不能只改模型大小。超大厨房需要门柜、地砖、桌脚等熟悉物作比例锚点；工业入口需要门洞、栏杆、平台和灯具提供人体参照。建立镜头之后应把同一地标留在可控首屏，避免玩家取得控制时失去方向。

## 从 4640 件学什么

- 数量首先来自基础件装配：方块、三棱柱、圆柱、木板条、球/环与组件组承担大面、斜撑、管线、边框、字符和具体物件轮廓。
- 3381 个非均匀缩放、1579 个极薄轴、1506 个长轴和大量非正交倾斜说明“同一件通过比例、姿态和编组变成不同职责”，而不是每次换一个资产。
- 4640 是多场景、角色、文字、系统与环境的总账，不是工业主题的最低数量。新方案仍按 `MASS → MID → SURFACE → ATMOSPHERE/ROUTE` 和峰值视区分配预算。
- 每个装配实例都要标设计职责。重复一千件基础件可以成立，但不能只有“装饰”：至少让各区域明确覆盖轮廓、包裹、结构、接触、导航、比例参照或状态反馈。
- 大型编组适合封装门跨、罐体、厨房家具和字牌；组内视觉小件与连续碰撞代理分离，避免每个薄板都承担物理。

## 入口 UI 反例

该图可控首屏的大面积红字与可选入口明显抢过环境和主任务。通用约束应是：

1. 取得控制后的第一视线只保留一个主任务、一个下一动作和必要危险提示；
2. 教程按玩家第一次接近或第一次失败渐进出现，不一次性占据中景；
3. 商店、角色、广告、社交号召与无障碍选项不得自动弹出遮挡出生观察面；
4. 所有可选 UI 必须可立即关闭，关闭后不留下多个同权重入口；
5. 用无输入基线验证 UI 不会阻塞、误触、自动结算或掩盖必要反馈。

## 叙事系统的有限启示

代码里的金券、巧克力、角色解锁、全局事件、计时器和显隐调用说明长叙事会同时管理章节、收集、角色与场景状态。可迁移的结构是让一次提交原子更新“收集集合、场景版本、当前目标、角色权限和出口”；但本次没有完成任何任务，所有阈值、先后顺序、存档和异常恢复都必须重新设计并试玩。

## 叙事与系统证据

- `[代码事实]` 已解析触发图含 240 个触发器、1263 个常量节点、960 个 API 调用和 400 个取值节点；高频调用包括取得单位、注册/取消计时器、切换模型/节点显隐、获取全体角色、销毁单位及子件、发送全局事件、显示消息和读取路径点位置。
- `[代码事实]` 文本可核对到“吃巧克力”、吃完后金券出现、金券集齐后前往工厂、多个角色解锁、长段章节文本以及“机械大世界”等场景或事件词。它支持“收集门槛—世界变化—角色/章节推进—多小游戏”的系统方向，不还原完整顺序，也不证明每个分支可靠。
- `[设计推断]` 多场景长叙事应把每个世界建成独立的装配包和状态边界：进入条件、建立镜头、尺度锚点、当前目标、可离开出口、清理所有者与重进快照必须成套。不能只靠一次传送把两个不同比例的场景拼在一起。
- `[设计推断]` 长图密度应按镜头与章节职责分配。入口门景需要远轮廓、中层结构和门洞方向；超大室内需要熟悉物件作比例锚点、连续接触面与近景互动。过渡空间可以更轻，不能把 4640 作为每张图或每个场景的数量目标。

## 可迁移的工业门景方法

1. 先用左右不对称但视觉平衡的大体量夹出中央入口，不从传送带和箱子开始。
2. 用柱跨、横梁、墙板厚度和栅格形成可解释的承重层；筒仓、罐体与管线作为第二轮廓，主题资产只做焦点。
3. 入口内部使用高亮或更低对比的远景形成穿透感；门洞、地面轴线和顶端轮廓共同指向同一去向。
4. 管线必须接入罐体、设备、墙体接口或明确封头；悬空短管和平均撒法兰只会制造噪声。
5. 为门景分别分配 `SILHOUETTE`、`ENCLOSURE`、`STRUCTURE`、`NAVIGATION`、`SCALE_REFERENCE` 与 `ATMOSPHERE` 职责；数量不能替代职责覆盖。
