# 匿名案例 case-021

原始名称与身份字段已移除；下文只保留聚合观察、设计推断和证据边界。

## 为什么读它

两张详情层候选说明“有运动项目”与“围绕一个比赛对象持续攻守”不是同一结构。它们只用于分类和入站检查，不是体育对局正向案例。

## 两个边界

| 候选 | 已核对事实 | 不能据此声称 |
|---|---|---|
| 《匿名观察-026》 | 详情列出篮球、足球、保龄球、跳马、跳高、射击、游泳、划船、跨栏、跑步十个项目 | 存在统一控球、两队比分、场界与死球重启；它更像章节/题芯合集 |
| 《匿名观察-027》 | 足球场封面、单球卖点、简介“连人带球一起踢！” | 存在合法得分校验、攻守方向、出界归属、开球、平局或加时 |

两图只到详情层，没有进入单人或缓存代码。这里的结论是“证据不足以通过体育入站门槛”，不是“运行时一定没有相关机制”。

## 体育主类型的最低判据

```text
SPORTS_MATCH = 唯一比赛对象
             + 至少两方与清楚方向
             + 合法得分校验
             + 场界/出界归属
             + 死球冻结与一次重启
             + 常规结束、平局或加时
```

- 多个项目依次闯关：优先归章节挑战或机制合集。
- 拿球送进区域累计分：可能是积分争夺，需看是否持续存在控球、攻守转换和死球。
- 只有球场、球门、队服或碰撞卖点：保留题材标签，不启用体育权威循环。

## 设计使用方式

设计体育图时，先画比赛对象状态图 `FREE/CONTROLLED/CONTESTED/DEAD/RESETTING`，再做球场美术；为四条边分别写出界归属与重启点；最后验证同时触球、反向进球、乌龙、得分同帧出界、超时平局和第二局。任何一项依赖玩家自觉，都仍是灰盒风险。
