# 蛋仔地图设计框架

## 体验契约

在画路线前先写三句话：

- **玩家身份**：玩家在这个世界里扮演或完成什么；
- **主要动词**：整局最常做的 1–3 个动作，如追、躲、推、互助、观察或解谜；
- **记忆画面**：通关后最应该记住的一个空间、一次机制变化和一种情绪。

主题、玩法和美术都要能回到这三句话。若主题说“逃离失控工厂”，玩法却只是无因果关系的通用跳台，先修体验契约，不要继续加装饰。

用户只有题材、平台标签或一句模糊点子时，不要立即套用熟悉场景。按 [地图概念合成与创意分化](concept-synthesis.md) 先写玩家身份、具体场所、世界过程、主矛盾、状态转变与记忆剪影，并给出三个至少改变两项分化轴的候选；选择后再进入六层结构。

## 六层结构

把地图拆成互相校验的六层，避免只做组件清单。

1. **玩法主干**：玩家从哪里来、看见什么、做什么、失败到哪里、如何继续。
2. **可碰撞骨架**：真正承重的地面、墙体、坡道、落点和保护边界。
3. **空间体量**：厂房、峡谷、洞口、塔楼、天花与远景等主轮廓；它负责包裹路线和形成尺度感。
4. **路线语言**：颜色带、灯光、边缘线、重复形状、开口方向和可见地标。
5. **主题细节**：道具、植被、管线、标牌、碎片与局部动画；它们增强故事但不决定通行。
6. **系统层**：机关、触发、计时、存档、胜利、排行榜、难度模式和恢复逻辑。

每个新增物件至少属于一层。无法解释用途的物件通常应删除、合并或降级为远景。

## 节拍与节奏

短图可采用“展示—教学—测试—变化—高潮—收束”；长图应把它扩展为多个章节，每章内部仍有教学、强化和回收。

为每段记录：

- 进入画面时的主地标与下一落点；
- 主要动作和允许的替代动作；
- 单人目标耗时与多人拥堵风险；
- 失败代价、复位距离和连续受阻上限；
- 与前后段的强弱对比；
- 本段新引入、复用和组合的机制。

不要连续引入多个未教学机制。连续高压段之间安排安全平台、宽路或视觉奖励，让玩家重新建立方向感。

把路线先画成图而不是坐标表：节点代表教学、测试、奖励、会合、检查点与终点，边代表可走路线。只有当图上的关键路径、备选路径和恢复路径都闭合，才把节点落成坐标。直线可以是有意的速度廊道，但不能因为没有设计空间关系而成为默认。

每个节拍同时标记三条曲线：动作压力、认知压力和视觉强度。三者不宜长期同时满载。若动作已经很紧，视觉可以变清楚；若要展示大场景，动作段应给玩家足够观察时间。

## 核心规则与变奏

有强噱头的地图先把核心规则写成一句玩家能够复述的话，再围绕它做变奏。推荐顺序是：

1. **安全展示**：在失败代价很低的环境里让玩家看到规则结果；
2. **主动验证**：要求玩家亲自使用一次规则，但不叠加其他新机制；
3. **改变空间关系**：在左右、前后、高低、朝向或节奏中只改变一个维度；
4. **与旧机制组合**：把规则和已经学会的移动、机关或道具结合；
5. **高潮回收**：连续调用前面教过的判断，不在终局突然换题；
6. **奖励收束**：用低压移动、景观或终点仪式释放认知负担。

欺骗、隐形路、真假地板和方向反转类机制尤其需要稳定规律、即时反馈与短复位。玩家失败后应能说出“下次该怎么做”，否则谜题只是随机惩罚。视觉表象与真实碰撞分离时，把这种不一致限定在机制区；出生缓冲、检查点和终点仍保持直观可信。

## 空间与构图

- 出生区先提供安全观察面，再让玩家起跳；不要把第一步设计成盲跳。
- 通过门洞、桥梁、峡缝、机械框架或光束形成框景，让下一目标落在自然视线中心。
- 使用转折和遮挡控制信息量：只展示当前目标和一个远期诱饵，不一次暴露所有工段。
- 用高差形成章节感，但让落点轮廓在起跳前可读。危险背景与可落脚表面要有材质或明度差。
- 远景负责尺度和方向，不必全部拥有精细碰撞；近景负责动作反馈和接触细节。

用三种距离组织目标：脚下或下一落点解决即时操作，章节出口解决十几秒内的方向，主地标解释整张图的前进关系。每次转折后至少恢复其中两个层级，避免玩家只看箭头仍不知道自己身处何处。

展示/社交空间也使用同样的三层目标，但把“落点—出口—终点”换成“接触面—可达活动锚点—合影主地标”。反射面、框景、雾雪和轮廓光可以连接三层；不要让远景漂亮却找不到可到达的中景，也不要让特效盖住角色和交互点。

空间包裹不等于封闭盒子。地面、侧壁、顶盖、远景和光雾可只选其中两三种形成场所感；关键是路线与环境共享支撑、边缘和轮廓，而不是两套互不相干的物件。

当地图超过单个灰盒场域时，按 [场所形态、世界壳体与关键镜头](world-shells-and-keyframes.md) 把这套关系写成逐场景壳体卡。拓扑节点与节拍必须被覆盖，出生、核心动作、恢复/回望和终局都用取得控制后的真实相机复核；不要让编辑器鸟瞰图掩盖首屏遮挡或中景缺失。

## 形状语法

主题地图不等于堆主题 Prefab。先定义 3–6 种可复用形状，例如方块、圆柱、圆锥、拱环、斜梁和薄板，再规定它们的用途：

- 方块/薄板：地层、台阶、梁、墙、挡边；
- 圆柱/圆锥：岩柱、管线、支撑、尖峰；
- 圆环/弧段：洞口、机械框架、拱门；
- 不规则装饰：只放在轮廓转折、地标和镜头近处。

同一基础件通过非均匀缩放、倾斜、遮挡和材质变化形成组合轮廓。保持一套统一比例和材质语言，避免每个局部像来自不同素材包。

把资产词汇分成三层管理：

- **主基础件**承担地形、墙体、角色轮廓或连续表皮，可以高频复用；
- **辅助结构件**解决转角、弧面、支撑、边缘和碰撞；
- **地标件**只放在出生首屏、章节转折、交接和终点。

高频复用不是简陋的同义词。一个基础模型可以占可见单位的一半甚至更多，前提是非均匀缩放、朝向、轮廓组合、材质和色阶让它承担不同空间职责。反过来，模型种类很多但每件只出现一次，往往会破坏主题一致性。不要把“过半”当成固定配额；它只说明评审时应看形状语法和职责，而不是看素材数量。

形状语法只有展开成可重复装配体才会真正产生完成度。把墙跨、桥段、岩壁、屋架、机械底座、植被簇等写成局部配方，再用少量变体复制到场景；不能用“一个墙”“一个工厂门”“若干管线”替代实际的梁、柱、表皮、接缝、支撑和碰撞代理。数量口径、经验区间和装配模板见 [基础件装配与成品密度](assembly-and-density.md)。

## 色彩与光照

颜色之前先完成主题卡和形状语法；峡谷、工厂、古建、童话、科幻、恐怖、季节景观、海洋与抽象世界的构成起点见 [视觉主题与世界构成蓝图](visual-theme-playbooks.md)。主题不能只靠调色或摆放几个成品道具成立。

先定义语义，再定 RGB：

- 环境基色覆盖最大面积，负责氛围；
- 结构辅色区分可触碰表面和装饰；
- 路线色连续出现于落点、边缘或方向箭头；
- 危险色只用于会伤害、会移动或会坠落的元素；
- 目标色用于终点、奖励和章节出口。

可从 60/30/10 开始分配主色、辅色和强调色，但应按主题与可读性调整。光照先服务轮廓分离和路线指引，再追求气氛；雾与逆光不能吞掉落点对比。

动态灯光、雾效、色彩切换和镜头变化应对应可说明的状态变化：进入新章节、危险升级、目标出现、任务完成或情绪转折。若变化不改变信息或情绪，只会增加噪声与成本。

## 机制密度

密集不等于丰富。统计“玩家需要做出的不同判断”，而不只统计机关数量。多个传送带、转盘或销毁区若只重复同一判断，应视为一次机制的强化；新机关只有在引入新信息、新时机或新空间关系时才算新的认知单位。

为每种核心机制维护四个状态：安全展示、主动验证、单变量变化、与旧机制组合。若缺少前两项，玩家会把失败归因于未知；若只有展示没有组合，地图会像机关展厅。

## 叙事与场景状态

叙事图优先让故事发生在移动与空间变化中：远处目标出现、环境从完好到失控、同一地标在返回时改变、伙伴动作打开新路径。公告牌和悬浮文字只承担短提示、角色语气或可选背景，不承载玩家必须边跑边阅读的长段信息。

镜头、动画和不可操作段都消耗玩家控制权。每次夺取控制权都要换回重要信息或情绪，并提供清楚的开始、结束与失败恢复；重复游玩时尽量避免强制重复完整演出。

## 任务状态与首屏信息

护送、伙伴或收集图优先选择场景内的可见状态载体：跟随角色、被搬运对象、逐步完成的装置或会改变外观的地标。玩家应能在不打开说明页时回答“我现在有多少、还缺什么、要带到哪里”。每个章节同时定义完成区、成功反馈和对象回收，避免进度数字变化但世界没有变化。

首屏信息按以下优先级排布：主任务与下一动作、即时危险与移动规则、必要能力、可选教程与辅助、社交/商业入口。后两类不得自动遮挡安全观察面，也不得与主目标共用同等大小、色彩和动画强度。任何自动弹窗都要能立即关闭，且关闭后目标提示仍存在。

## 密度与性能

场景密度不是平均撒满物件。把细节集中在出生第一视线、路线转折、近距离落点和章节地标，背景大面用更少、更大的体量。

灰盒数量与成品数量必须分开记录。约 100–200 个组件可以验证两分钟路线，却通常不足以同时承担空间外壳、中层结构、表面节奏和氛围；成品计划应先按区域和层估算展开实例，再通过装配族重复生成。若总量明显低于同尺度参考，说明是刻意极简、大型成品资产替代，还是仍缺某一层。

主题导向地图可把较多预算给空间体量和基础几何，而不是机关；具体比例要由目标时长、设备帧率和现有单位上限决定。重复单位优先评估：

- 是否需要物理；
- 是否需要投射阴影；
- 是否能批量合并或使用动态网格；
- 是否可远裁剪；
- 是否能用一个拉伸体代替多个小件。

窄资产词汇能建立整体感，也能提高归档压缩效率，但不自动等于运行时优化。重复物件仍需检查批量合并、物理、阴影、透明和远裁剪；长走廊还要通过章节地标、轮廓变化和节拍变化避免视觉疲劳。

先按语义给物件分配性能职责：承重/交互件保留必要碰撞与反馈；近景焦点按镜头需要保留阴影；不可达背景、密集植被和纯轮廓件优先关闭物理与投射阴影。不要以统一开关替代分类，也不要让看似装饰的物件意外参与碰撞。

审计高复用场景时同时看四项：最高频模型占比、非均匀缩放比例、关闭阴影/物理的比例、地标件是否集中在决策节点。最高频模型占比只衡量词汇集中度，不代表画面质量或性能；大量小件即使同模，也可能因碰撞和投影产生高成本。

## 不同尺度的取舍

- **约 2 分钟短图**：少章节、强首屏、低复位成本；每个机制至少复用一次，装饰集中而非平均铺开。
- **5–15 分钟章节图**：需要存档/检查点、难度波形、章节地标和中期奖励。
- **超长挑战图**：需要明确模式选择、长期进度、排名或成就、容错资源和性能分区；不能把这些系统默认塞进短图。

“简单难度”只描述动作门槛，不代表画面可以简陋。视觉完成度、路线清晰和稳定帧率在所有难度都需要。

地图类型比时长更早决定结构。确定类型和混合边界时读取 [类型与结构](archetypes.md)；涉及玩家互相依赖时读取 [合作机制](cooperation.md)。
