# 试玩与评审

## 四次门检

1. **纸面路线图**：关键路径、支线、恢复和终点是否闭合；每个节点是否推进主类型目标。
2. **灰盒单人/规则沙盒**：尺寸、跳距、时机、相机、复位、胜负条件和核心规则是否成立；此阶段不评价装饰数量。
3. **目标人数**：并行宽度、超车、合作依赖、等待、越序和掉队是否可恢复。
4. **主题成品**：首屏承诺、路线可读性、空间包裹、基础件装配层级、光色语义、性能和终点收束是否成立。约 100–200 个展开实例的版本默认仍按灰盒评审；先按真实空间合同选择 `micro_space/themed_short/multi_scene/long_world`，再使用 300/800/2000/5000 件下限。低于本档下限只有在结构化例外逐项解释尺度、`MASS/MID` 承担者、两个复核视角和取舍后，才进入成品门检。

不要在灰盒失败时继续堆美术，也不要因离线结构校验通过而跳过成品试玩。

## 记录表

每名测试者、每次完整试玩至少记录：

- 首个目标理解时间，以及他用自己的话描述的目标；
- 各节拍进入/离开时间、首次与重试耗时；
- 当前版本、角色能力和镜头条件下的 `B/H/Jc/Jm/Jx/Lerr/C/Tr` 或相关载具标定，以及计划值与实测值的偏差；
- 每次失败的位置、他认为的原因、实际原因和复位耗时；
- 停顿、回头、误入装饰区、镜头丢失和看不清落点的位置；
- 多人拥堵、等待、互相影响、掉队和重新会合时间；
- 合作图分别记录各角色的主动操作占比、最长连续等待、每次交接是否成功、缺员时由谁接管能力；允许单人时另跑完整降级路径；
- 任务/护送图记录玩家能否读出剩余对象、对象丢失与找回时间、完成区首次识别时间、重复进区是否重复结算，以及重生/换章后的状态一致性；
- 回合图记录首次接触、首次得分/淘汰、领先变化、闲置时间、终局长度与结算/重置；
- 解谜图逐单元记录入口理解、规则复述、首次有效输入、第一次错误归因、提示级别与触发时刻、提示后完成、局部复位耗时、检查点恢复和重进；合集型不能用“全图会玩”代替每个异构题芯的教学验证；
- 每张图至少跑一次取得控制后完全不输入：记录是否提前完成、首个不可避免失败时间、是否卡在房主/模式/弹窗等待，以及主任务和安全选择在任何可选入口之前是否仍可读；
- 状态型地图记录重复触发、多人同帧、越序、死亡/掉线、终局冲突和连续第二/第三局；同时检查旧代对象、计时器、运动机关、占用和反馈残留；
- 社交/展示图记录首次有效活动时间、各地标停留与回流时间、走散后的重新汇合、多人合影遮挡、交互独占和换景后的方向恢复；
- 帧率异常、迟加载、穿模、错误碰撞和触发软锁；
- 最坏视区/状态的可见、碰撞、投影、动态、透明、逻辑与生成峰值；同一设备和镜头路径下的基线、灰盒、成品、满员与连续多回合差异；
- 关键镜头缺少的层级：接触面厚度、环境体量、中层结构、近景细节或远景地标；同时记录重复装配是否过于整齐、噪声过多或接口露缝；
- 主题辨识来自哪些基础轮廓、装配、材质和状态变化；若只能说出颜色或几个 Prefab，标记为主题语法不足；
- 最记得的空间、机制和情绪，检查是否符合体验契约。

用中位数描述典型耗时，用较慢玩家或高分位观察容错；不要只用作者自己的最快通关时间。

## 八项量表

每项按 `0=阻断体验`、`1=可用但明显欠缺`、`2=达到设计目标` 评分，并附证据：

1. 目标与路线可读；
2. 核心机制可学习；
3. 操作节奏与难度波形；
4. 失败归因与恢复；
5. 空间体量与主题一致；
6. 色光、镜头与信息层级；
7. 目标人数下的公平/合作/拥堵；
8. 性能、触发和异常状态稳定。

总分只用于比较迭代版本，不用于掩盖关键项。第 1、2、4 或 8 项为 0 时，不应因总分较高直接进入部署。

## 症状到根因

| 试玩症状 | 优先检查 | 第一类修正 |
|---|---|---|
| 玩家频繁问“去哪” | 地标、开口、路线色、转折后视线 | 重构构图或出口，不先加更多文字 |
| 玩家知道路线但连续失败 | 起跳面、落点、机关窗口、相机 | 改尺寸/时序/镜头，再考虑降难度 |
| 单独测试能过，接到路线里频繁失败 | 入射角、前一动作、相机、落点误差包络 | 在真实节拍中重新标定，不套实验室极限距离 |
| 几何能容纳但多人仍卡住 | 占宽、操作间隔、边缘余量、迎面流和转向 | 用目标人数重测有效净宽与交叉节奏 |
| 载具频繁擦墙、翻车或看不见弯后 | 车宽/车长、转弯半径、制动距离、镜头包络 | 独立标定载具尺度并重做弯道/视距 |
| 玩家说失败像随机 | 教学、反馈、规律、复位距离 | 单独验证规则并暴露因果 |
| 玩家停着等提示或答案 | 题面可观察性、提示阶梯、进度取消条件、错误反馈 | 先修题面与渐进提示，不用更短倒计时奖励等待 |
| 上一题会做，下一房间仍无从下手 | 课程/合集结构声明、局部规则、共享接口 | 若是课程型减少同时变化；若是合集型补每房间观察—输入—反馈闭环 |
| 解对后重进却门态/提示错乱 | 完成锁、检查点原子提交、旧计时器和局部重置 | 先锁完成并取消旧回调，再开放出口和存档 |
| 短图通关过快却很累 | 动作与认知压力同时过高 | 插入流动或观察拍点，不单纯加长度 |
| 长图中途厌倦 | 章节差异、远期目标、奖励与恢复 | 改波形和地标，不平均加装饰 |
| 多人堵在同一点 | 净宽、触发占位、交叉路线、复位 | 扩宽、错峰或增加等价路径 |
| 回合中后期无人接触 | 目标迁移、资源刷新、空间收敛 | 改循环与热点，不只缩短总时限 |
| 领先者越来越不可追 | 资源控制、出生路线、复合优势 | 拆开位置与资源优势，加入可读反制 |
| 结算后下一局异常 | 一次性触发、分数、对象与计时器重置 | 补齐状态退出和幂等重置 |
| 同一事件偶尔重复计分/开门/发奖 | 事件幂等锁、对象代次、原子消费和同帧竞争 | 先锁权威状态并原子提交，再播放延迟反馈 |
| 画面、声音与真实状态互相矛盾 | 多份状态源、异步反馈和取消条件 | 用一个权威状态驱动全部表现并清理旧回调 |
| 第一局正常、第二局出现旧机关或资源 | 计时器、生成物、占用、终局锁和新局初始化 | 建立完整 RESET 状态并连续跑两到三局 |
| 所谓合作可以各走各的 | 玩家间状态依赖和回馈 | 增加真实因果链或改称多人同行 |
| 一人持续解题，另一人只跟随 | 角色独占动词、交接频率、等待者任务 | 把进度控制权交还另一角色，加入可见交付物 |
| 单人能进但中途软锁 | 缺员能力、章节门、存档与一次性状态 | 为单人建立完整降级分支并独立重置 |
| 玩家反复问“还缺谁/东西去哪了” | 状态载体、对象回收、完成区反馈 | 让对象与进度在场景中可见，补召回和幂等结算 |
| 出生后先关弹窗才看见目标 | 首屏信息优先级、自动弹窗、按钮动效 | 延后可选系统，保留可关闭且持续的主任务提示 |
| 玩家不操作却提前通关、秒死或永久卡住 | 计时起点、出生保护、默认终局条件、房主/弹窗依赖 | 明确无输入合同，修正默认分支并把可选入口移出主循环闸门 |
| 社交图拍完一张照就离开 | 活动节点、换景诱饵、回流与表达工具 | 增加轻循环和可见的下一活动，不平均加布景 |
| 地图能玩但像白模/百件样板 | 灰盒与成品数量差、MASS/MID/PROP 层、装配展开 | 先补环境体量和中层结构，再按焦点添加表面细节，不随机撒装饰 |
| 数千件仍显得杂乱 | 资产词汇、装配接口、变体规则、颜色职责 | 收缩模型种类，统一装配族并删除无职责实例 |
| 首屏流畅，进入密集镜头突然卡顿 | 峰值可见、投影、透明、动态灯和切换量 | 按视区分层减负，不拿全图平均数解释峰值 |
| 单人正常，多人或多回合逐渐变慢 | 生成物上限、计时器、运动体、占用与旧代清理 | 限制同时活动量并修复回收/RESET，不先砍静态场景 |
| 优化后流畅但路线与机关难读 | 降级顺序、路线色、危险预告、目标反馈 | 恢复信息层，转而删远景微件、投影和非状态特效 |
| 画面丰富但像素材展厅 | 主轮廓、形状语法、层级和留白 | 减少资产词汇，强化大体量与焦点 |
| 换了主题色和道具仍像通用跑道 | 世界句、比例词、基础件语法、装配族 | 重做轮廓和中层结构，不继续堆主题 Prefab |
| 气氛很强但路线/危险看不清 | 语义色、灰度对比、雾、逆光、动态特效 | 先恢复落点与出口对比，再降低非状态性特效 |

每轮只优先修 1–3 个最高影响根因，然后重复同一测试条件。保留版本间数据，避免凭印象反复改回。
