# 结构修饰器蓝图

修饰器改变主循环的条件，不拥有第二套终局。先选主类型；只有当另一套循环拥有独立决策、节拍与状态交接时才把它写成 `secondary_type`。上涨液面、护送对象、载具、非对称身份、节奏判定、恐怖张力、垂直空间、随机变化、累计能力和可破坏世界通常仍是修饰器。

## 共用合同

每个启用的修饰器都要声明：作用、开始前提、同源反馈、失败恢复、整局重置和一个会改变设计取舍的指标。另写以下边界：

- **权威**：谁能开始、推进、结算和取消修饰器；它不能与主类型争夺终局。
- **作用域**：整局、章节、房间、玩家、队伍或对象；局部状态不得泄漏到其他作用域。
- **包络**：最慢/最快、最小/最大、最近/最远或最低/最高状态下，空间、相机和反应时间是否仍可用。
- **代次**：计时器、生成物、载具、对象、随机结果和延迟反馈都绑定本轮/本章代次；清理后旧回调失效。
- **降级**：依赖的组件、音频、人数或持久化不可用时，主循环仍能安全完成或明确停止。

两个以上修饰器并用时，为每一对写兼容项：相互作用、冲突优先级、最坏组合与共同清理责任。不要分别证明“都可玩”后就假定组合仍可玩。

## 上涨、追逐与倒计时压力 `rising_pressure`

**职责**：迫使玩家前进或淘汰落后者，只选一个主目的。压力对象/时钟必须持续可定位，开始由主循环权威状态批准。

**合同字段**：权威、开始闸门、可见压力参照、慢/中/快路径余量样本、与检查点的关系、接触/超时处理、与冲线同帧的优先级、清理。

**空间与节拍**：出生先给安全读图；压力曲线按真实慢路径而非作者最快线标定。转角、封闭镜头和机关等待处保留额外余量；检查点不能把玩家复活在已经越过的压力后方。

**必测**：完全不输入、最慢可接受路线、检查点提交同帧被追上、压力与终点同帧、第二次进入。指标优先记录最小压力余量或被追上位置分布。[《case-024》](exemplars/case-024.md)只部分支持持续世界压力和封闭主题壳体，实际 90–120 秒节奏与复位仍未验证。

## 护送、收集与伙伴 `escort_collection`

**职责**：把世界对象作为进度载体。每个必要对象要有稳定身份、状态、归属、合法区域、交付事务和丢失恢复；抽象计数不能取代对象位置。

**合同字段**：对象身份、至少四个生命周期状态、归属、可见进度、合法区域、交付原子提交、防重复、丢失恢复、检查点快照、终局清理。

**装配接口**：`SOURCE + OBJECT_BAY + CARRY/ESCORT_CORRIDOR + RECOVERY_BEACON + DELIVERY_FRAME + PROGRESS_DISPLAY`。对象落地、被卡、掉出边界或被不同玩家接触时，恢复点和归属反馈必须同屏可读。

**必测**：对象越界、携带者死亡/退出、多人同帧交付、检查点边界提交、对象缺失却满足终局。[《case-019》](exemplars/case-019.md)支持世界对象承载章节进度，[《case-015》](exemplars/case-015.md)支持空间交付物与缺员分支；二者都未完整验证对象丢失与多人并发。

## 载具与驾驶 `vehicles`

**职责**：载具改变输入、速度、占宽、转弯、制动和镜头，不能在步行赛道完成后再把角色替换成车。

**合同字段**：车身/碰撞包络、上下车事务、至少低/中/高三档标定（转弯半径、制动距离、镜头、净空）、镜头包络、坡度/弯角/护栏规则、车辆碰撞与交通、毁坏/卡死后的替换、终局清理。

**装配接口**：`SPAWN_BAY + MOUNT_CLEARANCE + ACCELERATION_LANE + TURN_MODULE + BRAKE_ZONE + RECOVERY_POCKET + DISMOUNT/FINISH_BAY`。隧道、门洞、桥面与侧护栏按车身扫掠包络设计；出生和复位口避免车辆堆叠。

**基础件装配证据**：[《case-001》](exemplars/case-001.md)以 9 个核心、9 个主体、9 个座椅、9 个加速区域和 36 个轮子形成九套可推断的车辆接口，并用 193 个可变形方块、可见/无形边界、箭头路障和坡面基础件展开长赛道。可迁移的是 `CORE + BODY + SEAT + WHEELS + CONTROL + COLLISION ENVELOPE` 与 `ROAD_SURFACE + VISIBLE_EDGE + COLLISION_PROXY + DIRECTION_CUE + SCENERY` 两层装配，不是车型、车辆数或路线。

**必测**：上下车中断、三档速度、最紧弯、多人相撞/堵口、翻车或卡死替换、第二次进入。当前案例只证明车辆/赛道装配与出生选车视觉，没有完整驾驶；所有尺寸、转弯、制动和镜头仍属于 `TBD-PLAYTEST`，不得沿用步行标定。

## 非对称身份 `asymmetric_roles`

**职责**：躲藏者、搜寻者、追捕者、防守者等角色拥有不同信息、能力、弱点、反制和目标；阵营换色不构成非对称。

**合同字段**：至少两个角色的可见信息、独占能力、弱点、反制和目标；分配与确认、信息边界、接触/计分权威、缺角色补位、终局/平局和整局重置。

**公平方式**：不要求几何完全对称，而要求每个强位置都有成本、暴露路径或对方工具。出生阶段要避免提前泄露身份/位置；中途加入、掉线和角色互换必须有明确策略。

**必测**：缺少一个角色、晚加入、终局同帧、信息泄露、交换角色或第二局。现有团队擂台案例只提供阵营与返场线索，不支持躲藏/搜寻平衡结论，因此保持暂定蓝图。

## 节奏与音游 `rhythm`

**职责**：判定读取一个权威时钟；音频、视觉拍点、输入窗口、连击和舞台动画都从它派生，不能各自计时。

**合同字段**：权威时钟、提前量、音画同步、至少两个判定窗、输入去重、失误/连击、目标设备延迟标定、静音可玩方案、序列重置。

**空间与反馈**：视觉拍点应在输入窗前到达玩家可见区；背景动画不能伪装成可判定目标。命中、早按、晚按、漏按由同一目标给出不同反馈，结束/暂停后清空旧输入和连击。

**必测**：静音、低/高延迟、同帧重复输入、暂停/重进、第二段序列重置。案例库尚无合格音游实证；判定窗和延迟容错不得凭经验写成精确值。

## 恐怖与悬疑 `horror`

**职责**：恐怖控制信息和张力，不取消路线、接触面、危险和出口的最低可读性。惊吓只在玩家仍有可理解反应时成立。

**合同字段**：可读性下限、至少四拍张力曲线、威胁的预告/生效/结束、可信安全区、揭示冷却、控制权与镜头、无音频/闪烁降级、失败恢复、会话清理。

**空间节拍**：`SAFE → ANTICIPATE → REVEAL → CONSEQUENCE → RELEASE`。黑暗、雾与遮挡服务于延迟信息，不遮住必经落点；固定镜头或强制转向结束后必须重新定向。

**必测**：关闭声音/减少闪烁、惊吓后方向恢复、威胁区域重进、安全区是否被破坏、死亡/退出中断。[《case-013》](exemplars/case-013.md)补充了可信建筑壳体、侵蚀层和房间/钥匙/陷阱状态词汇，但只观察入口，没有触发威胁或进入楼内；现有叙事案例也只支持镜头与控制交接。因此张力曲线、预告、反制、冷却、安全区、可访问性与恢复仍保持 `TBD-PLAYTEST`。

## 垂直攀爬与坠落 `vertical_climb`

**职责**：垂直高度必须形成层级目标、恢复和风险，而不是把平面关卡沿 Y 轴堆叠。玩家随时知道上方目标、当前层和坠落去向。

**合同字段**：至少两层的上方目标、坠落去向、相机风险与恢复；全局上升目标、坠落图、头顶净空、镜头包络、捷径/越序保护、恢复、终局清理。

**装配接口**：`LANDING + UPWARD_LANDMARK + SIDE_REFERENCE + FALL_CATCH/RETURN + CAMERA_VOID + NEXT_LAYER_FRAME`。层间错开视线，避免上层底面遮住落点；长坠落设置可预期的中途接住或快速回收。

**必测**：最大坠落、头顶遮挡与仰视相机、跨层捷径、检查点边界死亡、多人上下交叉拥堵。峡谷与八层密室案例只支持体量或垂直分层；[《case-023》](exemplars/case-023.md)再提供约 945 米 Y 跨度、69 个存档区域与 39 个自然传送门的代码证据，但只观察出生首屏，仍不证明攀爬镜头、长坠落或恢复可靠。

## 随机与程序变化 `random_variation`

**职责**：随机选择经过可解性过滤的局势，不随机决定玩家是否有反应机会。选择、预告、生效、清理都绑定同一代次与同一结果。

**合同字段**：随机权威与种子、至少两个候选、可解性过滤、与其他系统的兼容矩阵、同源预告、公平边界、代次、无候选回退和清理。

**组合规则**：多个随机轴先生成候选组合，再通过兼容/可解过滤；不能让天气、地形和道具分别抽取后才发现无解。若过滤后为空，使用已验证的确定性回退。

**必测**：最小极端、最大极端、明确不兼容组合、重复种子、多人同局结果一致、第二代清理。[《case-022》](exemplars/case-022.md)可证明场地与天气随机系统存在，但没有实测最坏组合或连续重置。

## 累计能力成长 `cumulative_growth`

**职责**：输入计数、权威能力值与玩家看到的反馈档位分开。连续数值可以存在，但空间和信息只围绕少数经过验证的档位设计。

**合同字段**：输入事件、去重、权威值、夹紧/上限、至少两个反馈档位、检查点策略、至少三档空间标定和终局清理。

**空间耦合**：最低/中段/最高档分别标定起跳、制动、转弯、落点、机关窗和镜头；检查点原子保存位置与能力快照。新局和终局恢复默认能力并取消旧监听。

**必测**：长按/连按去重、检查点同帧死亡、达到上限、最高档操控和第二次进入。[《case-012》](exemplars/case-012.md)支持反馈档位与低渲染/高逻辑分账，精确去重、上限和继承仍未验证。

## 破坏、拆解与可毁世界 `destructible_world`

**职责**：把建筑面、道具、目标或遮挡从稳定对象状态变成可改变的路线、资源或场景结果。它只改变章节、积分、探索、战斗或沙盒主循环的环境条件；若“谁先拆够分数”决定胜负，积分仍是主类型，若“拆完房间开路”决定进展，章节仍是主类型。

**合同字段**：权威、目标身份、至少四个目标状态、合法伤害来源、同帧命中去重、伤害/进度规则、销毁原子提交、至少一组依赖结构、碰撞切换、碎片峰值/寿命/碰撞/清理预算、检查点策略、与主终局同帧的优先级和整局清理。

**对象与装配接口**：`STATIC_FRAME + DESTROYABLE_TARGET_SET + DEPENDENT_SURFACES + COLLISION_PROXY_SET + DAMAGE/COMPLETION_FEEDBACK + REWARD_OR_ROUTE_PORT`。静态梁柱、门框和收边负责空间连续性；可毁面拥有稳定 `TARGET_ID/generation`；视觉裂纹、碎片与音效只消费权威状态。需要独立受击、显隐、换材质或碰撞切换的件不能为了合并而失去对象边界。

**转换**：合法命中先验证主循环阶段、目标 ID、代次、来源、冷却与未提交锁，再只推进一次 `INTACT → DAMAGED → CRITICAL → COMMITTED_DESTROYED`。最后一次命中原子锁定目标/房间、提交奖励或章节进度、切换碰撞、执行有向无环的依赖结果，并开放下一路线/终局检查；不能先加分后销毁，或由画面上还剩多少模型反推完成。

**空间安全**：玩家脚下、头顶或唯一退路上的依赖面消失前必须有预告、合法落点、搬离、延迟或完整恢复分支。多房间变奏至少改变目标拓扑、工具取舍、环境压力、拆后用途或信息顺序之一；只增加耐久不算新节拍。

**性能**：为碎片、动态件、同时受击目标、碰撞切换、音效/粒子和延迟回调分别设峰值与回收。冷进入、首次命中、多目标同帧、整组连锁和终点出现分开测；全图实例多、模型词汇少或已有批合并都不能替代可控状态的帧率证据。

**必测**：同帧重复命中、完成奖励重复、玩家接触时依赖面坍塌、部分破坏后死亡/检查点恢复、销毁与主终局同帧、碎片/回调旧代残留和第二次进入。[《case-002》](exemplars/case-002.md)只提供多个房间、墙组—依赖地板/天花—产豆—出口的代码词汇和大厅首屏，未实际挥锤；命中手感、耐久、原子性、连锁安全、碎片峰值与重进均为 `TBD-PLAYTEST`。

## 组合验收

启用修饰器后仍需回答：

1. 主类型的终局是否仍唯一；
2. 修饰器最坏状态是否保留至少一条可理解、可执行的反应；
3. 作用域、代次、延迟与生成物是否有清理责任人；
4. 多个修饰器的每一对是否写了冲突优先级和共同最坏测试；
5. 依赖项失效时是安全降级、回到主循环，还是明确中止；
6. 所有未有本地案例支持的精确数值是否仍标为待试玩。
