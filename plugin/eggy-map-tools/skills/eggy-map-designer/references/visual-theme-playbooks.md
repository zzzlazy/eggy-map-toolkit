# 视觉主题与世界构成蓝图

本文件回答“同一玩法骨架如何真正变成某个世界”。主题不是背景名词或一组 Prefab；它至少要同时改变空间轮廓、结构装配、比例、材质节奏、光色和局部状态。组件具体名称与 EID 必须在当前版本目录中查询，本文件只定义设计角色。

需要直接落地时，先用 [视觉世界支持卡](visual-world-support.md) 把下列宽题材路由到十五个稳定 ID。支持卡为每个 ID 补齐精确的形状职责、装配族、基础件展开、壳体起点和实证边界；本文件保留各大题材的设计原理与案例解释。目录外题材可以自定义，但不能少于支持卡的合同深度。

## 证据边界

- **峡谷/自然地貌**有《case-005》的高密度基础几何、章节轮廓与性能分工证据；
- **热带泥地/角色场景**有《case-015》的方块、棱柱、圆柱高复用证据；
- **冬季景观/社交展示**有《case-020》的三层景深、窄植被词汇和装饰性能职责证据；
- **封闭酒窖/上涨逃生**有《case-024》的连续包裹、危险色和单基础件高复用证据；
- **现代城市/剧情空间**有《case-017》的基础件楼体、街景/室内门槛、近景任务道具和人口/设施状态变化证据；
- **人类尺度室内/学校**有《case-008》的出生教室、窄基础件词汇、组件组与碰撞/投影分账证据，但后段房间与完整动线未观察；
- **工业门景/混合尺度叙事**有《case-003》的入口建立镜头、超大厨房首屏、4640 单位多场景基础件装配和入口 UI 反例；**可破坏工厂室内**再有《case-002》的大厅首屏、7166 单位/30 模型路径窄词汇、房间/走廊/销毁词汇和持续低帧率反例，但两案都没有完成一段实际生产动线；
- **海洋环境封套/垂直跑酷**有《case-023》的海草/珊瑚近景、路线中景、雾化海床远景和 889 单位/约 945 米垂直跨度代码证据，但完整路线、海底探索拓扑与动态水体状态未观察；
- **恐怖旅馆/废弃室内**有《case-013》的入口首屏、2964 单位基础件/破损层和房间/钥匙词汇证据，但楼内路线、威胁节拍、可信安全区与性能未观察；
- 玩具工厂只有部分实证，仍不支持完整糖果、童话或巨物微缩世界；古建、科幻与抽象主题目前主要是通用设计模板。海洋与恐怖也只有部分实证，不得声称已由本地优秀样本完整验证。

案例只能证明其中出现过的构成方法，不能证明所有同题材地图都必须使用相同颜色、资产或路线。

## 先写主题卡

在组件清单前完成以下字段：

| 字段 | 要回答的问题 |
|---|---|
| 世界句 | 这是“什么地方 + 正发生什么”，例如“午夜停工后仍自行装车的玩具工厂”，而不是只写“工厂” |
| 记忆剪影 | 玩家离开后应能画出的一个大轮廓是什么 |
| 比例词 | 世界是厚重/纤细、巨大/微缩、整齐/歪斜、柔软/尖锐中的哪两到三项 |
| 主基础件 | 哪 3–6 类基础形状承担大部分可见单位 |
| 装配族 | 哪 3–8 种墙跨、桥段、地貌段、机械架、景观簇或活动台反复出现 |
| 材质节奏 | 大面、边框、接缝、磨损和发光分别出现在哪里 |
| 光色语义 | 环境、路线、危险、交互、目标与阵营各是什么角色色 |
| 世界状态 | 至少一种进入章节、危险升级、任务完成或情绪变化时可见的环境变化 |
| 禁用清单 | 哪些常见形状、颜色、Prefab 或特效会破坏本主题 |

若删掉地标 Prefab 后，剩余地面、墙体、支撑和边缘完全看不出主题，说明形状语法尚未建立。刻意以大型成品资产为核心的地图可以例外，但必须说明资产承担了哪些宏观与中层职责。

主题卡只决定“世界说什么”，还不能证明玩家真实相机里存在完整场所。灰盒通过后，按 [场所形态、世界壳体与关键镜头](world-shells-and-keyframes.md) 把拓扑节点和节拍分配到 `theme.world_shells[]`，逐壳体声明包裹、三层景深、比例锚点、共享装配族、状态变体、转场与复核视角；多场景地图不能把全部主题预算堆在出生首屏。参数化展开后再用 [题材适配账与视觉证据](theme-adaptation-audit.md) 将每个真实装配族和区域绑定到形状、结构、材质、变体、状态与相机复核，防止丰富主题卡落地成通用骨架换色。

## 1. 自然峡谷、山地与洞穴

**世界句示例**：被风蚀和旧工程切开的峡谷仍在坍塌，玩家沿残存栈道向光口攀升。

- **轮廓**：用大块不对称体量形成夹缝、外挑、层台和远近遮挡；不要把同尺寸石头均匀排成墙。
- **基础件**：非均匀缩放方块/棱柱做岩层，圆柱/锥体做岩柱和断面，薄片做层理，少量曲面做洞口或风蚀边。
- **装配族**：岩壁段、转角崖段、洞口框、栈道支座、落石簇、稀疏植被簇；相邻段整体旋转和错高，再用中块收缝。
- **色材**：先定三到五级同色岩层，再用路线表面和危险裂隙做语义对比；积雪、苔藓或熔岩只作为环境过程，不平均覆盖。
- **光雾**：雾用于拉开前中远景，洞口/天光负责方向；逆光不能吞掉落点轮廓。
- **性能**：视觉岩片默认无物理、少投影，通行与阻挡由连续代理承担；不可见背面不铺微件。

## 2. 工业、工厂与机械设施

**世界句示例**：自动化生产线失控后仍按错误节奏运行，玩家穿过分拣、组装、质检和装车区。

- **轮廓**：使用规则网格、重复跨、巨大设备、管线桥架和高低平台；章节变化来自生产功能与机器尺度，不只是换灯色。
- **基础件**：方块/薄板做梁柱和墙板，圆柱做管线与轴，环件做法兰/轴承，棱柱做支撑与导流罩，少量主题件做机器焦点。
- **装配族**：厂房墙跨、屋架、平台跨、管线架、传送/加工工作站、维护门架、警示灯组。所有管线要有来源、去向或明确截断件。
- **色材**：大面积结构色保持克制；路线、危险、待机/运行/故障使用稳定状态色。磨损集中在接触边、移动路径和泄漏源附近。
- **光效**：机器状态变化对应灯、声、运动或环境色变化；满场闪烁只会降低机关可读性。
- **常见失败**：三条传送带、几个箱子和警示灯不等于工厂；没有梁柱、平台侧脸、屋架、管网和设备底座时仍是机关灰盒。

[《case-003》](exemplars/case-003.md)提供的是“工厂入口”而非完整工厂路线证据：中央亮门洞由两侧厚重体量、柱栅和灯具夹出，背景筒仓、罐体与竖向管线再建立第二轮廓。其 4640 单位分布在多场景、人物、文字和系统中，不能当作工业配额；可迁移的是先覆盖 `SILHOUETTE/ENCLOSURE/STRUCTURE/NAVIGATION/SCALE_REFERENCE`，再添加设备与表面细节。该案取得控制后的超大厨房还说明尺度世界必须有熟悉物件作锚点；大面积教程/商店文字遮住中景则是首屏信息层反例。

[《case-002》](exemplars/case-002.md)补到的是可控工厂大厅和可毁房间词汇：米灰墙板、顶梁/灯格、两侧坡道、门框与房间牌先完成室内壳体，中轴装置、雕像和锤子再给出主题与动作。全图以 30 种模型路径展开 7166 个批加载单位，并记录大厅、仓库、包装、组装、电力、安保等房间名；不能把总量归到大厅，也不能由名称还原路线。其三次可控画面仍只有约 2–3 FPS，说明窄词汇与批合并记录不能代替目标设备的实际峰值测试。

## 3. 城市街区、古建与城堡

**世界句示例**：洪水退去后的山城重新点灯，玩家沿屋顶和拱廊寻找仍开放的城门。

- **轮廓**：先建立街墙高低、屋顶线、塔楼/城门和巷道宽窄，再做门窗；建筑只摆正方盒会失去年代与地区特征。
- **基础件**：方块/薄板做墙和檐口，棱柱做坡屋顶与扶壁，圆柱做柱/塔，拱环做门窗，条形件做栏杆、窗棂和屋脊。
- **装配族**：标准立面、转角立面、门楼、屋顶段、拱廊、桥/阳台、街道设施簇。模块接口统一层高、柱距、檐口和材质分缝。
- **比例**：玩家高频经过的门、梯、阳台必须按通行和相机测试；远景建筑可夸张塔顶和屋脊，减少内部结构。
- **色材**：墙、基座、木/金属结构和屋顶各有稳定家族；年代感来自边缘、沉积和修补节奏，不是全表面随机污渍。
- **常见失败**：每栋楼使用完全不同素材包；门窗均匀贴图式排列；屋顶、墙体与地面没有厚度和排水/承重关系。

[《case-017》](exemplars/case-017.md)补充了现代城市剧情尺度：2,108 个单位中可变形方块、自定义曲面与基础圆柱合计约 39.5%，并有 996 个单位处于父子装配层级。可迁移的不是其城市布局，而是“楼体大面/街道接触面/公园软景/室内门槛/近景任务道具”的层级，以及用人群消失、电梯开启、目标改写和雨伞架指引把场景状态变成叙事反馈。远景高楼不必逐层可玩，剧情镜头附近的门、按钮、人物轮廓和道具才应获得最高密度。

## 4. 玩具、糖果、童话与微缩世界

**世界句示例**：夜里醒来的玩具把包装线改造成自己的游乐王国，玩家在超大积木与礼盒之间穿行。

- **轮廓**：使用厚、圆、饱满和略夸张的比例；通过“玩家变小”让日常物件成为建筑或地形。
- **基础件**：大方块做积木/糖块，圆柱与球体做轮子、糖果和关节，圆环做发条/包装框，薄板做标签、丝带和卡片。
- **装配族**：积木墙跨、礼盒平台、玩具关节、糖果拱门、轨道/包装段、超大日常物件地标。装配接口像真实玩具一样有卡扣、缝隙或铆钉。
- **色材**：饱和色按角色分组，不同时把所有颜色设为强调色；路线与危险仍需独立语义。塑料、纸、布、糖晶至少在光泽和边缘上可区分。
- **叙事细节**：掉落标签、未封口箱、散落零件和歪斜贴纸说明“这里发生过什么”；不要平均撒小玩具。
- **常见失败**：只用粉色、彩灯和几个玩偶；积木没有拼接逻辑，礼盒只有立方体没有盖、带、折边和厚度。

[《case-002》](exemplars/case-002.md)只部分验证“玩具工厂”，没有验证完整微缩世界。其大厅用普通工业壳体承载橙色盲盒/展示装置、蛋仔雕像、手持锤和拆除技能，因此“玩具语义”来自焦点对象与玩家动词，而不是全场粉色；但玩家仍处于常规走廊比例，首屏没有超大桌面、包装边、日常物件或卡扣把角色明确缩小。新方案必须把四项分开：

1. `TOY_SEMANTICS`：轮廓、关节、工具、零件和包装怎样说明玩具；
2. `SCALE_ANCHORS`：至少两个熟悉物与玩家形成可复述比例；
3. `ROUTE_CONVERSION`：哪些物件真的成为地形、遮挡、门槛或交互面；
4. `MATERIAL_SPLIT`：塑料、纸、布、金属与糖晶怎样通过光泽、厚度和边缘区分。

只有第一项成立时称为玩具题材，不称为巨物微缩；只有色板和玩偶时，两者都没有完成。若主题同时是工厂，先用梁柱、墙跨、平台、管网与设备底座建立可信场所，再让包装线、玩具关节、零件状态和可破坏/组装动作改变房间身份。

## 5. 科幻、太空站与赛博设施

**世界句示例**：轨道站在断电后逐舱重启，玩家循着恢复的能源环前往逃生舱。

- **轮廓**：舱段、环形门、悬臂平台、能源核心和远景行星形成尺度；用少量大曲线与规则面板对比，不把所有表面切成碎片。
- **基础件**：薄板做舱壁/面板，条形件做框架，圆环做舱门/能源环，圆柱做导管，棱柱做斜面和装甲转角。
- **装配族**：舱壁跨、气闸门、能源管线、控制台、悬空桥、天线/核心地标。面板缝必须服从结构网格，不随机画线。
- **色材**：大面低饱和，交互/能量才发光；路线、危险和阵营色不能全部依赖同一种霓虹青。用亮度层级而非无限增加颜色。
- **状态变化**：断电—应急—恢复、失压—封锁、扫描—通过等状态要同时改变空间反馈与系统结果。
- **常见失败**：满屏发光线导致没有焦点；环件悬空没有舱壁连接；所有几何都很薄，看不出机器或建筑厚度。

## 6. 恐怖、废墟与悬疑空间

**世界句示例**：废弃疗养院在每次回望时都会少一扇门，但安全出口的标记始终可信。

- **基础世界先正常**：先按真实建筑、村落、矿井或工厂建立完整空间，再用封堵、破损、错位和状态变化制造不安；纯黑空房不是废墟。
- **形状语法**：重复门框、过长走廊、偏斜梁柱、被封闭洞口和局部尺度异常；异常必须有节奏，正常段为异常提供对照。
- **装配族**：完整/破损墙跨、封门、塌落段、可回望地标、光源簇、追逐门槛。A/B/C 变体可对应正常、受损和异常状态。
- **光色**：保证脚下、出口和危险来源仍可读；黑暗负责隐藏次要信息，不隐藏基本通行。闪烁与突亮必须有冷却和预告。
- **声音/事件**：每次夺取控制权或制造惊吓要换回线索、关系变化或空间后果；不能连续用无因果跳吓拖时长。
- **常见失败**：全图低亮度、红灯与血迹平均铺满；恐怖装饰堵住镜头；追逐失败后重跑过长演出。

[《case-013》](exemplars/case-013.md)只提供题材壳体与代码部分证据：可控首屏以完整楼体、重复窗格和中央门廊先建立正常建筑秩序，再用枯树、高草、暗窗、碎屑和开放门洞叠加侵蚀。其 2964 个单位中有 972 个可变形方块，并使用圆柱、球体、破损墙、枝杈、圆环和装饰线形成结构与破损层；这说明恐怖空间仍需要真实的 `MASS/MID/ENCLOSURE`，而不是几盏红灯。名称表中的房间、钥匙、电箱、陷阱、塌陷和安全出口只能生成房间网络与状态审计问题，不能证明实际顺序或恐怖节拍。入口初载约 3 FPS、稳定后恢复到 60 FPS，因此任何借鉴都要把加载瞬态与稳定逐视区性能分开测试。

## 7. 冬季、花园与季节景观

**世界句示例**：结冰湖面围绕温暖庆典逐步点亮，玩家在雪林场景之间换景与合影。

- **轮廓**：使用前景接触面、中景可达景观簇和远景主树/山体/文字三层构图；自然元素按簇和留白组织。
- **基础件**：树干、树冠、灌木、积雪顶、草花、石块和地面曲面形成窄词汇；通过大小、倾斜与聚簇变化，而不是频繁换模型。
- **装配族**：大/中/小植被簇、湖岸段、花坛/雪丘、观景岛、灯光树、换景门架。每簇有主方向和高度，不逐件随机。
- **色材**：季节基色占大面，暖色集中到可达地标和活动点；雾雪强化层次但不遮住角色与返回路线。
- **性能**：密集植被和积雪通常无物理、少投影，接触面与边界另设代理；镜面、动态灯和粒子集中在拍照焦点。
- **常见失败**：植物平均铺满、每棵都投影；远景漂亮但没有可达中景；多个合影点都使用同一构图。

## 8. 海洋、海底与漂浮世界

**世界句示例**：退潮后的海底城市短暂露出通道，水流与浮力不断改变可达路径。

- **先选世界结构**：水下跑酷封套、连续海床探索、沉船/遗迹室内、漂浮群岛或潮汐城市使用不同拓扑。已有 [《case-023》](exemplars/case-023.md)只部分支持第一种，不能把悬浮落点链套给所有海洋主题。
- **轮廓**：弧形洞口、珊瑚塔、沉船肋骨、气泡/浮岛和远处光柱形成向上或随流动的方向性。
- **基础件**：圆柱/锥体做珊瑚和桅杆，弧环做洞口/贝壳，薄板做船板和水草，球体做气泡/卵石，大曲面做海床。
- **装配族**：珊瑚簇、礁石洞口、沉船跨、漂浮平台、水流门架和空气站。小装饰默认无碰撞，避免水草和气泡成为意外障碍。
- **前中远分工**：近景生物簇框住角色和接触面，中景路线/洞口承担下一步，远景海床、岩壁、遗迹或光柱提供尺度。路线色应从冷色环境中抬出，但不把所有珊瑚都做成同权重高饱和焦点。
- **色材**：远处降低对比和饱和度，路线用更清楚的明度或暖色；水体特效不能让实际碰撞面失去边界。
- **状态变化**：潮位、水流方向、气泡路径或能见度变化必须有预告和稳定恢复。
- **垂直长线**：每层同时提供安全落点、上方地标、侧向参照、下一层框景、存档和坠落恢复；章节数、存档数与救援门数分别对账。已有样本的 69 个存档、39 个自然传送门和约 945 米跨度只证明这些对象大量存在，不证明镜头与恢复可靠。
- **性能**：连续海床/岩壁和接触面使用稳定碰撞代理；海草、薄珊瑚、气泡与远景默认无物理、少投影。透明、体积雾、粒子与动态水面按峰值视区限额，不把“水下感”全部压在透明叠层上。
- **常见失败**：只把普通地图染蓝；透明层叠导致性能和落点辨识问题；漂浮结构没有方向与层级。

## 9. 抽象、梦境、音乐与数据空间

**世界句示例**：一段失真的旋律逐拍重建空间，玩家踩过的几何会成为下一段节奏的背景。

- **先定一条数学/节奏规则**：例如尺寸按 1:2:4、角度按固定序列、颜色沿状态渐变或形状随节拍变换；抽象不等于任意。
- **基础件**：选择极少几何族并明确层级，例如方块负责路径、圆环负责目标、细线负责连接、球体负责状态。
- **装配族**：节拍门、序列平台、重复框景、数据柱、空间转场和主符号地标。变体来自规则参数，不是逐件随机。
- **色光**：背景、路线、危险、当前拍和目标必须分工；高饱和与发光只用于状态焦点，保留视觉休止。
- **机制结合**：若形状或灯光表达判定，装饰动画必须服从同一时间轴并提供静音可玩性。
- **可控首屏**：详情封面、固定建立镜头和实际取得控制后的相机分别验收。角色、近景曲面或巨大符号不能占满画面而抹掉中景结构与最近动作；需要贴近大物体出生时，预留相机口袋或先给一段安全拉远。
- **规则可复述**：玩家观察一个短节拍后，应能用一句话描述至少一条形状、尺寸、角度、颜色或运动之间的映射。无法复述时先减少变量，不能靠增加随机色块和悬浮文字制造“抽象感”。
- **常见失败**：所有物件漂浮且没有尺度；随机颜色/旋转冒充梦境；背景特效比路线反馈更强。

## 10. 学校、住宅、办公室与人类尺度室内

**世界句示例**：停电后的旧学校逐层恢复应急照明，玩家从教室穿过走廊与设备层寻找仍可用的出口。

- **先定房间功能与动线**：每个房间回答谁使用、主要家具是什么、玩家从哪看见下一出口、停留还是穿越；不要先复制空盒，再用桌椅填满。
- **基础件**：方块/薄片做墙地顶、柜体与桌面，圆柱做腿、管线和灯，棱柱/环件做椅背、风口、门窗和设备轮廓；少量主题件只负责高辨识物。
- **装配族**：标准/转角走廊跨、教室/病房/办公室房间跨、门窗族、家具簇、机电附着、楼梯/电梯前室和服务通道。统一层高、门洞、踢脚线、天花网格与标识高度。
- **比例与镜头**：家具建立熟悉尺度，但通行宽度按目标人数和相机实测放大；低吊灯、门楣、桌群和窄转角不能遮住目标或卡住多人。
- **信息语义**：房间编号、墙色、地面线、窗外地标和机电差异共同定位；关键出口不只靠文字。潜行/恐怖图中监控、暗灯和警卫外观仍必须服从真实状态合同。
- **性能**：细分家具与装饰多为无物理、少投影的视觉子件，桌群/柜体用连续代理；只给近景交互物、动态门和关键人物保留状态更新。
- **常见失败**：房间比例像空仓库；家具均匀网格导致没有动线；所有门长得相同；装饰摄像头与真实检测边界冲突；每个桌椅小件都启用碰撞和投影。

[《case-008》](exemplars/case-008.md)证明 1411 个方块、582 个圆柱与大量棱柱/环件可通过组件组塑造教室、通风设施、人物和车辆，也证明成熟学校外观仍可能只承载章节跑酷。使用本主题时同时审计空间装配与真实玩法合同，不能相互代替。

## 混合主题

最多选择一个主世界和一个对比层。对比层必须能解释为时间、阵营、污染、梦境、尺度或章节状态，而不是“两个素材包都喜欢”。

用共享项维持统一：至少保持两项不变，例如结构网格、基础比例、主材质、路线色或装配接口；再只改变一到两项，例如植物侵蚀工业设施、童话世界逐渐机械化、古城进入数据化梦境。

混合边界应出现在门槛、地标、状态事件或章节转折，给玩家一次可感知的转换。不要在同一墙跨上平均混合所有语汇。

## 视觉验收

1. **黑白剪影**：只看轮廓仍能区分主地标、路线开口和危险边界；
2. **去 Prefab 测试**：隐藏少量主题成品件后，基础结构仍保留主题比例和装配语言；
3. **三距离测试**：近景有接触厚度，中景有可达锚点，远景有方向地标；
4. **灰度测试**：路线、危险和目标不只依赖色相区别；
5. **重复测试**：同一装配族连续出现时有节奏与受控变体，而非复制粘贴或逐件随机；
6. **状态测试**：光、色、动效或场景变化对应真实的玩法/叙事状态；
7. **净空测试**：主题细节不侵入起跳、落点、运动机关、多人站位和镜头；
8. **成本测试**：不可达背景和微装饰不承担无必要的物理、投影、透明或动态灯成本。

通过这些检查后，才把主题称为“空间系统”；否则仍只是色板与道具清单。
